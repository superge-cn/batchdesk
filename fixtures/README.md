# fixtures：语料与性能数据集

> **判定权威不在本目录**。每条语料的"预期行为"以 T v1.1 §3.2 对应行为准；本目录只承载**能跑出样本的脚本**与**三行摘要**，不复制判定文本。

│       └── out/               生成物（**不入库**，见 §4）

## 2.1 回归范围：自动化 / 人工两栏（已确认）

T v1.1 §3.2 的 28 条按构造方式分两栏，**互斥且无遗漏**（由 `corpus/check_scope.py` 强制）：

**两栏的归属与执行方式**（哪条属哪栏、共几条，**不在本文件复述**，避免与门禁数据源漂移）

| 栏 | 归属判据 | 执行方式 |
|---|---|---|
| **自动化** | 具备 `corpus/{编号}/gen_*.py` 的语料 | CI 全自动回归 |
| **人工** | 登记在 `corpus/manual-only.txt` 的语料 | CI 显式排除；人工跟踪，结果记入 `corpus/manual-results.md` |

> 各栏的**当前条数与编号**以 `corpus/manifest.md` 的「进度汇总」与 `corpus/manual-only.txt` 为准，本文件不复制。

**口径**：CI 的通过率分母**不含**人工项，因此 **CI 绿灯 = 自动化语料零失败**；T v1.1 §1.3 字面的"语料回归零失败"由两栏共同构成，两栏都过才计入阶段级验收（T v1.1 §4.2）。详见 `corpus/manifest.md` 的「人工跟踪」节。

**范围门禁**（`check_scope.py`，CI 必跑）：manifest 行数＝28；manifest 的「人工」集合与 `manual-only.txt` 双向一致；「就绪」必须有脚本与目录；「人工」不得有脚本；磁盘目录必须在清单内。任一条不满足即 CI 失败——目的是让"新增语料漏建脚本"无法静默漏测。

## 3. 生成脚本约定

- **语言**：Python 3（D-R3=A）；
- **幂等**：重复运行产出**逐字节一致**（固定内容、固定行尾、不依赖时间戳/随机数）；已有内容相同时不重写文件；
- **自校验**：脚本末尾须验证该语料**确实具备区分力**（例如 K01 必须无法被 UTF-8 解码），不具备则报错退出——避免"生成成功但语料失效"；
- **合成样本**：全部为合成数据，**不包含真实客户数据**（对齐 T v1.1 §3.3）；
- **输出**：写入同目录的 `out/`，路径不做绝对化假设（以脚本自身位置为基准）。

## 4. 入库策略

| 内容 | 是否入库 | 理由 |
|---|---|---|
| 生成脚本 `gen_*.py` | **入库** | 脚本是权威 |
| `expected.md`、`manifest.md` | **入库** | 承载三行摘要与清单 |
| 生成物 `out/` | **不入库**（`.gitignore` 已排除） | 避免二进制与体积膨胀；由脚本幂等重建 |

> 若某条语料需要**逐字节固定**（例如 0 字节、引号不闭合这类边界），在 `manifest.md` 的备注列标注"需冻结"，并另存该样本的哈希值以便 CI 校验——**哈希记在 manifest，样本本身仍由脚本生成**。

## 5. 沉淀规则

**新 P0/P1 缺陷修复时，必须沉淀至少一条语料**并分配新编号（承接 T v1.1 §3.3 的沉淀规则）。流程：

1. 构造最小复现样本 → 2. 归入 K/T/R/E/Z 五类之一（新编号接在同类末尾）→ 3. 写 `expected.md` 三行摘要 → 4. 在 `manifest.md` 登记 → 5. 在缺陷记录中回填语料编号（T v1.1 §5.3 的必填字段之一）。

**编号不复用**：语料编号与功能编号（F/C/S）、缺陷级别（P0–P3）刻意错开，避免引用歧义（T v1.1 §3.2 表注）。
