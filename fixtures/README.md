## 3. 生成脚本约定

- **语言**：Python 3（D-R3=A）；
- **幂等**：重复运行产出**逐字节一致**（固定内容、固定行尾、不依赖时间戳/随机数）；已有内容相同时不重写文件；
- **自校验**：脚本末尾须验证该语料**确实具备区分力**（例如 K01 必须无法被 UTF-8 解码），不具备则报错退出——避免"生成成功但语料失效"；
- **合成样本**：全部为合成数据，**不包含真实客户数据**（对齐 T v1.12 §3.3）；
- **输出**：写入同目录的 `out/`，路径不做绝对化假设（以脚本自身位置为基准）；
- **生成物校验**：`verify_corpus.py --hashes` 校验 manifest 登记的冻结哈希；`--rebuild` 从零生成两次并比较逐字节结果（CI 必跑）。

## 4. 入库策略

| 内容 | 是否入库 | 理由 |
|---|---|---|
| 生成脚本 `gen_*.py` | **入库** | 脚本是权威 |
| `expected.md`、`manifest.md` | **入库** | 承载三行摘要与清单 |
| 生成物 `out/` | **不入库**（`.gitignore` 已排除） | 避免二进制与体积膨胀；由脚本幂等重建 |

> 若某条语料需要**逐字节固定**（例如 0 字节、引号不闭合这类边界），在 `manifest.md` 的备注列标注"需冻结"，并另存该样本的哈希值——**哈希记在 manifest，由 `verify_corpus.py --hashes` 校验**；样本本身仍由脚本生成。

## 7. 配置迁移样本（migrations）

承载配置 schema 的**历史版本冻结样本**（对齐设计契约 [03-配置schema与迁移契约](../docs/design/03-配置schema与迁移契约.md) §6：每个迁移函数必须有"旧版本样本 → 迁移 → 断言新版本字段"的单测）。

**与 28 条语料体系的关系——刻意分开，不进 corpus/**：

- corpus 的判定权威是 T v1.12 §3.2（28 条已逐条核对锁定，`check_scope.py` 规则 1 守门）；迁移样本**在 T 基线中没有对应行**，私加会破坏权威链；
- corpus 承载的是**文件处理管道的异常语料**（K/T/R/E/Z），迁移样本是**版本化配置 JSON**——性质不同，混入会污染自动化语料的通过率语义（断言 harness 覆盖到对应条目后）；
- `check_scope.py` 的扫描范围仅限 `corpus/`，本目录不受其规则约束；样本合法性由 **`fixtures/migrations/check_schema.py`** 校验（字段名、类型、枚举值与 `configVersion`），CI 必跑；kernel 迁移单测在迁移函数落地时补。

**目录规范**：`migrations/v{N}/config-v{N}.json`——schema v{N} 评审冻结时生成一份样本入库；未来每次新增迁移（v{N} → v{N}+1）时，v{N} 样本即为 `migrate(N → N+1)` 单测的输入基线。

**登记表**（新增样本在此登记，迁移动作落地时回填"已被消费"）：

| 样本 | 冻结日期 | schema 来源 | 被哪个迁移消费 |
|---|---|---|---|
| `v1/config-v1.json` | 2026-10-27 | 篇 03 §4（v1 冻结；v1.1 增量待确认） | 尚无（迁移链为空；`m1_to_2` 落地时作为输入基线） |

**入库策略**：样本本身**入库**——它不是生成物，而是"v{N} 形状"的权威快照（与 §4 的生成物规则相反，理由：schema 一旦冻结，历史形状必须逐字节固定，供未来迁移测试对照）。

**样本值的权威性声明**：样本只固定**字段名、类型与枚举值**；枚举值必须是篇 03 §4.1 已冻结值（不得出现 `keep-source` 等未定义枚举）。数值型默认值（隔离目录保留期、磁盘余量等）**不出现在样本中**，由默认档解析，避免与基线形成第二数值来源。**样本不得被当作默认值的权威来源**——默认值权威是篇 03 §4.1 登记表 + 基线。
