## 2. 判定口径

- 是否达标只能取方案 §9.1 的对应行：目录清单＝10 万文件 ≤30 秒（SSD，界面始终可响应）；大文件吞吐分档＝NVMe／机械盘两组数值，本机是 **SATA SSD**（Samsung 870 EVO，见 C-4/记录1），落在两档之间，故吞吐结论只作下限参考、不作达标判定。
- R-01…R-03 的耗时是 **CLI 单进程**口径；§9.1 同一行还含"界面始终可响应"，R-06 还含"常态 ≤300 MB／可配预算 512 MB"——两者属桌面壳（渲染线程与内存预算），本轮**没有**测，记在 §3，不得由 CLI 数值代替。
- RSS 口径：`/proc/<pid>/status` 的 VmRSS 是瞬时值（50 ms 采样），非 high-water 标记。早期用 `resource.RUSAGE_CHILDREN.ru_maxrss`（high-water）对 C-1 另测得 ≤11.2 MiB；两个口径都远低于 §9.1 的 300 MB 档，结论不变。
- fsync：`crates/` 与 `src-tauri/` 的 Rust 源码内均无 `sync_all`／`sync_data` 调用（当次 `grep -rn` 复核，命中 0 行），故写侧吞吐含页缓存收益；基线（方案 v1.19）未规定断电刷盘语义，本表不据此立要求，只标注口径限制。
- **就地改写类（R-09…R-18）的 apply 读数按"源字节/秒"计，但一次 apply 的磁盘 IO 约为源体积的 4 倍**：整源备份进隔离目录（读＋写）→ 流式重写（读＋写）→ 原子改名。所以 C01 的 86.9 MiB/s 对应的实际 IO 速率约 350 MiB/s，不可与 F01 的 386.8 MiB/s（只写不备份）直接对撞比较。
- **写侧粒度是本轮分档的主因，不是介质**：C01 按 64 KiB 块写出得 86.9 MiB/s，而 C02／C03 的改写器每行（每匹配）向裸 `File` 调一次 `write_all`（`crates/platform/src/fs.rs:247` 交出的是未加缓冲的 `File`）只有 3.9–5.6 MiB/s。同机同盘同夹具下的这个量级差属于实现特征，引用这些数值时须一并说明。
- **§9.1 第③子句与 §4.8 的"内存占用恒定"按段判定**：计划段与改写段分别记（R-12 计划段成立、R-17 计划段不成立、R-14～R-16 改写段成立）。不得用改写段的恒定读数去覆盖计划段的实测违背，反之亦然。
- **子档（C-2 集的前缀切片）不是 C-2 档**：R-13～R-16 的体积栏必须写明切片字节数，判定栏一律"不作达标"；整档读数只有 R-09～R-12、R-17、R-18 那几条。
- **受扰动读数不入中位数**：手册 §2.5 要求关闭无关后台任务；本轮出现过并发会话把 loadavg 抬到 16.2–27.9 的窗口（见 §4 轮次 3），该组读数单独列出、只作为扰动证据，不参与任何结论。
- 未达标按 T §4.2 由产品所有者签发延期豁免（模板 F），豁免不进毕业验收（T §4.4）。
