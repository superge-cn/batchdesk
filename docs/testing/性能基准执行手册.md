## 2. 环境与前置

1. 使用 **release 构建**（`cargo build --release`）；记录提交 SHA、构建号、Rust 工具链。
2. 先填写 C-4 环境台账：介质型号、文件系统、剩余空间、磁盘压缩/索引、实时杀软状态。
3. C-5 另填：UNC 路径、限速值、断线方式、探测超时（引 §4.9，不在本手册复述数值）。
4. 跑 C-2 前确认磁盘余量 ≥ 数据集体积 + 输出体积 + 安全余量（判定式引 §9.1）。
5. 关闭无关后台任务；同一轮内不更换机器/介质/文件系统。
6. **吞吐读数一律双分母（v1.22 §9.1，11.6-27）**：转换类（产物体积≠源体积）每次记录**源字节口径与产物字节口径两个读数**，达标判定对两个分母分别做、两个结论都写；只记一个分母＝记录不完整，按作废处理。纯 ASCII 上两分母重合，历史行不受影响。

## 3. 运行协议

- **预热**：每个场景先跑 1 次丢弃结果（WASM/磁盘缓存/杀软冷启动都会影响首轮）。
- **重复**：同一场景连续跑 3 次，取中位数；记录全部 3 次原始值，不只记中位数。
- **隔离**：不同数据集之间清理 `out/` 与临时目录；不要在 C-1 与 C-2 之间复用缓存结论。
- **证据**：记录命令、数据集生成命令与哈希、输出目录、日志、环境台账编号。
- **夹具与工具链缺项**：C-1／C-2 统一用 `fixtures/bench/measure.py`（预热 1＋正式 3；产物 sha256 在计时区外计算，不影响耗时口径）。该脚本自带墙钟计时与 50 ms 内存采样（Linux 读 `/proc/<pid>/status` 的 VmRSS；Windows 读 `GetProcessMemoryInfo` 的 WorkingSetSize，ADR-0082——两者同为驻留物理内存口径但不完全等价，结果行的内存列须写明平台，不做跨平台直接比较），因为部分执行机没有 `/usr/bin/time`（本项目开发机实测缺失）；采样值是瞬时值，与 `ru_maxrss`（high-water）口径不同，记录时须写明用哪个。工作目录缺省 `/tmp/batchdesk-bench`，Windows 上可用环境变量 `BATCHDESK_BENCH_DIR` 指到大盘。就地改写类（`c2rw`）额外要求：期望产物由夹具按**同一变换纪律独立算出** sha256 后断言逐字节一致，且计划条目必须"既不被阻断也不被跳过"——否则测的是空转，样本作废；`--plan-only` 只跑计划段，用于把"计划段的体积-内存关系"单独量化。
- **配对读数同窗口**：涉及「变体数据集 vs 基线数据集」的比较（如多字节 GB18030 对 ASCII 的 R-29／R-30），两条必须在同一负载窗口内背靠背跑，'
 '并各自记下开测／收测的 loadavg 1 分钟值；跨窗口引比值＝把扰动算进结论。
- **C-2 前置预检**：先跑一次带 RSS 保险丝的测量（`--rss-limit-mib`，默认 1024），峰值越限即 kill 并停测、不产出结果行——内存紧张的机器上不得盲跑全量档。
- **宿主扰动**：§2.5 的"关闭无关后台任务"在同机有其他会话时做不到。出现过 loadavg 16.2–27.9 的窗口，同一场景同一夹具的读数差到 2.3 倍（C01 整档 apply 56.3 秒 vs 静默窗口 24.3 秒）。处置口径：扰动窗口的读数**不入中位数、不作结论**，但要在 `results.md` §4 的轮次记录里留痕并写清负载区间；复跑后若两个窗口的速率一致（如 C02 的 4.3–4.5 MiB/s），说明瓶颈在实现侧而非争抢，这本身也是证据。
- **失败**：记录失败阶段（生成/读取/执行/写回）、错误码、是否可重试；不把失败样本混入中位数。保险丝触发（`breached`）是一种合法结论：它回答"这一档在本机能不能测"，夹具把它作为结果行带出并以退出码 3 结束，不得写成"未测"。

## 6. 判定

- 指标口径与阈值只认方案 §9.1（v1.20 起吞吐为**源/产物双分母**、v1.22 沿用，两个分母分别判定）；数据集构造只认 T 附录 C（v1.13 起 C-2 含编码两变体）。
- 未达标时按 T §4.2 由产品所有者签发延期豁免（含补测节点）；毕业验收不接受豁免（T §4.4）。
- 本手册不写死任何数值；新增数据集/参数先改 T 附录 C 或方案 §9.1，再回填本手册。
