# 14 AI 助手与工具调用契约

> 状态：已评审·实现冻结 v1（2026-10-28 用户按推荐确认；目标覆盖全量可计划功能与多计划，Phase 1 只启用 4 个功能） ｜ 日期：2026-10-28
> 适用：src-tauri（AI 编排）、web/（助手面板）、测试/验收 ｜ 权威：产品方案 v1.19 第 14 章、01/02/05/06/09/10/12、OQ-20/21/23
>
> 本契约定义 **F15 AI 助手** 的目标架构、命令/事件/DTO、FunctionCatalog、工具 allowlist、多计划编排、模型 Provider、数据最小化与安全边界。产品行为以方案第 14 章收编版为准；本契约不定义新的文件操作语义。

## 0. 结论

- **目标**：AI 能为**所有可计划（plan-capable）的 F/C 功能**生成单个或多个计划；多计划以 `IntentGraph` 表达依赖，由壳层生成 `PlanBundle`。
- **分阶段**：Phase 1 只启用 4 个功能、单计划；Phase 2 启用全部可计划功能、单计划；Phase 3 启用多计划。
- **不变的安全底线**：AI 永不直接 apply；只调用只读命令与 `planOperation`；计划由 kernel 生成；用户确认后执行；默认不发送文件内容/文件名。

## 1. 范围与分期

| 阶段 | AI 能力 | 启用范围 |
|---|---|---|
| **Phase 1（F15-lite）** | 单轮对话＋澄清；单计划 | F12、F05、F07、C07 |
| **Phase 2（F15 full）** | 单轮/多轮；单计划 | 全部 plan-capable F/C 功能（由 FunctionCatalog 决定） |
| **Phase 3（F15 multi-plan）** | 多计划、依赖、跨计划冲突检查 | 在 Phase 2 基础上启用 `IntentGraph`/`PlanBundle` |

- “全部功能”指**可计划功能**：有 plan/apply、有参数 schema、可预览/可回滚的 F/C 功能。授权（F14）、队列（C15）、日志（C17）、冲突策略（C19）、撤销框架（C20）、预检（S01/S02）等横切/授权能力**不暴露为 AI 计划**。
- 新功能是否对 AI 可见，只由 `FunctionCatalog` 决定；**AI 不维护第二份功能清单**。

## 2. 架构

```text
web/ AI 助手面板
  │ aiAsk / aiCancel / getAiStatus
  │ ai://delta / ai://tool / ai://bundle / ai://done / ai://error
  ▼
src-tauri/ai
  ├── AiOrchestrator（会话、取消、事件）
  ├── ModelProvider（OpenAI 兼容；唯一联网点）
  ├── IntentValidator（JSON schema / FunctionCatalog / IntentGraph）
  ├── PlanBundleBuilder（逐计划调用 planOperation；跨计划冲突检查）
  └── ToolGateway（只读 + planOperation）
          │ 现有 IPC
          ▼
src-tauri 队列 + crates/kernel（plan/apply/undo/log 原样不变）
```

- **kernel 不联网、不感知模型**；模型调用只在 `src-tauri/ai`（或后续云端服务）。
- AI 不直接访问 FsAdapter；文件操作全部走现有命令与 kernel 校验。
- Web/WASM 零强制力；Phase 1/2 不做 Web；Phase 3 若做 Web，只走云端并另立契约。

## 3. 命令与事件

### 3.1 命令

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `aiAsk` | `{sessionId?, text, context: AiContext, consentToken?}` | `{messageId}` | 发起请求；立即返回，流式走事件 |
| `aiCancel` | `{messageId}` | `void` | 取消模型/计划/束构建；幂等 |
| `getAiStatus` | — | `AiStatus` | 模型/阶段/目录/同意状态；仅显示 |

### 3.2 事件

| 事件 | payload | 说明 |
|---|---|---|
| `ai://delta` | `{messageId, text}` | 流式文本 |
| `ai://tool` | `{messageId, call: AiToolCall}` | 工具调用展示（执行由壳层完成） |
| `ai://bundle` | `{messageId, bundle: PlanBundle}` | 单/多计划就绪；复用现有预览 |
| `ai://done` | `{messageId, bundle?: PlanBundle, report?: ApplyReport, message: string}` | 完成/失败/取消；report 仅来自引擎 |
| `ai://error` | `{messageId, error: IpcError}` | E6xxx |

## 4. DTO

```ts
interface AiContext {
  fileCount: number;
  kinds: string[];
  locale: "zh-CN" | "en-US";
  includeFileNames: boolean;   // 默认 false；true 需 consent
  fileNames?: string[];        // 仅 includeFileNames=true 且同意时出现
}

interface AiStatus {
  available: boolean;
  configured: boolean;
  phase: 1 | 2 | 3;            // 当前启用阶段
  catalogVersion: string;
  supportedKinds: OperationKind[]; // 当前阶段可用的 plan-capable 功能；仅显示
  provider?: string;
  model?: string;
  consentRequired: boolean;
  dataPolicyUrl?: string;
  quota?: { used: number; limit: number }; // 仅显示
}

interface AiIntentStep {
  stepId: string;              // 束内唯一
  kind: OperationKind;         // 必须在 FunctionCatalog 且 planCapable
  params: Record<string, unknown>;
  dependsOn: string[];         // 束内依赖；空=可先执行
  needsClarification?: boolean;
  question?: string;
}

interface AiIntentGraph {
  steps: AiIntentStep[];       // Phase 1/2 最多 1 步；Phase 3 可多步
}

interface AiToolCall {
  callId: string;
  name: "scanDirectory" | "planOperation" | "loadRecipe";
  arguments: Record<string, unknown>;
}

interface PlanBundle {
  bundleId: string;
  steps: PlanBundleStep[];
  conflicts: BundleConflict[];
  status: "draft" | "ready" | "running" | "partial-failed" | "completed" | "failed" | "cancelled";
}

interface PlanBundleStep {
  stepId: string;
  plan: PlanDocument;          // 由 kernel planOperation 生成
  dependsOn: string[];
  status: "pending" | "ready" | "running" | "done" | "failed" | "skipped" | "cancelled";
  error?: IpcError;
}

interface BundleConflict {
  kind: "target-overlap" | "dependency-cycle" | "unsupported-phase";
  stepIds: string[];
  paths?: string[];            // 仅 target-overlap
  riskLevel: "safe" | "caution" | "danger";
}

interface AiAuditRecord {
  ts: string; sessionId: string; messageId: string;
  bundleId?: string; stepId?: string; planId?: string;
  provider: string; model: string;
  intentKind?: OperationKind;
  toolNames: string[];
  resultCode?: string;
  latencyMs?: number;
  // 不记录 prompt/response、文件名、文件内容、许可证/设备信息
}
```

- `PlanDocument` 必须由 kernel `planOperation` 生成；AI 不得直接构造 `PlanEntry`。
- `PlanBundle` 由壳层 `PlanBundleBuilder` 生成；AI 只能提供 `AiIntentGraph`。
- `PlanBundle.conflicts` 为跨计划冲突；`target-overlap` 默认阻断该步骤，必须由用户跳过/调整后才能执行。
- `AiStatus.quota` 仅供显示；真实配额以服务端/Provider 记账为准。

## 5. FunctionCatalog（单一来源）

AI 不维护自己的功能清单。`FunctionCatalog` 从方案 §3.2 的功能元数据 + 01 §3.2 的 `OperationKind` 生成/登记：

```ts
interface FunctionDescriptor {
  kind: OperationKind;
  displayName: string;
  planCapable: boolean;        // 无 plan/apply 的横切功能为 false
  aiPhase: 1 | 2;              // 从哪个阶段对 AI 可见
  paramSchemaRef: string;      // 参数 schema 的单一来源
  requiresSourcePaths: boolean;
  supportsPreview: boolean;
  supportsUndo: boolean;
  tier?: "G0" | "G1" | "G2" | "G3";
}
```

规则：

1. **新增功能必须登记**：新增 F/C 功能时，在 `OperationKind` 与 `FunctionCatalog` 同步登记；未登记即 AI 不可见。
2. **AI 不得硬编码 kind 列表**：Phase 1 的 4 个功能只是 `aiPhase=1` 的目录子集，不是架构写死。
3. **参数 schema**：每个 plan-capable 功能必须有 JSON schema（字段、类型、必填、范围引用基线）；AI 输出参数必须校验。
4. **不可计划功能不暴露**：F14/C15/C17/C19/C20/S01/S02 等 `planCapable=false`；AI 不得调用。
5. **目录版本**：`catalogVersion` 随功能登记变更；`getAiStatus` 返回，便于 UI/测试对齐。
6. **Phase 2 前先补 01**：当前 01 §3.2 的 `OperationKind` 只列 v1 已冻结功能；Phase 2 要启用的每个 plan-capable 功能必须先追加 kind，再登记 FunctionCatalog。AI 侧禁止自造 kind 字符串。

## 6. 工具 allowlist

| 工具 | 类型 | 用途 | 约束 |
|---|---|---|---|
| `scanDirectory` | 只读 | 获取文件数量/类型摘要 | 结果传给模型时只保留摘要，不传路径/文件名 |
| `planOperation` | 纯函数 | 为单个 `AiIntentStep` 生成 `PlanDocument` | 参数 schema 校验；AI 不得直接写 PlanEntry；可多次调用（每步一次） |
| `loadRecipe` | 纯函数 | 载入配方并生成计划 | 载入后仍须预览，不执行 |

**禁止**：`applyPlan`、`setConfig`、`activateLicense`、`cancelTask`、任意 shell/网络/文件系统工具。AI 尝试调用禁止工具 → **E6004**，不执行、记审计。

## 7. 执行与确认

### 7.1 单计划（Phase 1/2）

```text
aiAsk → AiIntentGraph(1 step)
  → 校验 kind/params（FunctionCatalog）
  → planOperation 生成 PlanDocument
  → ai://bundle（1 step）
  → 现有预览面板
  → 用户确认 → 现有 applyPlan
  → ai://done（report 来自 ApplyReport）
```

### 7.2 多计划（Phase 3）

```text
aiAsk → AiIntentGraph(N steps, dependsOn)
  → 校验目录/参数/依赖（环、未知 step、未启用 kind）
  → 每步 planOperation → PlanBundle
  → 跨计划目标冲突检查（target-overlap）
  → ai://bundle
  → UI 展示步骤链；用户逐项预览/确认
  → 按依赖拓扑序逐步 applyPlan
  → 每步进度/Journal/日志；失败默认停止
  → ai://done（每步 report/status）
```

规则：

- **AI 永不直接 apply**；AI 面板不得提供“跳过预览直接执行”。
- **跨计划冲突**：同一目标路径出现在多个步骤 → `target-overlap`，默认阻断该步骤；用户必须调整/跳过，不能静默覆盖。
- **失败策略（OQ-23 已确认）**：某步失败即停止后续步骤；已完成步骤保留，可按各自 Journal 撤销；不做跨计划自动回滚。
- **计划束上限**：单个 `PlanBundle` 最多 **10 步**（可配置；超限 E6010）；Phase 1/2 只接受 1 步（多步 E6011）。
- **束级撤销（OQ-23 已确认）**：v1 不提供自动束级回滚；只提供逐计划撤销入口。若后续提供束级入口，仅按已完成步骤的 Journal 逆序逐计划撤销，不新建撤销机制。
- 风险分级、二次确认、冲突策略、撤销/日志沿用现有规则（方案 §7.1/§7.7/§7.11）。
- 执行结果由引擎返回；AI 只能据此总结，不得虚报成功或补造条目。

## 8. 错误码（E6xxx）

| 码位 | 语义 | retryable | 说明 |
|---|---|---|---|
| E6001 | 模型未配置/不可用 | false | 引导配置或手动操作 |
| E6002 | 模型鉴权失败/供应商配额耗尽 | false | 不自动换供应商 |
| E6003 | 模型输出不符合 intent/tool schema | false | 不执行，提示重新描述 |
| E6004 | 工具调用不在 allowlist | false | 拒绝并审计 |
| E6005 | 内容安全策略拒绝 | false | 不展示内部策略细节 |
| E6006 | 模型请求超时 | true | 可重试；无文件副作用 |
| E6007 | 用户取消 | false | 无文件副作用 |
| E6008 | 上下文超限 | false | 提示缩小范围/手动操作 |
| E6009 | 供应商限流 | true | 退避后重试或提示稍后 |
| E6010 | 计划束依赖非法/循环/步骤超限 | false | 不生成/不执行 |
| E6011 | 当前阶段不支持多计划 | false | Phase 1/2 返回；提示升级/单计划 |

- 用户文案 key：`error.E6xxx.summary/detail/action`（06/09）。
- 供应商原始错误只进诊断日志的 `detail`，不得直接透出。

## 9. 数据最小化与日志

- 默认请求：用户文字 + 文件数量/类型 + locale；**不含**文件名、路径、内容、许可证/设备信息。
- `includeFileNames=true` 必须逐次同意；UI 展示将发送的文件名清单；文件内容仍不发送。
- 会话历史仅当前会话，可导出/删除；prompt/response 不写操作/诊断日志。
- 审计记录 `AiAuditRecord`：model/provider、intent kind、工具名、bundleId/stepId/planId、错误码、耗时；不含内容/文件名。
- 支持包/诊断导出不含 prompt/response；如用户主动导出会话，需明确提示去向。

## 10. 安全与滥用

- **提示注入**：用户文字、文件名、内容一律视为数据；不得覆盖系统规则；工具 allowlist + schema + 计划复核 + 用户确认。
- **多计划注入**：某一步注入不得改变其他步骤或触发自动执行；每步独立校验；跨计划冲突必须暴露。
- **模型不参与授权**：AI 不得读许可证/层级；功能门禁仍走 `LicenseService`；Web 零强制力。
- **危险操作**：删除/覆盖仍走隔离目录/二次确认；AI 不得建议跳过确认。
- **速率/成本**：按账号/会话限流；配额由 Provider/服务端记账；不把配额显示当成授权判定。
- **无自主循环**：一次请求生成一个 `IntentGraph`；不做后台多步执行；不自动 apply。

## 11. 测试锚点

- AI fixtures：`fixtures/ai/`（prompts + expected）；mock provider 确定性测试；不并入 corpus 28。
- **目录覆盖矩阵**：每个 `planCapable=true` 且 `aiPhase<=当前阶段` 的功能至少有一条 AI-Plan 用例；Phase 2 验收前完成矩阵。
- 功能：意图映射、参数抽取、歧义追问、unsupported 拒绝、单/多计划预览、确认执行、撤销、结果总结。
- 多计划：依赖顺序、环/未知 step、跨计划目标冲突、某步失败停止、已完成步骤撤销、注入只影响单步。
- 安全：提示注入（用户文本/文件名/内容）、工具越权、无直接 apply、非法 schema、超时/取消、配额/鉴权、日志脱敏、无未同意外发。
- Web（Phase 3）：零强制力、同意、数据最小化、云端、流式/取消。
- 详见 `docs/testing/AI助手测试分册-AI-v0.1.md`；正式验收前由 T 升版收编 F15 与 AI 安全套件。
