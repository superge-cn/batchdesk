## 1. 已确认的范围

| 项 | 决定 |
|---|---|
| 功能编号 | **F15 AI 助手（对话式任务编排）** |
| 优先级/阶段 | **P1 / 阶段 1**，不进阶段 0 |
| 形态 | **目标**：所有可计划 F/C 功能、单/多计划；**Phase 1** 只启用 4 类任务（F12/F05/F07/C07）、单计划 |
| 多计划 | **Phase 3**：`IntentGraph`/`PlanBundle`；依赖顺序、跨计划目标冲突检查；仍不直接 apply |
| 模型部署 | **远程模型，显式 opt-in**；默认关闭；本地模型 Phase 3 再评估 |
| 数据边界 | **默认不发送文件内容，也不发送文件名**；UI 必须展示“将发送什么”，用户可取消；文件内容一律不发送 |
| 执行方式 | **AI 永不直接 apply**；AI 只产出意图/参数，计划由 kernel 的 `planOperation` 生成；用户确认后由现有 `applyPlan` 执行 |
| 工具边界 | 只允许只读命令＋`planOperation`；禁止 `applyPlan`、`setConfig`、`activateLicense`、任意 shell/网络工具 |
| Web | Phase 1/2 不支持 Web；Phase 3 再评估“云端 AI”，且仍零强制力 |
| 授权 | 建议 G2/G3＋配额；具体层级/配额待 §8.1 确认 |
| 结果输出 | AI 只根据引擎的 `ApplyReport` 做总结；不得虚报成功、不得编造执行结果 |

## 2. 用户流程

### 2.1 Phase 1/2：单计划

```text
1. 用户在工作区选中文件（AI 不读内容）
2. 用户在助手面板输入自然语言
3. UI 显示将发送的字段（默认仅用户文字；不含文件名/内容）
4. 远程模型返回结构化意图/参数（JSON schema）
5. 壳层校验 allowlist/schema，调用 planOperation（纯函数，不落盘）
6. 预览面板展示 PlanDocument；用户确认
7. 现有 applyPlan 执行，进度/日志/撤销不变
8. AI 根据 ApplyReport 总结；不直接碰磁盘
```

### 2.2 Phase 3：多计划

```text
1. AI 返回带依赖的 IntentGraph
2. 壳层逐计划生成 PlanBundle；拒绝环/未知 step/未启用功能
3. 跨计划目标冲突检查；冲突默认阻断
4. 用户逐项预览/确认 → 按依赖顺序 applyPlan
5. 某步失败默认停止；已完成步骤可按各自 Journal 撤销
6. AI 只汇总每步 ApplyReport，不直接碰磁盘
```

示例：

> 用户：“把这批合同按年份分到文件夹，重名跳过。”
>
> AI 输出：`kind=c07`（清单移动）及参数；壳层调用 `planOperation` 生成计划；预览显示 12 条、1 条警告；用户确认后执行。重命名等复合任务在 F15-lite 中拆成另一轮请求/配方，不自动串联。

## 3. 非目标（Phase 1 明确不做；Phase 2/3 仍遵守安全底线）

- 不新增任何文件操作语义；AI 只能编排既有 F/C 功能。
- 不直接执行写操作、不调用 `applyPlan`、不自动确认危险操作。
- 不发送文件内容；默认不发送文件名；不读取用户未选中的文件。
- 不做 shell、任意网络请求、任意 URL、任意工具调用。
- 不做后台自主 agent、定时任务、多步无人确认执行。
- 不做 Web/WASM 侧 AI；不在前端做授权/配额判定。
- 不做“AI 直接回答文件内容”类问答（属于另一个功能，需单独评估隐私/本地模型）。
