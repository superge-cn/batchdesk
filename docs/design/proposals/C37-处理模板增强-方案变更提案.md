# C37 处理模板增强（模板化）方案变更提案

> 状态：v1.0 已收编（方案 v1.19 / T v1.12 / 设计 03 v1.3） ｜ 日期：2026-10-28
> 决策来源：用户提出（2026-10-28）——同一类型的数据/文件在第一次配置好参数与处理方法后，可保存为模板，下次直接引用，减少重复设置。
> 已确认（2026-10-28，产品所有者）：按 C37 承载；Phase A/B **均进阶段 1**；单步模板沿用 G1、多步骤模板归 G2；不完全匹配时**处理全部，由功能校验/跳过**；多步骤**一键执行 + 逐步骤确认降级**；UI 名称**处理模板**；模板默认不保存输出目录；多步骤上限**沿用 F15 单束 10 步**；Phase A **不做内置模板**；Web **支持模板存储/导入导出、零强制力**。
> 本文件**不是基线**，也不改变现有冻结契约。确认后按方案 §11.6 流程收编，再同步设计 03/01/06/12/14、U、T 与 TC。

## 1. 结论先行

1. **不新增 F/C 编号**。现有 **C37「批处理配方保存复用」** 已定义为“一组功能参数的命名保存，可一键复用到新文件集”（方案 §1.4／§3.2；设计 03 §5），本次需求的主体就是 C37；另造“模板系统”会造成参数快照、导入导出、版本迁移、授权检查四套重复。
2. **C37 升级为“处理模板”**：保留内部 `Recipe`／`C37` 命名与存储格式，UI 对用户使用“处理模板”这一更易懂的名称（2026-10-28 已确认）。
3. **分两阶段，均进阶段 1**：
   - **Phase A（P1/阶段 1，G1）**：单功能模板增强——保存/复用已有；补类型匹配建议、模板管理、导入导出与 v1 迁移。**单步，不引入新的计划架构**。
   - **Phase B（P1/阶段 1，G2）**：多步骤处理模板——按顺序执行多个已有功能；**一键执行 + 逐步骤确认降级**。首步先预览确认；后续步骤在无冲突/无警告时自动 plan/apply，遇风险或失败立即降级为逐步骤确认。
4. **四条安全底线不因模板改变**：
   - 模板只保存声明式参数，不保存脚本、宏、凭据、文件内容或绝对源路径；
   - 应用模板只生成计划，**必须重新预览**，不得直接 apply（方案 §7.3／§7.4；AGENTS 不变量 2）；
   - 每个步骤的 `OperationKind` 仍由 `LicenseService` 在计划/执行层复核，模板不能绕过授权；Web/WASM 仍零强制力；
   - 导入的模板视为不可信输入，必须做 schema/参数校验，未知功能或高版本拒绝。

## 2. 现状与差距

| 能力 | 现状 | 本次缺口 |
|---|---|---|
| 参数保存/复用 | C37 已有：`RecipeDocument` 保存 `kind + paramsSnapshot`，载入后重新预览 | 无 |
| 类型识别/建议 | 无；配方列表需用户自行辨认 | **有**：按扩展名/类型提示“可能适用”的模板 |
| 保存入口 | 设计 03 有 `saveRecipe`，但未定义“从预览/参数页保存”的交互与命名 | **有**：保存时自动带入类型、名称、描述、适用扩展名 |
| 模板管理 | 只有 `listRecipes/deleteRecipe/exportRecipe/importRecipe` | **有**：搜索、置顶、重命名、复制、最近使用、适用类型展示 |
| 多步骤处理 | C37 仅单 `OperationKind` | **有**：按顺序组合多个功能（Phase B） |
| 版本迁移 | `RecipeDocument.schemaVersion` 独立于 `configVersion`，高版本 E1007 | 需补 v1→v2/v3 迁移与未知功能处理 |
| 授权 | 现有操作逐项由 LicenseService 校验 | 模板不得内嵌层级判断；每步仍复核 |

**结论**：把本次需求理解为“C37 的 UX/匹配增强 + 可选的多步扩展”，而不是一个与 C37 并列的新功能。

## 3. 用户流程

### 3.1 保存模板（Phase A）

```text
用户完成参数设置 → 生成预览 → 点击“保存为处理模板”
  → 自动带入：功能名、当前参数快照、当前选择的扩展名、建议名称
  → 用户编辑：名称、描述、适用扩展名、标签
  → 保存到本地 recipes/
  → 不保存源文件路径、预览结果、文件内容
```

- 同名模板：提示“覆盖/另存为”，不静默覆盖。
- 保存的是**参数快照**（含输出命名、冲突策略等参数），不是某一次的具体文件清单。
- 若参数中包含绝对输出目录：默认标记为“本机路径”，导出时剔除；应用时若目标机不存在则要求重新选择（详见 §6.4）。

### 3.2 应用模板（Phase A）

```text
选中文件/文件夹 → 打开“处理模板” → 顶部显示“匹配当前选择”的模板
  → 选择模板 → 参数回填到四段式配置区
  → 必须重新预览（现有 planOperation） → 用户确认 → applyPlan
```

- **绝不自动 apply**；模板只是快速回填参数。
- 模板的“适用类型”只用于排序/提示，不过滤选中集；应用时始终把**完整选中集**交给 `planOperation`，非匹配项由功能自身校验/跳过/阻断，预览如实展示。
- 不完全匹配时显示“模板适用 n/m 项；其余将按功能校验/跳过”，不弹“仅匹配/全部”二选一。
- 若 0 项匹配，一键执行不启动；逐步骤模式可查看计划并决定是否继续。
- 不做“根据扩展名自动选中模板”或“自动执行”。

### 3.3 管理模板（Phase A）

- 列表：搜索、按最近使用/名称排序、置顶、标签筛选；展示功能名、适用类型、最近使用时间。
- 操作：编辑名称/描述/适用类型、复制、删除（二次确认）、导出、导入。
- 空状态、无匹配、模板不兼容、模板来自更高版本，分别给出可恢复提示。
- 模板删除不影响已生成的任务/计划；正在预览的模板被删除时，预览保留但禁止再次应用，提示重新选择。

### 3.4 多步骤模板（Phase B，一键执行 + 降级）

**两种运行模式**（模板级运行选项，存入本机偏好，不写入导出模板）：

```text
一键执行：
  选择模板 → 第 1 步 plan + 预览 + 用户确认
    → apply 第 1 步
    → 第 2 步 plan → 风险闸门 → apply（无风险时自动）
    → ... 任一步有风险/失败 → 停下并展示该步预览，降级为逐步骤确认
  → 任一步失败即停止；已完成步骤按各自 Journal 可撤销

逐步骤确认：
  每步 plan → 预览 → 用户确认 → apply → 下一步
```

- **一键执行不跳过 plan/apply**：每步仍由 kernel 生成 `PlanDocument`、由 `applyPlan` 执行；区别只在后续步骤是否逐个人工确认。
- **首步始终先预览确认**；一键执行只自动处理后续“无风险”步骤。
- 一键执行沿用方案 §7.4 的“信任模式”边界：**仅低风险且可全量回滚的步骤**允许自动执行；高风险、冲突、警告任一出现即降级逐步骤，不新开绕过预览的口子。
- **风险闸门**（每步 apply 前）：计划含 conflict/warning/blocked、操作属于高风险（覆盖、永久删除、不可逆等 §7.11 现有风险口径）、或授权检查失败 → **不自动 apply**，停下并展示该步预览，转为逐步骤确认。
- **一键执行可用性**：本机新建模板默认一键执行；导入模板默认逐步骤；含高风险步骤的模板强制逐步骤；用户可在运行选项中切换。首次一键执行仍先展示首步预览并要求确认，不跳过首步预览。
- 步骤是**线性顺序**，不建依赖图；`source` 仅两种：
  - `original`：仍使用用户最初选择的输入；
  - `previous`：使用上一步的实际产物。
- **不预生成“所有步骤的完整计划”**：第 2 步的输入路径在第 1 步执行前并不存在；逐步骤生成 `PlanDocument` 可以避免对不存在路径的伪计划，也避免一次性 apply 多个写操作。
- 某步无产物 → 记录“跳过”并继续；不静默当成成功。
- 失败策略沿用 OQ-23 的单计划失败口径：某步失败停止后续，不自动跨步回滚；已完成步骤可逐项撤销。
- 多步骤上限沿用 F15 的单束 **10 步**口径（OQ-23 已确认；本处仅复用，不新增数值）。

## 4. 分期与范围

| 阶段 | 内容 | 优先级/层级（建议） | 是否新增计划架构 |
|---|---|---|---|
| **Phase A** | 单功能模板：保存/复用、类型匹配建议、管理、v1→v2 迁移、导入导出 | **P1 / 阶段 1 / G1** | 否 |
| **Phase B** | 多步骤模板：顺序步骤、`original/previous`、一键执行 + 逐步骤降级、失败停止 | **P1 / 阶段 1 / G2** | 否，复用 `planOperation` |
| **Phase C（可选）** | F15 AI 引用模板：AI 按名称选择模板/步骤，仍只生成计划、逐项预览 | 随 F15 Phase 3 | 否 |

**非目标**：

- 不做自动执行、定时执行（定时属 C57）、无人确认的流水线；
- 不做脚本/宏/外部命令/任意 URL；
- 不做模板市场、云端同步、跨设备共享（导入导出 JSON 仍是唯一跨形态载体，引用方案 §13.8）；
- 不做由文件内容推断模板（只读扩展名/用户标注）；
- 不做绕过 LicenseService 的模板级授权；
- 不在本提案中新增错误码段或数值阈值。

## 5. 数据模型

### 5.1 推荐方案：在 C37 上做版本化演进

**Phase A：`RecipeDocument` v2**（在设计 03 §5 基础上追加可选元数据，不改单步语义）

```ts
interface RecipeDocument {
  recipeId: string;                 // ULID，沿用
  schemaVersion: 2;                 // v1 配方迁移后为 2
  name: string;
  description?: string;
  kind: OperationKind;              // Phase A 仍为单功能
  paramsSnapshot: Record<string, unknown>;
  match?: {                         // 仅用于建议，不自动应用
    extensions?: string[];          // 小写、不带点；空/省略 = 不建议
    tags?: string[];                // 用户标签，可搜索
  };
  sourceFormat?: "desktop" | "web"; // 沿用
  createdAt: string;
  updatedAt?: string;
  lastUsedAt?: string;
  usageCount?: number;              // 仅供排序/展示
  pinned?: boolean;
}
```

- **v1→v2 迁移**：保留 `recipeId/name/kind/paramsSnapshot/createdAt/sourceFormat`；`match` 为空，`schemaVersion=2`；不改变参数含义。
- **v2→v3（Phase B）**：增加可选 `steps: TemplateStep[]`；单步配方迁移为 `steps[0] = { kind, paramsSnapshot }`；`kind/paramsSnapshot` 保留为只读兼容字段或标记 deprecated。步骤字段：

```ts
interface TemplateStep {
  stepId: string;
  kind: OperationKind;
  paramsSnapshot: Record<string, unknown>;
  source: "original" | "previous";  // 线性步骤，顺序即依赖
}
```

- **运行模式**：`一键执行/逐步骤确认` 是本机 UI 偏好（按 `recipeId` 记忆），**不写入导出模板**；本机新建默认一键，导入模板默认逐步骤；含高风险步骤时一键不可用。
- **存储**：沿用设计 03 的 `recipes/`（桌面）／OPFS `recipes/`（Web）；不新建第二套目录。
- **命令**：Phase A 沿用 `saveRecipe/listRecipes/loadRecipe/deleteRecipe/exportRecipe/importRecipe`；`saveRecipe` 入参追加可选 `description/match`（不传按空处理），命令名不变；`loadRecipe` 仍返回单个 `PlanDocument`。`importRecipe` 接受 v1/v2，`exportRecipe` 输出 v2。Phase B 追加 `getRecipe({recipeId}) -> RecipeDocument`（读取完整步骤）与步骤计划命令；不重载 `loadRecipe` 的返回类型。
- **模板名称**：内部仍叫 `RecipeDocument`；UI 文案可叫“处理模板”。如果未来要彻底改名，另做一次纯重命名迁移，不与本提案混在一起。

### 5.2 类型匹配（Phase A）

- 只使用**扩展名**（小写、不带点）和用户标签；读取文件内容或 MIME 不在范围内。
- 建议条件：
  - 模板 `match.extensions` 非空；
  - 当前选择中存在扩展名命中的条目；
  - 展示“匹配 n/m 项”，按精确匹配数、置顶、最近使用排序；不设隐式阈值。
- 没有 `match` 的 v1 模板仍可在“全部模板”中使用，只是不进入“匹配当前选择”。
- UI 上的“图片/视频/文档/压缩包/其他”只是扩展名分组展示，不新造文件类型语义，也不写回模板。
- 匹配只是建议；**不自动选择、不自动过滤选中集、不自动 apply**。

### 5.3 绝对路径与可移植性

- 模板不保存 `sourcePaths`；源文件清单永远来自当前选择。
- 若某功能参数包含输出目录等绝对路径：
  - 保存时标记“本机路径”；
  - 导出时默认剔除该字段（或替换为占位符）；
  - 导入/应用时若为空或路径不存在，要求重新选择；
  - 不把本机路径当作模板适用条件。
- 模板不保存凭据、授权数据、文件内容、文件名清单。

## 6. 安全、授权与隐私

| 议题 | 规则 |
|---|---|
| 执行 | 模板只回填参数并生成计划；单步/逐步骤必须预览；**一键执行也以每步 plan/apply 为基础，首步先预览确认，风险步骤强制降级确认** |
| 脚本 | 模板只允许声明式参数；禁止脚本/宏/shell/任意 URL/外部命令 |
| 参数校验 | 载入与导入都按 `OperationKind` 的参数 schema 校验；未知/缺失/非法参数拒绝或明确标记，不静默丢弃 |
| 正则 | 沿用 E1005 的正则校验；导入模板中的正则同样校验，不因“来自模板”放宽 |
| 授权 | 每步 `OperationKind` 由 LicenseService 复核；模板不得内嵌层级/配额判断；不得保存许可证数据 |
| Web/WASM | 模板可存 OPFS、可导入导出；授权仍零强制力；不放行/拦截判定 |
| 导入 | 不可信输入；限制结构深度/规模，拒绝未知字段以外的危险载荷；高版本 `schemaVersion` 报 E1007 |
| Web | 模板存 OPFS、可导入导出；不承诺跨设备/跨会话留存；仍零强制力 |
| 隐私 | 不保存文件内容、文件名清单、绝对源路径；匹配只用扩展名与用户标签 |
| AI（Phase C） | 模板可作为 `loadRecipe` 的计划来源；AI 仍不得 apply；模板参数不扩展 AI 的数据边界 |

## 7. UI/UX 要点

- 入口：侧栏“规则配方”改为“处理模板”（2026-10-28 已确认）；图标语义与视觉在 U 后续升版收编，颜色/间距/字阶只用 U v1.3 token。
- 保存入口：预览页/参数区提供“保存为处理模板”，不是独立表单。
- 列表：搜索、置顶、最近使用、适用类型、功能名；空状态说明“保存一次，下次直接套用参数”。
- 应用：选中集不变；模板只回填参数；预览必须重新生成；不匹配项在预览中显示。
- 状态：无匹配、部分匹配、模板不兼容、高版本模板、路径需重选、授权不足（E4001）分别有明确文案与下一步。
- 多步骤（Phase B）：步骤列表显示“第 1 步/第 2 步”、输入来源、状态；一键执行时首步预览确认，后续无风险步骤自动 apply；风险/失败降级为逐步骤确认；失败停在当前步，已完成步骤可撤销。

## 8. 错误与边界

| 场景 | 处理 | 码位/依据 |
|---|---|---|
| 参数缺失/非法 | 拒绝保存/导入/载入，指出字段 | E1001／E1002（06 §2） |
| 正则非法 | 拒绝，保留原模板 | E1005（06 §2） |
| 模板 schemaVersion 更高 | 拒绝载入，提示升级 | E1007（06 §2） |
| 未知 OperationKind | 拒绝该模板/该步，提示“当前版本不支持” | 复用 E1002 或经 06 评审新增码位；不自行发明 |
| 参数在新版本被移除/改名 | 迁移函数处理；无迁移则标记不兼容，不静默丢参 | 设计 03 §6 迁移规则 |
| 选择与模板类型不完全匹配 | **处理全部**；非匹配项由功能校验/跳过/阻断，预览如实展示；0 匹配不启动一键 | 已确认（2026-10-28） |
| 输出路径不存在/无权限 | 载入时要求重选；执行前预检 | E1003／E2002 |
| 授权不足 | 计划/执行层拒绝，不因模板放行 | E4001（01 §3；不变量 5） |
| 多步骤某步失败 | 停止后续；已完成步骤可撤销；不自动跨步回滚 | 沿用 OQ-23 口径 |
| 模板被删除 | 已生成计划保留；预览不可再次 apply，提示重新选择 | 交互规则 |
| 导入超大/异常结构 | 拒绝并提示；具体规模上限按实现期安全校验回填 03/06，不新增产品阈值 | 安全校验 |

## 9. 测试与验收建议

**T 基线**：T v1.12 §2.2 已将 C37 扩为 6–8 条用例；**TC v0.3 已展开 C37 8 条与 B9 8 条**。本提案主张**不并入 28 条文件语料**：C37 是配置/复用能力，不产生文件管道异常语料，现有 `fixtures/corpus/manifest.md` 的 28 条清单也不含 C37。

| 用例 | 断言 |
|---|---|
| 保存单功能模板 | 从预览保存；参数一致；不保存源路径/预览结果 |
| 应用模板 | 回填参数；重新生成预览；未预览不能 apply |
| 类型建议 | 选图片时优先展示图片模板；不读内容；不自动应用 |
| 部分匹配 | 显示匹配 n/m；仍处理全部，由功能校验/跳过；0 匹配不启动一键 |
| v1 迁移 | v1 配方 → v2；参数不丢；可正常载入 |
| 导入/导出 | v2 JSON 往返；高版本 E1007；未知功能拒绝 |
| 路径可移植 | 绝对输出路径导出剔除/导入重选；不把本机路径当匹配条件 |
| 授权 | 模板含当前层级不允许的功能时，计划/执行层拒绝，不绕过 |
| 正则 | 非法正则导入被 E1005 拒绝 |
| Web | OPFS 存取、导入导出、零强制力；不放行/拦截 |
| 多步骤（Phase B） | 第 2 步以第 1 步产物为输入；一键执行时后续无风险步骤自动 apply；冲突/警告/高风险/授权失败立即降级逐步骤；失败停止；已完成步骤可撤销 |
| 一键执行风险闸门 | 高风险步骤模板禁用一键；任何 conflict/warning/blocked 不自动 apply；首步预览不可跳过 |
| 处理全部 | 模板不过滤选中集；非匹配项由功能校验/跳过；0 匹配不启动一键 |
| 安全 | 模板不能携带脚本/凭据/源路径；导入不可信模板不执行任何代码 |

**验收底线**：预览强制、模板不自动 apply、每步 LicenseService 复核、导入不执行、版本不兼容不静默丢参。
