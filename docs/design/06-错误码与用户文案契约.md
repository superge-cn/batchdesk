> 本表是**错误码单一登记处**。码位语义以本表为准；新增码位先改本表，再改代码与测试。数值、文案口径仍以基线为准，本表不定义产品阈值。

## 1. 规则

1. **分段固定**：E1xxx 输入/参数、E2xxx 文件系统/权限、E3xxx 编码/格式、E4xxx 授权、E5xxx 环境/依赖、**E6xxx AI/模型**、E9xxx 未知（方案 §4.6 增补 E6xxx）。
2. **只追加不改义**：已发布码位不得改语义或复用；废弃码位保留并标注“已废弃”。
3. **禁止平行错误处理**：任何模块不得自造码位或把内部字符串直接透出（AGENTS 不变量 3）。
4. **retryable 只表示“同一请求重试可能成功”**：权限、格式、授权、配置损坏等不得标 true。
5. **测试与语料只能用本表码位**：`fixtures/corpus/*/expected.md`、TC/TW 中出现未登记码位即视为缺陷；`scripts/check_docs.py` 会做白名单校验。
6. **用户文案不在此表写死**：只约定 key 形式 `error.<code>.summary` / `.detail` / `.action`，实际中英文文案由设计 09 的资源文件承载。

## 3. 文案 key 约定

```text
error.<code>.summary   一句人话摘要（方案 §4.6 提示三层的第一层）
error.<code>.detail    可展开详情（技术细节，进日志不出界面）
error.<code>.action    建议动作/下一步
```

- 同一码位在 `zh-CN` 与 `en-US` 必须有同名 key；缺失即构建失败（设计 09）。
- 文案不得暴露路径、文件名、许可证载荷或堆栈；`detail` 仅进诊断日志。
- 云端返回的码位在客户端**不得改写**（05 §4）；客户端只做展示与引导。

## 4. 与测试/语料的锚定

- `expected.md` 的“预期行为”应引用本表码位（若基线明确了错误行为）；仅“告警/跳过”而无码位的，不得为了凑码位而发明错误。
- TC/TW 的负面用例必须写明码位或“无码位告警”；缺陷单必须填码位（T §5.3）。
- 新增/改码位时同步：本表 → 01/02/03/04 对应段 → 代码 → 测试/语料 → 用户文案资源。
