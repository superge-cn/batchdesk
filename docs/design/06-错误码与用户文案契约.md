> 本表是**错误码单一登记处**。码位语义以本表为准；新增码位先改本表，再改代码与测试。数值、文案口径仍以基线为准，本表不定义产品阈值。

## 1. 规则

1. **分段固定**：E1xxx 输入/参数、E2xxx 文件系统/权限、E3xxx 编码/格式、E4xxx 授权、E5xxx 环境/依赖、**E6xxx AI/模型**、E9xxx 未知（方案 §4.6 增补 E6xxx）。
2. **只追加不改义**：已发布码位不得改语义或复用；废弃码位保留并标注“已废弃”。
3. **禁止平行错误处理**：任何模块不得自造码位或把内部字符串直接透出（AGENTS 不变量 3）。
4. **retryable 只表示“同一请求重试可能成功”**：权限、格式、授权、配置损坏等不得标 true。
5. **测试与语料只能用本表码位**：`fixtures/corpus/*/expected.md`、TC/TW 中出现未登记码位即视为缺陷；`scripts/check_docs.py` 会做白名单校验。
6. **用户文案不在此表写死**：只约定 key 形式 `error.<code>.summary` / `.detail` / `.action`，实际中英文文案由设计 09 的资源文件承载。

## 2A. 预警类别登记表（`PlanWarning.kind`）

- **本表是告警类别的唯一对照源**。内核是类别的唯一生产者；类别串（kebab-case）经 `web/src/warnings.ts`
  映射为界面 key `warning.<camelCase>.title`，两个语言包必须逐条齐全。`scripts/check_locales.py` 第 ⑪ 项做
  **三方逐类对齐**（本表 ↔ 映射表 ↔ 语言包）：漏接、多接、映射表外的 `warning.*` 文案都直接红；
  本表解析出 0 条时报「门禁自校失败」（探测器失效＝没有正例）。
- **追加即兼容、禁复用**（同 §1 对码位的规则）：新增类别必须先增本表，再补映射与两语言文案。
- **风险级不在本表另立判据**：判定取 `PlanWarning.riskLevel`（`safe`／`caution`／`danger`，设计 01 §2 的 DTO），
  界面按它上语气色；下表「缺省风险级」是实测快照，仅供评审认类别，改判定以代码与测试为准。
- **「语义」列不是界面文案**：它按内核 `suggestion` 的原意写成中文，用途是评审时认得出类别。界面显示的类别
  标题取语言包；**建议行（`suggestion`）目前仍是内核产出的技术文本**——它是否继续原样显示给用户，属 §5 待决
  （与 [OQ-38](../OPEN-QUESTIONS.md) 同族：技术细节给不给用户看），本表不替产品定案。

## 3. 文案 key 约定

```text
error.<code>.summary   一句人话摘要（方案 §4.6 提示三层的第一层）
error.<code>.detail    可展开详情（技术细节，进日志不出界面）
error.<code>.action    建议动作/下一步

warning.<kind>.title   预警类别标题（类别清单见 §2A）
```

- 同一码位在 `zh-CN` 与 `en-US` 必须有同名 key；缺失即构建失败（设计 09）。
- 文案不得暴露路径、文件名、许可证载荷或堆栈；`detail` 仅进诊断日志。
- 云端返回的码位在客户端**不得改写**（05 §4）；客户端只做展示与引导。

**落地边界（v1.4）**：`detail` 既已定为"仅进诊断日志"，**界面资源只需要 `summary` 与 `action` 两条**——`error.<code>.detail` 不建资源 key，界面上也不渲染 `IpcError.message`／`detail` 原文（它们在本仓库里同属技术串，常含绝对路径）。界面保留码位本身作为支持句柄。当前首批收口 21 个"界面真会遇到"的码位（壳层 11 个＋计划/执行条目里的 10 个内核码），其余码位若冒到界面则回退显示 `message` 原文并标记未本地化；映射表在 `web/src/errors.ts`，由 `scripts/check_locales.py` 第 8 项门禁。决策与边界见 [ADR-0061](../adr/0061-错误文案的界面分层与错误码映射表.md)。

## 4. 与测试/语料的锚定

- `expected.md` 的“预期行为”应引用本表码位（若基线明确了错误行为）；仅“告警/跳过”而无码位的，不得为了凑码位而发明错误。
- TC/TW 的负面用例必须写明码位或“无码位告警”；缺陷单必须填码位（T §5.3）。
- 新增/改码位时同步：本表 → 01/02/03/04 对应段 → 代码 → 测试/语料 → 用户文案资源。
- 新增/改预警类别时同步：§2A 表 → `web/src/warnings.ts` → 两语言包 → 测试；`scripts/check_locales.py` 第 ⑪ 项做三方逐类对齐，漏任一处即红（同 §2 码位的第 ⑧ 项手法）。
