# 07 云端服务端契约

> 状态：v0.1 草案·待评审 ｜ 日期：2026-10-28 ｜ 适用：云端服务端、web/（客户端已由 02/05 约束） ｜ 权威：02 §4、05 §4、方案 §13.1/§13.7/§13.8/§13.10.2、ADR-0006
>
> 本契约只定义**服务端实现面**；客户端命令与 DTO 沿用 01/02，不另立平行体系。身份方案、计费与配额分层仍待产品确认（见 `docs/OPEN-QUESTIONS.md` OQ-05）。

## 1. 边界

- **只做云端通道**：本地/WASM 通道不经过本服务；客户端不得因本契约新增本地判定逻辑。
- **服务端是云端强制力唯一归属**：配额、白名单、资源上限、任务沙箱均以服务端返回为准（05 §4）。
- **不记录文件内容与文件名**：日志仅任务 ID、大小、类型、耗时、结果码（方案 §13.7、§9.7）。
- **不定义新的产品阈值**：大小分档、资源上限、保留期一律引用方案 §13.10.2 与 §13.7 的单点表/配置项；本契约只定义字段与状态机。
- **AI 模型调用不属于云端文件处理通道**：F15-lite 由桌面壳直连 Provider（设计 14）；若未来统一走服务端，另立契约并复用本契约的配额/审计边界。

## 2. 端点

在 02 §4.2 的 8 个端点基础上，服务端必须实现：

| 端点 | 方法 | 服务端职责 |
|---|---|---|
| `/v1/sessions` | POST | 校验白名单（扩展名+魔数）、创建会话与配额预留；返回 `uploadSessionId`/`expiresAt` |
| `/v1/sessions/{id}` | GET | 断点查询：`expiresAt`、`receivedChunks`、`totalChunks`；过期/失效 `410 E5005` |
| `/v1/sessions/{id}/chunks` | PUT | 幂等接收块；校验块序号/长度/校验和；失败只作废该块（`422 E5012`） |
| `/v1/sessions/{id}/complete` | POST | 聚合校验（总长/块完整性）→ 创建任务 → 返回 `taskId`/`state` |
| `/v1/tasks/{id}` | GET | 返回 `TaskSummary`/`ApplyReport`/`resultCode`；不返回文件内容 |
| `/v1/tasks/{id}/result` | GET | 结果流；带长度与 ETag；到期 `410 E5006` |
| `/v1/tasks/{id}/cancel` | POST | 中止沙箱并即时清理；`202`；不产生回滚（云端无 Journal） |
| `/v1/tasks/{id}` | DELETE | 用户放弃：销毁沙箱/结果；`204`；再取 `E5006` |

## 3. 数据模型（草案）

```ts
interface UploadSession {
  uploadSessionId: string;        // 服务端生成，不可猜测
  accountId?: string;             // 匿名/登录待 OQ-05
  taskKind: string;               // 01 §3.2 OperationKind
  paramsDigest: string;           // 参数快照摘要，不存明文参数中的敏感值
  size: number; mime: string;
  totalChunks: number;            // 由 §13.10.2 配置项决定，不在此写死
  expiresAt: string;              // RFC 3339 UTC
  receivedChunks: number[];
  state: "created" | "uploading" | "completed" | "expired" | "aborted";
}

interface CloudTask {
  taskId: string;
  uploadSessionId: string;
  state: TaskState;               // 01 §6；云端 additional: cancelled = 中止+清理
  resultCode?: "completed" | "failed" | "expired-not-retrieved"; // 方案 §13.7 三态，措辞以基线为准
  createdAt: string; finishedAt?: string;
}
```

- 服务端不持久化原始文件内容；输入/中间产物在任务完成后即时删除，结果文件按 §13.7 的保留规则删除。
- `taskId`/`uploadSessionId` 必须不可枚举；对外只暴露 opaque id。

## 4. 状态机

```text
UploadSession: created → uploading → completed
                    └── expired（超时）
                    └── aborted（用户取消/删除）
CloudTask: queued → running → completed
                     ├── failed
                     └── cancelled（中止+清理，不回滚）
```

- 状态迁移必须幂等：重复 `complete` 不得创建两个任务；重复 `cancel`/`DELETE` 返回同一终态。
- 客户端轮询与 `task://progress` 的语义沿用 02 §4.1；服务端不推送本地 Journal 事件。

## 5. 配额与身份（待 OQ-05）

- **配额账本**：预留（会话创建）→ 消费（任务开始/完成，按产品口径）→ 退还（取消/失败且未实际消耗）；必须支持幂等键，防止重放重复扣减。
- **匿名/登录**：方案 §11.4-12 已确认“匿名可用＋登录提额”；具体身份协议、token 生命周期、跨设备策略待 OQ-05。
- **配额判定**：仅服务端记账；客户端展示 `quota` 只读值，不得扣减/退还（05 §3）。
- **超限**：`403 E1006`（白名单外）、`429 E4004`（配额耗尽）；响应体沿用 `{ error: IpcError }`。

## 6. 安全与隔离

- 强制 HTTPS，证书校验不可关闭；明文回退拒绝（`E5007`）。
- 白名单：扩展名＋魔数双校验；拒绝猜测性解析；解压类复用方案 §5.11 的路径穿越/解压炸弹防护。
- 沙箱：任务级独立进程/容器与临时目录，任务间不共享挂载；结束即销毁（方案 §13.7）。
- 上传：块级校验和；complete 时聚合校验总长与块完整性；失败不进入沙箱。
- 访问控制：任务/会话只能由创建者访问；匿名场景用不可猜测 id + 短期 token；禁止通过日志/错误信息泄露他人 id。
- 限流：按账号/IP/会话维度；具体阈值待 OQ-05，不在本草案写死。

## 7. 保留、清理与可观测性

- 输入与中间产物：任务完成/失败/取消后即时删除；结果文件按 §13.7 保留至下载完成或到期，先到为准。
- 清理任务必须幂等、可重试；删除失败要重试并记录结果码，不无限保留。
- 日志字段：任务 ID、大小、类型、耗时、结果码；不含文件名/内容/参数明文（方案 §13.7、§9.7）。
- 指标：队列深度、任务时延、失败率、配额拒绝率、清理积压；告警阈值属运维配置，不在本契约写死。

## 8. 验收锚点

- TW-E1…TW-E13（含 `GET /v1/sessions/{id}` 断点查询）。
- ADR-0006 §5 的 P1–P5（幂等、断点、块校验、会话过期、complete 聚合校验）。
- 方案 §13.7 的隐私/保留/白名单/沙箱行为；不得以“客户端已校验”替代服务端校验（05 §4）。
