# 10 日志与诊断契约

> 状态：v0.1 草案·待评审 ｜ 日期：2026-10-28 ｜ 适用：kernel、src-tauri、web、支持/诊断 ｜ 权威：方案 §4.6（双轨/提示三层）、§9.6（保留/脱敏）、§9.7（隐私）、01 §8（Journal）、03 §4.1（logging）
>
> 本契约定义**日志字段、分流、脱敏、保留与导出**；保留期/数值一律引用基线，不在此写死。

## 1. 双轨

| 轨 | 载体 | 用途 | 权威 |
|---|---|---|---|
| 操作日志（审计轨） | 本地数据库（桌面 SQLite；Web 会话内） | 撤销/审计报表/任务追溯（C06/C17/C58） | 方案 §4.6、10.2 |
| 诊断日志（运行轨） | 滚动文件（桌面；Web 会话内导出） | 异常、性能采样、环境信息 | 方案 §4.6、§9.6 |
| Journal | 按 plan 的 JSONL（01 §8） | “怎么撤”，与操作日志并存 | 01 §8 |

- 操作日志字段集以方案 §10.2 的 C17a 定义为权威；本契约只补工程字段名与类型，不复制基线字段说明。
- Journal 不是日志轨：不得把 Journal 当审计日志，也不得用操作日志替代回滚依据。

## 2. 类型

```ts
interface OperationLogRecord {
  id: string;                 // ULID
  ts: string;                 // RFC 3339 UTC，经 Clock 端口
  taskId: string; planId: string;
  entryId?: string;
  opKind: OperationKind;      // 01 §3.2
  phase: "start" | "entry" | "retry" | "rollback" | "finish";
  status: "ok" | "skipped" | "failed" | "overwritten" | "reverted";
  code?: string;              // 06 的错误码
  before?: string; after?: string; // 路径；受 logFullPaths 控制
  overallCompleted: boolean;  // 对应 C17a 的“是否整体完成”
  detail?: string;            // 技术细节，默认不进界面
}

interface DiagnosticLogRecord {
  ts: string;                 // RFC 3339 UTC
  level: "debug" | "info" | "warn" | "error";
  target: string;             // 模块/组件
  code?: string;              // 06 的错误码
  taskId?: string; traceId?: string;
  message: string;            // 技术消息，不含用户内容
  fields?: Record<string, string | number | boolean>;
}
```

- 线上 `LogRecord`（01 §3.2）是 UI/导出的**展示投影**，不要求包含全部内部字段。
- 新增字段必须可选/有默认值；删除/改义按 01 §9 的破坏性变更处理。

## 3. 脱敏与隐私

- 默认不记录文件内容；不记录完整路径（`logging.logFullPaths` 默认 false，03 §4.1）。
- 许可证 ID/设备指纹只记前缀；不记录许可证载荷、签名、激活码明文（方案 §9.6/§9.7）。
- 参数快照中的敏感值（如正则、替换文本）按功能风险等级决定是否记录；默认只记哈希/摘要。
- 诊断包/崩溃报告**默认关闭**；用户开启时先预览将上传内容（方案 §9.7）。
- 任何日志不得包含堆栈中的用户路径原文；导出前统一脱敏。
- **AI 助手**：默认不记录 prompt/response/文件名；只记录 `AiAuditRecord`（model/provider、intent kind、工具名、planId、错误码、耗时）。AI 会话历史仅会话内，可导出/删除；支持包不含 prompt/response。

## 4. 保留、轮转与清理

- 操作日志与诊断日志的保留期引用方案 §9.6；`logging.retentionDays` 只控制操作日志（03 §4.1）。
- Journal/备份/隔离目录的保留与撤销窗口同口径（方案 §7.8）；不得把日志保留期当作撤销窗口。
- 轮转策略（按大小/时间）属工程配置；阈值不写死在本契约，实现时以配置项单点管理并在 ADR 记录选型。
- 一键清理：清理配置/日志/备份/隔离目录；**不包含授权/试用状态**（OQ-12 已确认 2026-10-28，ADR-0009）。
- 日志损坏：保留损坏副本并回退/重建；不得静默清空（03 §6.1-3 的同原则）。

## 5. 导出与支持包

支持包（用户主动导出）建议包含：

- 版本/构建号/通道、OS/架构、配置（脱敏后）、最近诊断日志、错误码统计、复现步骤；
- **不包含**：文件内容、完整路径（默认）、许可证载荷/签名、设备指纹原文、激活码；
- 用户可在导出前预览/勾选；Web 形态只导出会话内日志（02 §3.4）。

导出格式：JSON + 可选文本摘要；字段稳定、可被支持工具解析。

## 6. 测试锚点

- C17a：字段集、供 C06 反查、脱敏开关、日志不含文件内容（TC §3 的 C17a 四条）。
- 保留期：窗口内可查、到期清理、清理失败可重试（测试以配置缩短窗口，不写死产品值）。
- 脱敏：路径开关、许可证/指纹前缀、诊断包预览。
- 损坏：数据库/日志文件损坏时保留副本、不静默清空。
- 一键清理：不删除授权状态（OQ-12 已确认）。
