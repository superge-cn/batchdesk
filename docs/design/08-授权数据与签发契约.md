# 08 授权数据与签发契约

> 状态：v0.1 草案·待评审 ｜ 日期：2026-10-28 ｜ 适用：crates/kernel（判定）、src-tauri（注入/存储）、签发工具/服务端 ｜ 权威：方案 §8.2–§8.9、§12.4、ADR-0003、01 §3 LicenseService
>
> ADR-0003 定义了“签什么、怎么校验、异常怎么分流”的原则；本契约把它落成**可实现的载荷、序列化、状态机与测试向量**。标记“候选”的项需评审后才能冻结。

## 1. 边界

- 客户端只依赖 `LicenseService` 抽象（01 §3，不变量 5）；许可证文件/激活码的解析、验签、状态迁移由实现自管，不进入 `ConfigDocument`。
- 授权数据单独加密存储，不与普通配置混放（方案 §8.5、篇 03 §8）。
- 本契约不定义试用期天数、单项次数、设备上限等产品值；一律引用方案 §8.2/§8.4/§8.9 与 §11.6 的确认结果。
- C-7 的六态样本依赖本契约的字段与签发工具；在冻结前 C-7 保持“阻塞”（`fixtures/bench/C-7-授权状态集/README.md`）。

## 2. 载荷（LicensePayload）

字段名与语义为工程契约；值的产品口径以方案 §8.8 为准：

```ts
interface LicensePayload {
  schemaVersion: number;      // 载荷版本，独立于产品版本
  licenseId: string;          // 全局唯一
  product: string;            // 产品代号
  sku: string;                // SKU/销售项
  tier: "G0" | "G1" | "G2" | "G3";
  featureBitmap: string;      // 功能位图（编码方式待定，见 §4）
  quotas: Record<string, number>; // 量级配额；键名与功能位图一致
  validFrom: string;          // RFC 3339 UTC
  validUntil: string;         // RFC 3339 UTC
  issuedAt: string;           // RFC 3339 UTC
  deviceFingerprint?: string; // 设备指纹摘要；离线绑定场景必填
  deviceLimit?: number;       // 设备上限；以方案 §8.4 为准
  nonce: string;              // 防重放随机数
}
```

- 不要在本契约复制 §8.8 的字段表；若两处冲突，以方案 §8.8 为准并修订本契约。
- `featureBitmap` 的编码（位图/列表/压缩）待评审；无论选哪种，必须可确定性序列化且可向前兼容。

## 3. 签名与序列化

- **算法候选：Ed25519**（方案 §8.3 示例）；最终算法、曲线/参数与库选型待评审，依赖须过 cargo-deny。
- **确定性序列化候选：RFC 8785 JCS**（JSON Canonicalization Scheme）；签发端与验签端必须使用同一规范，禁止依赖语言默认 map/struct 顺序（ADR-0003）。
- 签名覆盖范围：`LicensePayload` 全字段 + 版本/算法标识；**本地判定状态**（试用起算、最近运行、累计天数）与**完整性基线自身**也必须被签名/HMAC 覆盖（ADR-0003）。
- 密钥：私钥只在签发端/离线签发机，客户端内置公钥；支持 key id 与轮换，旧公钥保留一个过渡期；私钥泄露有吊销/黑名单流程。
- 编码：授权文件建议 JSON 载荷 + 分离签名（base64url）；短码激活码的压缩/分组格式待定。

## 4. 设备指纹

- 强因子：主板/固件 UUID、系统安装标识、机器 GUID、系统盘序列号；弱因子：网卡 MAC 集合、CPU 型号、内存总量、屏幕分辨率（方案 §8.4）。
- 指纹 = 规范化文本摘要（哈希），不上传原始硬件信息；弱因子不参与密钥派生（方案 §8.5）。
- 采集不足时**拒绝生成指纹**，不得退化为通用哈希（ADR-0003）。
- 匹配算法沿用方案 §8.4；本契约只定义输入字段与摘要格式，不复制匹配阈值。

## 5. 状态机

```text
unactivated → trial → activated → grace → expired
                    └── revoked
trial/activated/grace ──签名或完整性失败──▶ invalid（降级 G0，审计）
```

- 状态迁移必须持久化且可审计；**任何异常都不得延长/重启试用**（ADR-0003）。
- 时钟回拨按方案 §8.2 处理；联网时用服务端时间交叉校验，离线时用本地单调计时辅助。
- 降级不锁死：已产出文件不删不锁，正在执行的任务允许完成（方案 §8.2）。

## 6. 激活与恢复流程

| 流程 | 输入 | 输出 | 约束 |
|---|---|---|---|
| 在线激活 | 激活码/账号凭证 | 许可证 + 状态 | 服务端校验设备/配额；客户端不信任本地判定 |
| 离线激活（短码/文件） | 激活码/授权文件 | 许可证 + 状态 | 验签、SKU/产品匹配、有效期、nonce/导入缓存防重放 |
| 换机迁移 | 迁移申请码/解绑 | 新许可证 | 旧许可证吊销/黑名单；纯离线按方案 §8.4 的迁移申请码 |
| 恢复 | 损坏/不可读 | 恢复或重新激活 | 不静默放行；不重启试用（ADR-0003） |

- 在线/离线流程的产品分期见方案 §8.10；首批是否含离线激活以 §11.6-3 为准。

## 7. 错误与审计

- 授权错误码：E4001 未授权功能、E4002 过期、E4003 设备不匹配、E4004 配额耗尽、E4005 激活码无效（06 表）。
- 审计事件：许可证 ID、设备指纹前缀、结果码、时间；不记录完整指纹/载荷（方案 §9.6/§9.7）。
- 可疑篡改 → 降级 G0 + 审计；损坏/不可读 → 恢复通道；两者都 fail-closed（ADR-0003）。

## 8. 测试向量（签发工具就绪后）

1. 合法载荷 → 验签通过 → 状态/位图正确；
2. 任一字段改动 → 验签失败 → 降级/拒绝；
3. 过期/未生效/错误 SKU/错误产品 → E4002/E4005；
4. 设备指纹不匹配/不足 → E4003 或拒绝生成指纹；
5. 时钟回拨 → 降级 G0，不延长试用；
6. 重放同一激活码/授权文件 → 导入缓存拒绝；
7. 本地判定状态被篡改 → 签名覆盖失败 → 降级，不重启试用；
8. C-7 六态样本逐态断言（待 C-7 解阻）。
