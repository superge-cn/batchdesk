## 0. 范围声明（v1 解决四件事）

1. **路径规范化**：比较前的形态统一（§1）；
2. **大小写折叠策略**：按平台能力选择比较器（§2）；
3. **目标名合法性**：哪些名字在该平台上不可落盘（§2.1，v1.13 增补）；
4. **保护目录匹配**：名单的子树语义与命中处置（§3）。

**v1 明确不做**（留 §7 待决，防止隐性承诺）：8.3 短名展开、卷挂载点/mount 等价性、网络路径与本地路径的大小写语义差异、通配符匹配。

## 1. 路径规范化（纯函数）

```rust
/// 词法规范化：不触盘、不解析链接。kernel 内纯函数，可单测（不变量 1）。
pub fn normalize(path: &str) -> String;
```

规则（冻结后只增不改）：

| # | 规则 | 说明 |
|---|---|---|
| N1 | 分隔符统一 | `\` 与 `/` 在比较副本中等价处理；用户可见路径保持原样不改写 |
| N2 | 折叠重复分隔符 | `a\\b` ≡ `a\b` |
| N3 | 词法解析 `.` 与 `..` | 纯词法回退，**不触盘**；越出根的 `..` 视为非法（E1003） |
| N4 | 剥离长路径前缀 | `\\?\` 与 `\\?\UNC\` 剥离后参与比较；**落盘操作仍由 FsAdapter 统一加前缀**（§4.7，业务层禁止自拼，不变量 8） |
| N5 | 抹平尾部分隔符 | `C:\foo\` ≡ `C:\foo` |
| N6 | 保留原始大小写 | 规范化不折叠大小写（折叠是比较策略，见 §2） |

**不做**：符号链接/绕接点解析（走 `canonicalize`，§4）、环境变量展开、UNC 机器名/共享名大小写归一（§7）。

## 2. 大小写折叠（能力查询，不硬编码平台）

```rust
pub enum CaseSense { Sensitive, CaseInsensitive }
// FsAdapter 增补：fn case_sensitivity(&self) -> CaseSense;
```

- Windows / macOS → `CaseInsensitive`；Linux → `Sensitive`（判定权威 §5.13"唯一性校验在 Windows/macOS 用大小写折叠比较，在 Linux 区分大小写"）。
- kernel 通过 FsAdapter 端口取得能力再选比较器——**不写平台 if/else**（环境事实经端口注入，对齐不变量 1 的端口化精神；Web/WASM 适配层按浏览器文件系统语义返回，OPFS 视为 Sensitive）。
- 折叠仅用于**比较**（保护匹配、冲突判定、去重）；任何落盘与展示路径保持用户原样。

> **v1.13 实现说明**：适配层只做**平台先验**——Windows/macOS → `CaseInsensitive`、Linux → `Sensitive`（`platform::fs::case_sensitivity()`）。按**卷**探测（大小写敏感的 APFS 卷、开了 casefold 的 ext4 目录、Linux 上挂的 FAT/NTFS）未做，见 [ADR-0073](../adr/0073-目标名合法性改为能力值.md) §5。

### 2.1 目标名合法性（能力查询，v1.13 增补）

```rust
pub struct NameRules {
    pub illegal_chars: &'static [char],            // 只列这些字符，不做额外推断
    pub reject_control_chars: bool,                // 是否把 ASCII 控制字符也算非法
    pub reserved_names: &'static [&'static str],   // 保留设备名（按主名、ASCII 大小写不敏感）
    pub trailing_dot_space: bool,                  // 结尾空格/点是否非法
}
// FsAdapter 增补：fn name_rules(&self) -> NameRules;
// 两个冻结取值：NameRules::windows() / NameRules::posix()
```

| 平台 | 非法字符 | 控制字符 | 保留名 | 结尾点/空格 |
|---|---|---|---|---|
| Windows | `< > : " \| ? *` | 非法 | `CON`/`PRN`/`AUX`/`NUL`/`COM1–9`/`LPT1–9`（含 `CON.txt`） | 非法（系统会静默截断） |
| POSIX（Linux/macOS） | 仅 `/` 与 NUL | **合法**（除 NUL） | 无 | **合法** |

- 规则值由适配层给出、经计划输入注入（`PlanF12Input`/`PlanF13Input`/`PlanC04Input`/`PlanF11Input`/`PlanC10Input`，以及 apply 期的 `ApplyContext`/`ArchiveApplyContext`）；**kernel 不得出现 `cfg!(windows)` 判断**（§2 同一条纪律，ADR-0073）。
- plan 与 apply 必须用**同一套**规则：C10 在执行期会重算条目选择，规则分叉会造成「计划选中、执行判不安全」。
- 「空名/纯空白名」对所有平台都拒绝——那是产品级的"无意义名"，不随平台变化，故不放进 `NameRules`。

## 3. 保护目录匹配（§6.7 名单的落地语义）

### 3.1 匹配语义（冻结点）

| 项 | 语义 | 理由 |
|---|---|---|
| 匹配单位 | 目录路径条目（可为盘符根） | §6.7"保护目录名单" |
| 命中定义 | **子树保护**：目标位于任一保护条目子树内（含该目录本身）；文件目标按其父目录参与匹配 | 只保护目录本身无意义 |
| 路径形态 | **双形态匹配**：字面规范化路径（§1）命中，或 `canonicalize` 后真实路径命中，任一即保护 | 覆盖 symlink/junction 落入保护区的绕行；`canonicalize` 失败时降级为仅字面匹配并出 `PlanWarning` |
| 大小写 | 按 FsAdapter `case_sensitivity()` 选择比较器（§2） | 与文件系统实际行为一致 |
| 通配符 | **v1 不支持**（决策） | 保护名单是安全屏障：通配符扩大误配/漏配面且测试面陡增；"保护整棵目录"的真实诉求由子树语义满足；未来如需，追加 glob 语法另行冻结 |
| 名单来源 | 用户配置 `security.protectedDirs`，经参数传入 kernel | kernel 不读配置文件（不变量 1）；存储与迁移归篇 03 |

### 3.2 命中处置（与篇 01 机制衔接，强制力在 kernel 执行层 §8.5）

1. **plan 阶段**：命中条目标 `PlanEntry.blocked { code: "E2009", reason, hint }`（复用篇 01 §5 blocked 机制）——预览期即暴露，用户可见"为什么不可执行"；
2. **apply 阶段**：对每个条目**二次复核**（plan→apply 间名单或路径可能变化，与 §5.13 二次裁决同语义）；复核同时覆盖**源路径与目标路径**（rename/move 的目标及其父目录），命中条目记 `skipped` + E2009，**绝不执行、绝不静默**；目标路径在冲突二次裁决之后、落盘之前判定（契约 v1.2）；
3. 保护复核在 kernel 执行编排内完成，不信任壳层或入口门禁（§8.5 强制力边界）。
4. **名单变更（v1.2 壳层落地）**：若预览时保护名单来自 `ConfigDocument.security.protectedDirs`，apply 前壳层比较当前名单与预览快照；不一致即拒绝执行并提示重新预览（E1002 "protectedDirs changed after preview"），使旧判定失效；显式参数来源的名单以预览快照为准（调用方已显式给出）。

### 3.3 默认名单（边界声明）

契约层默认 `[]`。**已拍板（用户确认 2026-10-27）**：v1 不预置平台保护名单，风险由预览危险级提示承担（方案 §7.11）；预置系统目录列为二期增强候选，届时须一并设计不可被用户配置关闭的"硬保护"的 §8.5 复核路径。**已收编基线 §3.3／§9.2（11.6-9；历史收编于方案 v1.7 R71）**。

## 4. FsAdapter 能力增补（Rust 签名，篇 01 §3 的扩展）

```rust
pub trait FsAdapter: Send + Sync {
    // …… 篇 01 §3 既有方法不变 ……

    /// 解析 symlink/junction 后的绝对路径；失败（含不支持的平台）返回 Err，调用方降级
    fn canonicalize(&self, path: &str) -> Result<String, KernelError>;
    /// 平台大小写敏感能力（§2）
    fn case_sensitivity(&self) -> CaseSense;
}

/// 纯函数：子树判定（child 是否位于 ancestor 子树内），kernel 内可单测
pub fn is_under(child: &str, ancestor: &str, sense: CaseSense) -> bool;
```

- `is_under` 输入均为规范化后路径；实现必须防前缀字符串误判（`C:\foo` 不是 `C:\foobar` 的祖先——边界必须落在分隔符上）。
- Web/WASM 适配：`canonicalize` 基于 OPFS/目录授权句柄解析；浏览器无 symlink 语义时原样返回（Err 或恒等，按适配层能力声明）。

### 4.1 实现期增补（v1.1，纯增量）

- **内容指纹复核**：`FsAdapter` 增加可选 `content_hash(path, algorithm) -> Result<Option<String>, KernelError>`，默认实现返回 `Ok(None)`（适配层不支持时调用方降级为大小复核）；桌面 `CliFsAdapter` 对 `blake3` 返回小写十六进制摘要。该能力只服务 plan→apply 再校验，不改变 `plan_*` 纯函数边界。
- **Windows 长路径**：桌面适配器在调用 `std::fs` 前统一把绝对路径扩展为 `\\?\` / `\\?\UNC\` 前缀，返回给 UI/Journal 的路径再剥离前缀；kernel 与业务层仍禁止自拼前缀（不变量 8）。前缀逻辑属适配层内部，不进入线协议。**已落地（v1.3，2026-10-30）**：`CliFsAdapter` 全部操作、`platform::scan`（枚举/哈希/文件身份）、`platform::preflight`（probe_root/probe_write/path_check/probe_unc）、S02 `protected::prepare` 与壳层 canonicalize 显示值（`canonicalize_display`）统一收口；加前缀前先经 kernel `try_normalize` 归一分隔符与 `.`/`..` 段（`\\?\` 不吃 Win32 归一化），相对路径与 `C:` 盘符相对形式不加前缀。回归：`scans_long_paths_beyond_the_win32_limit`（Windows CI 真实 >260 字符深树）、`extended_path_*` 单测、`cargo check --target x86_64-pc-windows-msvc`。
- **S01 预检的 UNC 探测根（v1.10，2026-11-02）**：`\\host\share\dir\a.txt` 里能被"探测可达性"的单位是**共享名** `//host/share`——既不是叶子路径，也不是本地盘根。此前 S01 把整条路径交给 `probe_root`，在非 Windows 上会退化成探测本地 `/`，任何 UNC 条目都得到 E2002「路径不可达」，把方案 §4.9 的**降级**（不可达只警告、不阻断本地条目）变成了整单阻断。现由 `platform::preflight::unc_share_root` 只截到 `//host/share` 再交探测，截不出共享名（非网络路径）返回 `None`、按本地路径原样处理。锚点：`platform::preflight::tests::unc_share_root_picks_the_share_not_the_local_root`＋壳层 `tasks::tests::preflight_gate_warns_on_unreachable_unc_without_blocking_the_task`（设计 12 §S01）。
- **Windows 文件身份**：扫描适配器使用 `volume_serial_number` + `file_index` 生成 `FileIdentity`；无法取得身份时仍回退为 `needs_manual_review`，不自动清理。
- **同卷判定/单文件删除/逐级建目录（v1.9，2026-11-01，服务 C07 清单驱动移动；C07 切片登记时曾误标 v1.5，v1.5 实为 F09 区间读取）**：`same_volume(a,b)`（缺省 false＝保守按跨盘处理；桌面实现复用 S01 的 probe_root＋元数据比对）、`remove_file(path)`（仅供跨盘移动校验通过后删源——数据已存在于目标，属移动语义后半步而非内容删除）、`create_dir_all(path)`（目标子目录自动创建，不记 Journal）。三者缺省 E5001/false，调用方按契约拒绝或降级；桌面 `CliFsAdapter` 均已实现。
- **隔离备份与路径预留（v1.4，2026-10-30，服务设计 01 §8 dataRef 语义）**：`FsAdapter` 追加两个可选能力——`backup_to_quarantine(path)`（把原文件**复制**进隔离目录并返回备份路径，供覆盖类动作撤销还原）与 `quarantine_target_path(file_name)`（在隔离目录预留一个不存在的新路径，供"新建产物撤销＝产物进隔离目录"的 reverse 记录）。默认实现返回 E5001，调用方按契约拒绝该动作、不静默降级；桌面 `CliFsAdapter` 均已实现（命名与 `remove_to_quarantine` 同式，长路径前缀收口同样生效）。
- **区间读取（v1.5，2026-10-30，服务 F09 位置行抽取）**：`FsAdapter` 追加 `read_ranges(source, ranges) -> Result<Vec<u8>, KernelError>`——按顺序读取给定字节区间到内存，只读区间、不整文件读入；区间非空且必须落在源文件范围内（缩短/越界返回 E2010），默认实现返回 E5001。桌面 `CliFsAdapter` 按 64 KiB 块 `seek+read` 实现，空区间与越界拒绝；F09 apply 只读取表头区间与选中记录区间，不调用 `read_bytes`。
- **流式原子写（v1.6，2026-10-30，服务 F10 目录清单）**：`FsAdapter` 追加 `write_atomic_with(path, write)`——适配层创建临时文件，把 `&mut dyn Write` 交给回调流式写入，flush 后原子改名；回调失败清理临时文件并原样返回错误，默认实现返回 E5001。桌面实现与 `write_atomic` 共用长路径/临时文件/Windows 替换语义；F10 的 CSV 逐行写出不整段缓存。
- **目录创建/删除（v1.7，2026-10-30，服务 F11 按清单建档）**：`FsAdapter` 追加 `create_dir(path)`（只创建单级目录，父目录由计划保证）与 `remove_dir_if_empty(path)`（只删除空目录，非空必须失败，禁止递归）；默认实现返回 E5001。桌面 `CliFsAdapter` 经长路径收口实现；F11 计划逐级展开条目，撤销按 Journal 逆序删除空目录。
- **流式读取（v1.11，2026-11-02，服务 F04 合并与后续大文件路径）**：`FsAdapter` 追加 `read_stream(path, read)`——适配层按自选块大小回调（桌面 64 KiB），回调返回错误即中止并原样上抛；默认实现返回 E5001，**调用方不得静默降级为 `read_bytes`**（否则"流式"只是名义上的）。F04 合并改为 `read_stream`＋`StreamTranscoder`＋`write_atomic_with`，内存 O(块) 而非 O(产物)。锚点：`platform::fs::tests::read_stream_delivers_bounded_chunks_and_propagates_the_callback_error`、`generic_apply::tests::merge_transcodes_inputs_in_order_and_undo_removes_the_output`（断言 `read_bytes` 调用 0 次、块大小 ≤3 字节）。
- **拉取式读取（v1.12，2026-11-03，服务 C13 外排归并）**：`FsAdapter` 追加 `open_read_stream(path) -> Result<Box<dyn Read + Send>, KernelError>`——与 push 型 `read_stream` 并存：顺序扫描用前者，多路归并要「比较 k 个游标、取最小、再要下一条」，只有拉取式能表达。缺省实现返回 E5001，**调用方不得静默降级为 `read_bytes`＋内存游标**（否则「流式」只是名义上的）。桌面 `CliFsAdapter` 用 `File::open`＋`BufReader`，长路径收口与读取错误映射同 `read_bytes`。锚点：`platform::fs::tests::open_read_stream_pulls_bytes_on_demand_and_reports_missing_files`、`generic_apply::tests::csv_sort_external_merge_streams_the_source_and_pulls_each_chunk`（断言源侧 `read_bytes` 0 次、每块各开一次拉取流）。
- **流式原地重写（v1.8，2026-10-31，服务 C02 换行转换）**：`FsAdapter` 追加 `rewrite_atomic_with(path, rewrite)`——适配层打开源文件与临时文件，把 `&mut dyn Read`/`&mut dyn Write` 交给回调流式读写，flush 后原子改名；回调失败清理临时文件并原样返回错误，默认实现返回 E5001。桌面 `CliFsAdapter` 与 `write_atomic_with` 共用长路径/临时文件/Windows 替换语义；调用方先备份原文件并写 Journal，源文件在改名成功前保持不变。
- **原子复制（v1.14，2026-11-08，D3 实机缺陷修复）**：`copy`、跨卷 `move_file` 与 `backup_to_quarantine` 统一走 `copy_file_atomic`——同目录临时文件写入、校验写入字节数与源大小一致后再 `rename` 到目标；失败只删临时文件，**不先删除既有目标**，因此断线/短写不会在最终目标路径留下 0 字节半成品，也不会破坏原有文件。`rename` 在 Windows/Unix 均可替换既有文件（桌面 CI 双平台回归），故不再需要"先删后改名"的 Windows 分支。锚点：`platform::fs::tests::failed_copy_preserves_an_existing_target`、`failed_copy_leaves_no_zero_byte_target`（Unix）、`short_or_failed_copy_never_reaches_the_target_path`、`copy_replaces_existing_target_and_cleans_the_temp_file`；决策见 [ADR-0083](../adr/0083-实机缺陷D3D4的安全默认修复.md)。
- **断线重试与 Windows 网络错误映射（v1.15，2026-11-08，D1/D2 实机缺陷修复）**：`io_error` 把 Windows `raw_os_error` 64/59/121/1236（NETNAME_DELETED／UNEXP_NET_ERR／SEM_TIMEOUT／CONNECTION_ABORTED）显式映射为 **E2005（retryable）**；执行器只在**触及 UNC 路径**的条目上按方案 §4.9 做最多 3 次重试、退避 2/4/8 秒，耗尽后桌面壳把任务置 `paused` 并提示、CLI 以 E2005 中止整任务（CLI 无暂停交互面）。`NetworkRetry` 是注入端口，kernel 不 sleep、不读时钟；`edit-content`/`transcode` 不在重试族（重试会重复落备份）。锚点：`platform::fs::tests::windows_network_disconnect_maps_to_e2005`、`kernel::generic_apply::tests::network_disconnect_is_retried_three_times_then_pauses_and_resumes`、`kernel::apply::tests::c09_network_disconnect_is_retried_three_times_then_pauses`、`tasks::tests::auto_pause_sets_reason_and_resume_clears_it`、`platform::tests::archive_network::c10_extract_retries_network_inspect_three_times_then_pauses`；C10 归档执行器（inspect/compress/write_atomic/write_atomic_with/stat/create_dir）已接入同一端口，`platform::archive` 把 ZIP 读与源文件读的网络错误保持 E2005；决策见 [ADR-0084](../adr/0084-实机缺陷D1D2D5的断线重试与两阶段Journal.md)。
