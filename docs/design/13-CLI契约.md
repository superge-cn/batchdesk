# 13 CLI 契约（C40，P1）

> 状态：v0.10 草案·占位（不进入阶段 0；2026-10-29 追认 C09 实验切片；2026-10-31 扩展 C01/C02/C03 与 F01–F13 实验命令，OQ-30） ｜ 日期：2026-10-31 ｜ 适用：crates/cli ｜ 权威：方案 §9.5（CLI 与 GUI 共用内核）、§7.1（plan/apply）、01/06

> C40 属 P1；本文件只锁定“CLI 不得另造一套逻辑”的边界与未来命令面的占位，**尚未评审冻结**。

## 1. 原则

- CLI 与 GUI 共用 `crates/kernel`；不得复制 plan/apply、错误码、撤销逻辑（方案 §9.5、AGENTS 不变量 2/4）。
- 默认安全：不覆盖、占位文件跳过、删除进隔离目录（方案 §4.5）。
- 所有写操作先 plan 后 apply；plan 为纯函数、绝不落盘。
- 输出分两档：人可读文本（默认）与机器可读 JSON/JSONL（`--json`）；错误必须带 06 的码位。

## 2. 命令面（草案，未冻结）

```text
batchdesk --version
batchdesk plan   --kind <f01..> --input <path...> [--param key=value...] [--json]
batchdesk apply  --plan <plan.json> [--on-conflict skip|sequence|overwrite] [--json]
batchdesk undo   --plan <planId> [--json]
batchdesk config get|set|reset [--scope <scope>] [--json]
```

- `plan` 只产出 `PlanDocument`（01 §5），不落盘；`apply` 消费计划并按 Journal 执行。
- `--json` 输出使用 01 的 DTO；人可读输出不得改变判定语义。
- 退出码（草案）：0 成功；非 0 由 06 的码位映射到稳定类别，具体表待评审。

### 2.1 实验切片命令追认（OQ-30，2026-10-29 用户确认；2026-10-30 扩展）

`crates/cli` 既有命令 `c09`（检测/计划预览）、`apply`、`undo`、`cleanup` 追认为 **C09 纵向切片的实验性命令**（PDR-001 授权）；C01 `c01`、C02 `c02`、C03 `c03` 与 F01–F13 的 `f01`…`f13` 计划命令与复用同一 `apply` 路由的切片追认为 **功能切片实验命令**。二者均不构成本契约 §2 命令面的冻结：

- 命令形状以设计 01（§4/§5 DTO）与仓库 README 快速开始为准；正式命令面冻结评审时，将其归并进 §2 形状或明确保留为专有入口；
- 实验命令只随对应功能切片存在，只增加该切片所需参数；不得借此新增与功能切片无关的命令，也不得改变 `apply`/`undo` 的既有语义；
- 本节清单按切片增量维护（当前 C09、C01、C02、C03、F01–F13）；新增 `fNN` 实验命令须在同一 PR 更新本节清单，未登记不得发布；
- 退出码沿用临时口径（0 成功/非 0 失败，stderr 带 06 码位），正式退出码表仍挂 §4 待决。

## 3. 安全与边界

- 不接受“跳过预览直接执行”的默认路径；如提供 `--yes`，必须先展示变更摘要并二次确认。
- 网络盘/占位文件/保护目录按 GUI 同一规则处理，不因 CLI 放宽。
- 授权：CLI 与 GUI 共用 `LicenseService` 注入；不得在 CLI 内自建层级判断。
- 日志/审计走 10 的同一套记录；CLI 不另建日志格式。
