# 未签名安装包说明（Windows）

> 状态：草案（内部验证用，未评审）｜日期：2026-11-24｜适用：`src-tauri`、`.github/workflows/release.yml`、发布／运维
> 权威来源：设计 11《发布、签名与更新契约》、ADR-0002《二进制加固与混淆边界》、方案 §9.1／§11.5／§11.6、OQ-06、OQ-11。
> 本文只记录**当前实现与缺口**，不定义产品行为、不另立数值。

## 1. 一句话结论

现在能产出 Windows 安装包（NSIS），**但未签名**。未签名的产物只能用于内部验证与测试安装，**不得对外分发**（ADR-0002 §4①；设计 11 §3、§6）。

## 2. 产物形态与路径

| 产物 | 路径（构建机） | 说明 |
|---|---|---|
| NSIS 安装包 | `src-tauri/target/release/bundle/nsis/BatchDesk_<version>_x64-setup.exe` | `<version>` 取自 `src-tauri/tauri.conf.json` 的 `version`；当前按用户级安装（`currentUser`），不需要管理员 |
| 裸可执行文件 | `src-tauri/target/release/batchdesk-desktop.exe` | 未打包运行时；同样未签名 |
| 校验和 | `src-tauri/target/release/bundle/nsis/SHA256SUMS.txt` | 仅工作流生成（本地构建需自行算）；**只能防传输损坏，不能证明来源** |

当前**不产出**：MSI、增量/差分包、更新清单、任何签名文件。原因见 §7。

## 3. 配置要点

`src-tauri/tauri.conf.json` 的 `bundle` 段：

- `active: true`、`targets: ["nsis"]`——只构建 NSIS，不引入 WiX（MSI 是否需要待裁决，见 §7）。
- `icon`：`icons/32x32.png`、`icons/128x128.png`、`icons/128x128@2x.png`、`icons/icon.icns`、`icons/icon.ico`（均为仓库既有文件，未新增美术资源）。
- `windows.webviewInstallMode: downloadBootstrapper`——安装时在线拉取 WebView2（最小体积方案；离线安装变体待裁决）。
- `windows.nsis.installMode: currentUser`、`windows.nsis.languages: ["SimpChinese", "English"]`——与方案 v1.15 确认的中英双语范围一致（安装器按 OS 语言自动选择，未开放语言选择器）。
- `createUpdaterArtifacts: false`——更新包需签名密钥（OQ-06 托管位置未定），显式关闭以免误产出无签名更新包。
- **未填写** `publisher`、`copyright`、`licenseFile`：涉及法律主体、版权年与 EULA 口径，未定前不发明（见 §7）。

`src-tauri/Cargo.toml`：

- 新增 `[profile.release]`（`strip = "symbols"`、`lto = true`、`codegen-units = 1`、`panic = "abort"`）。`src-tauri` 是**独立 workspace**，不继承根 `Cargo.toml` 的发行 profile；不重复声明的话，安装包里的二进制会带完整符号，与 ADR-0002 §3 的发行构建要求不符。取值与根 `Cargo.toml` 完全一致，未新增参数。

CSP、`capabilities`、`withGlobalTauri`、`freezePrototype` 等安全配置**未改动**。

## 4. 本地构建

前置条件（与 `cargo tauri info` 的输出对照即可）：

- Rust stable（MSVC 工具链）＋ `wasm32-unknown-unknown` target；
- Node 22 / pnpm 12.16.1；
- `wasm-bindgen-cli`：**版本必须与 `Cargo.lock` 中 `wasm-bindgen` 一致**（当前 `0.2.130`），不一致时 `wasm-bindgen` 直接报版本错误；
- NSIS 与 WebView2 引导器由 Tauri CLI 在首次打包时自动下载（需要网络）。

命令（仓库根目录执行）：

```bash
pnpm install --frozen-lockfile
pnpm install --frozen-lockfile --dir web
cargo install wasm-bindgen-cli --version 0.2.130 --locked   # 已装可跳过，但版本必须对齐
node scripts/build-wasm.mjs                                  # 生成 web/wasm/（不入库）
pnpm tauri build --ci --no-sign
```

注意事项：

- `web/src/lib/wasm/*.ts` 静态引用 `web/wasm/batchdesk_wasm.js`（`.gitignore` 排除、不入库），**跳过 `build-wasm.mjs` 会让 `pnpm build` 直接 TS2307 失败**。
- `tauri build` 会经 `beforeBuildCommand` 再跑一次 `pnpm build`，所以前端会构建两次（一次供 §5 的 CSP 断言，一次给打包用）。这是刻意保留的重复，避免断言跑在过期产物上。
- `--no-sign` 是**显式**声明"不签名"，不是省略。将来证书就位后应删掉该参数并另立流程，不要在这里打开。

## 5. 工作流触发（`.github/workflows/release.yml`）

- 触发：Actions → release → Run workflow（`workflow_dispatch`）；或推送 `v*` 标签。
- 单 job（`windows-latest`），步骤：装依赖 → 构建 WASM → 构建前端 → 产物 CSP 前置断言（`scripts/check_dist_csp.py`）→ `pnpm tauri build --ci --no-sign` → 生成 SHA256 → 上传 artifact。
- artifact 名：`batchdesk-windows-unsigned-<commit sha>`，内容含安装包、裸可执行、`SHA256SUMS.txt`。
- **不做**：代码签名、创建 GitHub Release、上传商店/下载站。`permissions` 只给 `contents: read`。
- **版本号唯一来源是 `src-tauri/tauri.conf.json` 的 `version`**；tag 名只用来看，不参与产物命名——发 `v0.2.0` 标签而配置里还是 `0.1.0`，产物仍是 `0.1.0`。发布前人工核对两者一致。
- 与 `ci.yml` 的关系：两者互不替代。发布前的 lint/deny/test 门禁结论仍以 `ci.yml` 在该 commit 上全绿为准（设计 11 §6），本工作流不重复跑六 job。

## 6. 未签名意味着什么

| 影响 | 具体表现 | 处理口径 |
|---|---|---|
| SmartScreen 拦截 | 首次运行安装器出现"Windows 已保护你的电脑"，需"更多信息 → 仍要运行" | 只在内部验证/测试安装时告知；**不得**把该绕过步骤写进对外说明或用户手册 |
| 杀软误报 | 未签名二进制更易被判可疑，尤其带文件批处理行为时（方案 §11.2 已单列该风险） | 内部验证时记录误报样本，作为后续签名必要性的证据 |
| 来源不可证明 | 任何人都能改包重发；SHA256 只能防传输损坏，不能证明"这是官方构建" | 产物只在内部流转；对外分发一律等签名流程（ADR-0002 §4①） |
| 无时间戳 | 即使日后补签名，也无法回溯证明这批构建的产出时间 | 需要可信时间戳的诉求随证书采购一并决定（设计 11 §3 待决） |
| 企业策略拦截 | 域内终端可能直接阻断未签名安装器 | 域内部署需先拿到签名口径 |
| 与发布检查清单不一致 | 设计 11 §6 的"安装包签名/校验通过"一项未过 | 本产物**不满足发布条件**，只能算中间物 |
