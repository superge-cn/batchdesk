## 1. 设计原则

### 1.1 视觉基调决策记录

**决策**：视觉基调取 **A——Fluent 2 语义 ＋ shadcn/ui 实现的混合基调**（状态：已确认）。

**a）问题**：在 **Tauri（Web 前端）＋ Windows 办公用户 ＋ 数据密集型 UI** 三个条件同时成立时，视觉基调如何选型——既要"原生 Windows 办公感"，又不能依赖任何系统原生控件。

**b）四步方法**

| 步 | 内容 | 结论 |
|---|---|---|
| ① 锚定约束 | 用户心智（1.2 的目标用户为非技术办公人员）／技术栈（4.1 推荐的 Tauri ＋ Web 前端）／内容形态（6.2 的十万行级数据密集）／商业边界（闭源分发，不能引入需随附源码或受限许可的资产） | 约束即上述四条件 |
| ② 候选打分 | 按"办公熟悉度／实现成本／定制上限／长期维护"四项对 A／B／C 打分 | 见 c） |
| ③ 硬约束校验 | 状态色须与 7.11／6.2 保持唯一映射；须支持十万行密度的两档行高（§4） | 通过（A 与 B 均满足；C 需自建组件库，成本不可控） |
| ④ 盲测（5–8 人） | 三个问题：更放心／更像 Office 生态／更愿意每天用 | **待复核**——本轮未执行，本决策按现有论证生效 |

> 步④的状态如实记为**待复核**（**不得读作"已验证"**）。复核若出现偏差，按 5 的处理流程回填本档并升版。

**c）三候选结论**

| 候选 | 结论与理由 |
|---|---|
| **A 混合基调** | **选用**。Fluent 提供视觉语义与状态语言（办公用户的熟悉度），shadcn/ui 提供组件与无障碍实现（闭源分发可用的实现路径），token 层做定制以兼容两者（第 2 章三层架构） |
| B 纯 shadcn 默认风 | 实现成本最低，但与 Office 生态存在可感知的视觉缝隙；**记为保底退路**（非当前路线） |
| C 纯 Fluent 复刻 | Web 前端无法使用系统原生控件，需自建并长期维护私有组件库，与 4.11.3 成本红线的精神相悖——**否决** |

**d）后果与退路**

- **后果**：第 2 章三层架构中的**语义层以 Fluent 语义映射为基准**；**组件层基于 shadcn／Radix 扩展**（组件结构不重写，只覆盖 token 值）；
- **退路**：若后续发现定制能力不足，退路为**把语义层映射回 shadcn 默认值**——**架构不动**（三层结构与变量名不变，只换映射值）。

**e）法律边界声明**：本档仅采用 Fluent 的**风格与语义**，**不使用 Segoe UI、Fluent Icons 等微软受保护资产**；中文字体栈与图标库按 2.2（微软雅黑为主的系统字体栈）与第 8 章（lucide）的既定方案执行。

### 1.2 四条原则与 A 路线的对应关系

四条原则全部与方案的"安全优先于效率"（7.1 的总原则）对齐，视觉层不为"看起来更快"牺牲"看得更准"。

| 原则 | 含义 | 视觉落点 |
|---|---|---|
| **清晰可扫读**（数据密集优先） | 界面第一任务是让人一眼分辨"哪些会变、哪些有风险"，而不是展示装饰 | 中性色承担 90% 面积；强调色只用于状态与操作；行高、分隔线、数字等宽列（§4） |
| **状态可预期** | 同一状态在任何界面都长同一个样，用户不需重新学习 | 状态色单源（2.1.3）；组件状态矩阵（§3）；同一状态禁止两种外观 |
| **警示分级与 7.11 对齐** | 绿／黄／红三级与方案的提示分级一一对应，不新增第四级 | 状态色家族只有 safe／warn／danger 三色（2.1.3） |
| **密度可调** | 十万行场景下用户能自行选择密度（引用 6.2 的"仅统计视图"与虚拟滚动） | 行高两档＋统计视图专用版式（§4） |

**四条原则是 A 路线的展开**：清晰可扫读 ← Fluent 的数据密度语义；状态可预期 ← Fluent 的状态色体系；警示分级 ← 与 7.11／6.2 的唯一映射；密度可调 ← shadcn／Tailwind 的两档行高实现。

**一条反向约束**：视觉不得引入方案未定义的语义。例如不使用"紫色＝高级功能"这类方案中不存在的含义；需要新语义时记入附录 B，不自行发明（自检⑤）。

## 2. Token 体系（三层架构）

### 2.0 三层结构与命名规则

| 层 | 作用 | 命名 | 谁可以引用 |
|---|---|---|---|
| **primitive 原始层** | 纯色值、纯尺寸，无业务含义 | `--n-*`（中性）、`--brand-*`（品牌）、`--status-*`（状态）、`--scale-*`（尺寸） | 仅 semantic 层 |
| **semantic 语义层** | 把原始值绑定到用途，**与 shadcn/ui 的 CSS 变量名对齐** | 沿用 shadcn 约定：`--background`／`--foreground`／`--card`／`--border`／`--ring`／`--destructive` 等 | 组件层与业务样式 |
| **component 组件层** | 单个组件的专属覆盖 | `--btn-primary-bg` 形式 | 仅该组件内部 |

**命名规则**：小写＋连字符；层级前缀不重复（`--n-n-100` 这类双前缀禁止）；**同一视觉值不得有两个名字**（自检②）——需要别名的场合，用 semantic 层指向 primitive，而不是在 primitive 层再造一个同值 token。

**与 shadcn/ui 的兼容约定**：semantic 层的变量名**直接采用 shadcn/ui 的既有约定名**（`--background`、`--foreground`、`--card`、`--card-foreground`、`--popover`、`--popover-foreground`、`--primary`、`--primary-foreground`、`--secondary`、`--secondary-foreground`、`--muted`、`--muted-foreground`、`--accent`、`--accent-foreground`、`--destructive`、`--destructive-foreground`、`--border`、`--input`、`--ring`、`--radius`）。这样做的收益：shadcn 组件不改其自身样式文件即自动套用本项目视觉；我们只覆盖变量值。**D-U1 的"双层混合"落地方式**＝Fluent 2 决定**语义与形态**（层级、密度、状态含义），shadcn/ui 决定**实现形态**（组件结构与变量名）。

### 2.1 色彩

#### 2.1.1 中性阶（9 档）

| token | 亮色主题值 | 主要用途 |
|---|---|---|
| `--n-000` | `#FFFFFF` | 最上层表面（卡片、对话框）。**不属于 9 档序列**，仅作表面基准白 |
| `--n-100` | `#F5F7F9` | 应用画布底色（亮） |
| `--n-200` | `#E7EBEF` | 分区底、表头底、悬停底 |
| `--n-300` | `#D2D8DE` | 分隔线、控件描边 |
| `--n-400` | `#AEB7C0` | 禁用描边、图形弱对比 |
| `--n-500` | `#87929D` | **仅占位符、禁用文字、图标**（对白底约 3.2:1，不满足正文 4.5:1） |
| `--n-600` | `#66707B` | 次级正文（对白底约 5.0:1）、暗色描边 |
| `--n-700` | `#4A535C` | 高对比描边、暗色悬停底 |
| `--n-800` | `#242B33` | 暗色卡片／浮层底 |
| `--n-900` | `#171C22` | 正文（亮）／暗色画布底 |

中性序列承担全部大面积着色；**强调色只出现在"状态"与"主操作"两处**。

#### 2.1.2 品牌阶（占位）

| token | 值 | 用途 |
|---|---|---|
| `--brand-500` | `#占位` | 主操作、选中态、焦点环基准 |
| `--brand-600` | `#占位` | 主操作悬停／按下 |
| `--brand-100` | `#占位` | 选中底、浅色强调面 |

> **品牌色相约束（硬规则）**：最终值须与 safe（绿）、warn（黄）、danger（红）三色相的**间隔均 ≥30°**，避免品牌色被误读为状态。选定后须做一次色相距离核对并留档。

#### 2.1.3 状态色（单源，三处共用）

| 语义 | token（亮色） | 亮色值 | 对应语义来源 |
|---|---|---|---|
| 安全 | `--status-safe-fg` / `-surface` / `-border` | `#17794A` / `#E8F5EE` / `#7FC3A0` | **7.11 三级提示的"安全（绿）"** |
| 注意 | `--status-warn-fg` / `-surface` / `-border` | `#8A6100` / `#FFF3D1` / `#D9A521` | **7.11 的"注意（黄）"＋ 6.2 的黄色角标** |
| 危险 | `--status-danger-fg` / `-surface` / `-border` | `#B3261E` / `#FDE7E5` / `#D64C42` | **7.11 的"危险（红）"＋ 6.2 的红色角标** |

**唯一性声明（本节是全档最关键的一条）**：7.11 的绿／黄／红三级提示、6.2 的 Web 版黄／红两色角标、6.4 预览差异高亮（见下），**共用同一对（同一组）token**——黄角标就是 `--status-warn-*`，红角标就是 `--status-danger-*`；**全文禁止出现第二套警示色**（自检①）。

**语义来源（1.1 落定后补）**：状态色的**语义取 Fluent 映射基准**（即"安全／注意／危险"三级的含义与使用场合沿用 Fluent 的状态语言），**数值经本规范第 7 章的对比度校验后落定**——上表三组色值即为校验通过的结论值，与本档 §5.2 的暗色换值配套。语义换算与数值定稿是两件事：前者由 1.1 的 A 路线决定，后者由本档 §7 的硬约束决定。

**差异高亮的取值方式（重要说明）**：6.4 的新旧对照表需要"新增／删除／变更"三种差异色，它们**不新开色板**，而是**复用状态家族的三个色相**：

| 差异类型 | 复用 token | 强制附加标记 | 说明 |
|---|---|---|---|
| 新增（新值出现） | `--status-safe-*` | 前缀字形 `+` | 列标题写明"新值"，语义是"从旧到新"的方向，**不表示"对／错"** |
| 删除（旧值消失） | `--status-danger-*` | 前缀字形 `−` | 同上，列标题"旧值" |
| 变更（值被改写） | `--status-warn-*` | 前缀字形 `~` | 冲突／非法／超长等异常状态由"状态"列的文字承担（对应 6.4 的状态与原因说明列） |

之所以强制"色 + 字形 + 列名"三重表达，是因为**差异高亮必须色盲安全**（§7）：红绿组合对红绿色盲不可辨，字形与列名是唯一可靠的冗余通道。

#### 2.1.4 品牌主色候选方向（D-U3，三选一）

| 方向 | 理由 | 风险 |
|---|---|---|
| **沉稳蓝**（推荐） | 与 Windows 原生办公感、Fluent 体系一致；蓝与三个状态色相隔最远，不产生误读 | 是同类工具最常见的选择，品牌辨识度较低 |
| **青绿** | 数据工具的"清爽、可计算"联想，与办公文档类工具形成区分 | 与 safe 绿的色相距离偏近，需按 2.1.2 的 ≥30° 规则单独核对；若选此方向，建议 safe 绿向深绿偏移 |
| **深青灰** | 极克制、近乎中性，让状态色成为唯一强调，契合"安全优先"的调性 | 品牌存在感弱，长时间使用偏沉闷，营销物料上不易延展 |

最终值由产品所有者选定（见附录 B）。

### 2.2 字体（D-U4）

#### 2.2.1 字体栈

```css
--font-sans: "Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC",
             "Noto Sans CJK SC", "Source Han Sans SC", sans-serif;
--font-mono: "Cascadia Mono", "Consolas", "SF Mono", "Menlo",
             "Noto Sans Mono CJK SC", monospace;
```

不引入 Web 字体：规避字体授权争议与首屏加载开销（跨平台交付时系统栈已覆盖 Win／mac／Linux 三端中文）。

#### 2.2.2 字阶（数据密集型论证后定基准 13px）

| token | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `--text-xs` | 12px | 16px | 400 | 角标、辅助说明、编号 |
| `--text-base` | **13px** | 20px | 400 | **正文与表格正文（基准）** |
| `--text-md` | 14px | 20px | 500 | 小标题、按钮文字 |
| `--text-lg` | 16px | 24px | 600 | 区块标题（参数分段、面板标题） |
| `--text-xl` | 20px | 28px | 600 | 页面标题（当前功能名） |
| `--text-mono` | 13px | 20px | 400 | 清单列、哈希列、正则表达式（配合 `--font-mono`） |

**基准取 13px 的理由**：① 12px 中文在 100% 缩放下笔画粘连，且小字号与 4.5:1 对比度叠加时容错更低；② 14px 在十万行列表下可视行数明显减少，与 §4 的密度目标冲突；③ 13px 位于 12–14 区间中部，向上可直接用 14px 承载按钮与标题形成层级，向下用 12px 承载角标，层级只用两级跳跃即可分辨，不需要更多字号。

**数字等宽场景（强制）**：文件清单的大小／时间列、哈希列、行数／条数列、进度数字——**必须用 `--font-mono` ＋ 右对齐或小数点对齐**。理由：非等宽数字在虚拟滚动的十万行列表里会造成列宽抖动，破坏 §4 的视觉稳定性要求。

**字重纪律**：仅用 400／500／600 三档。**不使用 300 细体**——中文细体在 100% 与 125% 缩放下发虚，且与本档的对比度门槛相互抵消。

### 2.3 间距与圆角（4px 网格）、描边、阴影

#### 2.3.1 间距

```css
--space-1: 4px;   --space-2: 8px;    --space-3: 12px;  --space-4: 16px;
--space-5: 20px;  --space-6: 24px;   --space-8: 32px;  --space-10: 40px;
```

全部尺寸（含组件内边距、图标与文字间距）取自该序列，**不出现 4 的倍数以外的值**。唯一的例外是 1px 描边与 2px 焦点环，属线宽不属间距。

#### 2.3.2 圆角

```css
--radius: 6px;                                  /* 基准：按钮、输入框、卡片 */
--radius-sm: calc(var(--radius) - 2px);          /* 4px：角标、标签 */
--radius-lg: calc(var(--radius) + 2px);          /* 8px：对话框、浮层 */
```

基准取 6px 而非更大的圆角：数据密集界面中大圆角会挤压有效内容区，且与"列对齐"的视觉基线相互干扰。

#### 2.3.3 描边

- 统一 **1px**（逻辑像素）；100%／125%／150% 缩放下均为 1 逻辑 px，不做物理加粗；
- 强调边界用**颜色**区分（`--n-300` 常规 / `--n-400` 禁用 / `--brand-500` 聚焦），不靠加粗；
- 表格与列表的横线优先于竖线：**只在行间画横线**（`--n-300`），列间不画线，靠对齐与留白分隔。

#### 2.3.4 阴影（扁平优先）

| token | 用途 | 说明 |
|---|---|---|
| `--shadow-1` | 下拉菜单、悬浮提示、行内悬浮卡 | 最小扩散 |
| `--shadow-2` | 对话框、阻断卡 | 附带 `--overlay` 遮罩 |
| — | **列表行、表格、卡片一律不用阴影** | 用 1px 描边与底色区分层级 |

**禁止**：多层叠加阴影、彩色阴影、大于 2 级的阴影层级。

## 3. 组件状态规范

所有组件的状态外观**只允许引用 token，不允许裸值**（自检③）。下表"外观"列中的颜色／尺寸均指 token 名。

### 3.1 按钮

| 状态 | 主要按钮（primary） | 次要按钮（secondary） | 危险按钮（destructive） |
|---|---|---|---|
| 默认 | 底 `--primary`／字 `--primary-foreground` | 底 `--secondary`／字 `--secondary-foreground` | 底 `--destructive`／字 `--destructive-foreground` |
| 悬停 | 底 `--brand-600` | 底 `--n-300` | 底加深一档（`--status-danger-fg` 派生） |
| 按下 | 底再加深＋1px 内阴影 | 底 `--n-400` | 同左 |
| 禁用 | 底 `--n-200`／字 `--n-500`／无悬停反馈 | 同左 | **危险按钮禁用时降为中性外观**，不保留红底 |
| 聚焦 | 外环 2px `--ring`，offset 2px（见 §7） | 同左 | 同左 |

**危险确认的视觉形态（支撑 7.11 的"确认按钮不带默认焦点"）**：确认对话框内，危险动作按钮为 `destructive` 实心样式，**打开时初始焦点落在"取消"上**（视觉上"取消"显示焦点环）；危险按钮**不加任何自动获取焦点的强调**（不用脉动、不用默认高亮、不用品牌色描边）。这样"回车即确认"的误操作路径在视觉层即被消除，与 7.11 要求一致。

### 3.2 输入框

| 状态 | 描边 | 底 | 其他 |
|---|---|---|---|
| 默认 | `--input` | `--card` | — |
| 悬停 | `--n-400` | `--card` | — |
| 聚焦 | `--brand-500` | `--card` | 外环 2px `--ring` |
| 禁用 | `--n-300` | `--n-200` | 字 `--n-500` |
| 校验失败 | `--status-danger-fg` | `--status-danger-surface` | 下方错误文案 `--status-danger-fg` ＋ 错误图标（不仅靠颜色） |
| 只读 | 无描边 | `--n-100` | 字 `--muted-foreground`，光标为默认箭头 |

校验失败必须同时有图标与文字，禁用与只读必须视觉可分（否则用户不知道能不能改）。

### 3.3 列表行（6 态）

| 状态 | 底 | 其他 |
|---|---|---|
| 默认 | 透明（露出 `--card`） | 行间 1px `--border` 横线 |
| 悬停 | `--n-200`（亮）／`--n-700`（暗） | 整行高亮，非仅悬停单元格 |
| 选中 | `--accent`（`--brand-100`） | 左侧 2px `--brand-500` 竖条 ＋ 行首勾选框 |
| 禁用 | 透明 | 字 `--n-500`，行不可点 |
| 失败 | `--status-danger-surface` | 行尾状态文字 ＋ 图标（对应 6.2 的"状态标记"列） |
| 占位（内容未就位） | 透明 | 名称后加"占位"标签（`--radius-sm` 浅底），字 `--muted-foreground`（对应 4.9 的占位文件与 6.2 的状态列） |

选中态同时用**底色＋竖条＋勾选框**三重表达，避免与"失败"底的浅红、与差异高亮的浅绿在低质量屏幕上混淆。

### 3.4 表格

- 表头：底 `--n-200`，字 `--text-xs`＋`--muted-foreground`＋500 字重；表头**不参与滚动**（粘性）；
- 数据行：行高见 §4；数值列右对齐且用 `--font-mono`；文本列左对齐；
- 排序态：表头末尾箭头（升／降／未排序三态），排序中表头字色转 `--foreground`；
- 空态：表体区域用 §8 的空状态插图版式，不使用"空表格骨架"；
- 表头与数据行的分隔线用 `--n-400`（比行间线重一档），保证表头可辨识。

### 3.5 对话框

- 容器：底 `--popover`，圆角 `--radius-lg`，`--shadow-2`，遮罩 `rgba(0,0,0,0.4)`（亮）／`rgba(0,0,0,0.6)`（暗）；
- 结构：标题（`--text-lg`）／正文（`--text-base`）／操作区右对齐，按钮间距 `--space-2`；
- 危险对话框：标题左侧加 `--status-danger-fg` 图标，**不做整块红底**（红底会盖住正文里的差异高亮）；
- 阻断卡（对应 13.10.4 的 Web 版超限引导卡）复用对话框形态，容器边框改 `--status-warn-border`，但**正文字色保持 `--foreground`**，仅图标与标签用警示色。

### 3.6 任务行（对应 6.5 的状态集合）

6.5 原文列举为六项状态：排队／运行／暂停／完成／部分失败／已取消。本规范按原文六项全覆盖（**本档不使用"五种状态"的表述**）。

| 状态 | 状态标签外观 | 进度条 | 行内操作可见性 |
|---|---|---|---|
| 排队 | `--n-200` 底 ＋ `--muted-foreground` 字 | 0%，灰槽 | 取消可见；暂停置灰 |
| 运行 | `--brand-100` 底 ＋ `--brand-600` 字 | `--brand-500` 填充，含"任务级＋条目级"双层（对应 7.5） | 暂停／取消可见 |
| 暂停 | `--status-warn-surface` 底 ＋ `--status-warn-fg` 字 | 保持当前填充，槽色转 `--status-warn-border` | 继续／取消可见 |
| 完成 | `--status-safe-surface` 底 ＋ `--status-safe-fg` 字 | 100% | 查看明细／撤销可见 |
| 部分失败 | `--status-danger-surface` 底 ＋ `--status-danger-fg` 字 | 100%（含失败段） | 重试失败项／查看明细可见 |
| 已取消 | `--n-200` 底 ＋ `--n-500` 字 | 停在中断处，槽色 `--n-400` | 撤销可见 |

进度条统一高度 4px、圆角 `--radius-sm`；**进度变化不得引发布局抖动**（行高固定，百分比数字用 `--font-mono` 定宽）。

### 3.7 预览差异高亮（6.4）

三种差异色按 2.1.3 复用状态家族，并**强制"色＋字形＋列名"三重表达**（色盲安全，§7）：

| 差异 | 底／字 | 字形前缀 | 备注 |
|---|---|---|---|
| 新增 | `--status-safe-surface` / `--foreground` | `+` | 仅高亮变化片段，不高亮整行，避免十万行时色块过重 |
| 删除 | `--status-danger-surface` / `--foreground`（旧值加删除线 `--muted-foreground`） | `−` | 旧值列默认就是"被替换的一方"，删除线强化方向感 |
| 变更 | `--status-warn-surface` / `--foreground` | `~` | 冲突／非法／超长由"状态"列文字承担（对应 6.4 的状态与原因列） |

**统一禁令**：差异高亮**一律不用纯色文字承担对比**（不用红字压浅红底这类组合），底色只做 `-surface` 级浅色，字色保持 `--foreground`——这保证差异单元格里的正文对比度与普通正文同档。

### 3.8 角标

| 类型 | 形态 | token | 语义来源 |
|---|---|---|---|
| 黄角标 | 小圆点 ＋ 悬停文字，或胶囊标签 | `--status-warn-surface` 底／`--status-warn-fg` 字／`--status-warn-border` 边 | 6.2 的"较大，建议云端或客户端" |
| 红角标 | 同上 | `--status-danger-*` | 6.2 的"超出在线处理上限" |
| 信息标签（非警示） | 胶囊 | `--n-200` 底／`--muted-foreground` 字 | 用于"占位""只读""默认值"等中性标记 |

角标尺寸：字号 `--text-xs`，圆角 `--radius-sm`，内边距 `--space-1 --space-2`。**角标不抢占行首名称的宽度**（名称过长时先省略名称，不推挤角标位置）。

### 3.9 骨架屏

- 用于"内容加载中"（对应 7.4 的预览按需异步刷新）；
- 形态：与真实行**同高同列宽**的占位条，底 `--n-200`，做低幅明暗呼吸（周期 1.2s，对比幅度 ≤6%）；
- **禁止**：整页遮罩式加载、旋转指示器替代骨架（旋转器只用于按钮内的短操作）、骨架屏与真实内容行高不一致导致的跳动；
- 骨架屏不表态：不使用警示色，不使用品牌色填充。

## 4. 数据密集场景规范（引用 6.2）

### 4.1 行高两档

| 档位 | 行高 | 适用 | 说明 |
|---|---|---|---|
| **紧凑** | 28px | 十万行级清单、日志区（6.6） | 13px 正文＋16px 行高＋上下各 6px 内边距 |
| **标准** | 32px | 默认档；条目数较少、含多行说明的场景 | 13px 正文＋20px 行高＋上下各 6px 内边距 |

两档均为 4px 网格倍数；切换入口的**视觉形态**＝工具栏内的分段控件（紧凑／标准两段，当前档高亮 `--accent`）。切换入口的具体归属与是否记忆属交互问题，见附录 B。

### 4.2 斑马纹与分隔线的取舍

**结论：用行间 1px 分隔线，不用斑马纹。** 理由：本界面已有三层底色语义（悬停、选中、差异高亮），斑马纹会引入第四层底色，在暗色主题下与选中态叠加后视觉层级不可辨；分隔线方案下，行高固定＋横线对齐反而更利于横向扫读。

### 4.3 虚拟滚动的视觉稳定性要求

1. **行高必须固定**：单元格内容一律单行＋尾部省略号；禁止因内容长度改变行高（换行用悬浮提示承载）；
2. **滚动条不跳动**：滚动条槽常驻（`scrollbar-gutter` 类策略），内容从"不足一屏"到"超过一屏"时不得出现横向挤压；
3. **批次加载不闪白**：加载下一批时沿用上一批的骨架行，禁止先清空再填充；
4. **列宽稳定**：数字列定宽（配合 `--font-mono`）；名称列占据剩余宽度，是唯一弹性列。

### 4.4 "仅统计视图"的视觉区分（对应 6.2）

- 版式从"行式列表"改为**统计卡网格**（每卡一项汇总指标），行分隔线消失，改用 `--space-4` 间距分隔；
- 顶部常驻一条**视图模式条**：明确标注当前处于"仅统计视图"，并提供切回列表的入口；
- 统计卡内数字用 `--text-lg` ＋ `--font-mono`，标签用 `--text-xs` ＋ `--muted-foreground`；
- **不使用**警示色——统计视图是降载模式，不是错误态。

### 4.5 筛选态标识

- 生效的筛选以**胶囊**形式常驻工作区顶部：`--accent` 底、`--brand-600` 字、尾部带清除按钮（清除按钮以图标而非颜色表达）；
- 多个筛选并列，超出宽度时折叠为"＋N"；
- **筛选不改变行高与列宽**，只改变可见行集合；
- "仅显示异常项"（6.2）为预设胶囊，选中态与普通筛选一致，不特殊着色。

### 5.1 亮暗 token 映射表

仅列需要换值的 semantic token；未列出的 token（如 `--radius`、间距、字号）两主题共用。

| semantic token | 亮色 | 暗色 |
|---|---|---|
| `--background` | `--n-100` | `--n-900` |
| `--foreground` | `--n-900` | `--n-100` |
| `--card` | `--n-000` | `--n-800` |
| `--card-foreground` | `--n-900` | `--n-100` |
| `--popover` | `--n-000` | `--n-700` |
| `--secondary` | `--n-200` | `--n-700` |
| `--secondary-foreground` | `--n-900` | `--n-100` |
| `--muted` | `--n-200` | `--n-700` |
| `--muted-foreground` | `--n-600` | `--n-400` |
| `--border` | `--n-300` | `--n-600` |
| `--input` | `--n-300` | `--n-600` |
| `--ring` | `--brand-500` | `--brand-500` |
| `--status-safe-fg` | `#17794A` | `#3FBF7F` |
| `--status-warn-fg` | `#8A6100` | `#E3A008` |
| `--status-danger-fg` | `#B3261E` | `#F2726B` |
| `--status-*-surface` | 高亮浅底（见 2.1.3） | 同色相低饱和深底（不透明，不用 alpha 叠加） |
| `--overlay` | `rgba(0,0,0,0.4)` | `rgba(0,0,0,0.6)` |

暗色的 `-surface` 一律用**不透明深底**而非亮色底加透明度：透明度会让下层的斑马纹／差异高亮透出，破坏 §4 的层级稳定。

### 5.2 暗色下的可辨识校验（数值化）

暗色主题的换色不是"把亮色反相"，而是**重新取一组满足对比度的前景色**。已核算的关键组合（对比度＝WCAG 相对亮度公式）：

| 组合 | 对比度 | 门槛 | 结论 |
|---|---|---|---|
| `--n-100`（暗色正文）on `--n-900`（暗色画布） | 约 16.6:1 | ≥4.5:1 | 通过 |
| `--n-100` on `--n-800`（暗色卡片） | 约 14.4:1 | ≥4.5:1 | 通过 |
| `--n-400`（暗色次级文字）on `--n-800` | 约 5.6:1 | ≥4.5:1 | 通过 |
| `--status-safe-fg` 暗色 `#3FBF7F` on `--n-800` | 约 6.1:1 | ≥4.5:1 | 通过 |
| `--status-warn-fg` 暗色 `#E3A008` on `--n-800` | 约 6.3:1 | ≥4.5:1 | 通过 |
| `--status-danger-fg` 暗色 `#F2726B` on `--n-800` | 约 5.0:1 | ≥4.5:1 | 通过 |
| `--border` 暗色 `--n-600` on `--n-900` | 约 3.5:1 | ≥3:1（非文本） | 通过 |
| `--border` 暗色 `--n-600` on `--n-800` | 约 2.8:1 | ≥3:1（非文本） | **未达 3:1**，见下 |

**对未达标项的处理规则（不回避）**：卡片内部的次级分隔线按 2.8:1 使用，但**必须同时满足**两个条件——① 该分隔线不承担"区分可点区域"的职责（可点区域一律用 `--status-*`／`--brand-*` 描边或底色标识）；② 相邻分组之间有至少 `--space-4` 的留白或一个分组标题。若某处既需要依赖分隔线区分区域、间距又不足 `--space-4`，则必须改用 `--n-400`（对 `--n-800` 约 6.8:1）。

> 上表数值为按 WCAG 相对亮度公式核算的结果；实现期须用对比度工具对**最终数值**（尤其品牌色定稿后）复算一次，复算记录留档。

## 6. 高 DPI 与缩放

- **基准测试档位**：100%／125%／150% 三档（Windows 缩放设置的常见档位）；
- **整数对齐**：1px 描边在 125%／150% 下仍按 1 逻辑 px 渲染；图标与文字基线按逻辑 px 对齐，避免半像素模糊；
- **图标**：只用 16／20／24 三个逻辑尺寸，三档缩放下均能整数映射（不出现 13px、18px 这类尺寸）；
- **位图资源**：仅空状态插图与安装引导页配图使用位图，须提供 2 倍图；其余界面不用位图；
- **布局**：三档缩放下均以 4px 网格为准；125% 下允许出现的非整物理像素由渲染器处理，**不得为避免模糊而改成 3px／5px 这类非网格值**。

**口径声明**：本节是**实现核对口径**（用于验收"在不同缩放下是否保持网格与对比度"），**不构成产品阈值**；方案 9.1 的性能指标与 13.10.2 的大小阈值不受本节影响，本档也不重复其数值。

## 7. 无障碍底线（硬约束）

引用 7.9（快捷键）。**先说清一件事：快捷键 ≠ 无障碍。** 7.9 定义的是效率通道，无障碍要求的是"完全不用鼠标也能完成全部流程，且不依赖颜色也能读懂状态"——两者目标不同，不可互相替代。

| 项 | 硬约束 |
|---|---|
| 正文对比度 | ≥ **4.5:1**（WCAG AA）。覆盖：正文、表格数据、次级文字、警示文案、差异单元格内文字 |
| 大文本与图形对比度 | ≥ **3:1**。覆盖：≥18px 或 ≥14px 加粗的文本、图标、描边、状态标签、进度条填充与槽 |
| 键盘可达 | 全部可操作元素可 Tab 到达、可激活、可退出；不出现只能鼠标触发的操作 |
| 焦点环 | 2px `--ring` ＋ 2px offset；**必须在任何底色上可见**（含选中态、差异高亮底、暗色卡片） |
| 焦点顺序 | 按视觉顺序（左→右、上→下）；对话框打开时焦点进入对话框内、关闭时回到触发元素；危险确认的初始焦点落在"取消"（3.1） |
| 状态不靠颜色 | 差异高亮必带字形（3.7）；状态标签必带文字；角标必带悬停文字或标签文字；进度状态必带状态词 |
| 动效 | 骨架屏呼吸幅度 ≤6%（3.9）；禁止闪烁类效果；系统开启"减少动态效果"时，所有非必要动画降为静态 |

**三类必须覆盖对比度的对象**（自检④）：① 正文与次级文字；② 警示色作为文字／图标时的前景比对；③ 差异高亮单元格内的文字。

## 8. 图标与插图

### 8.1 图标

- **选型：lucide（1.1 落定后确认）**。在 **A 路线（Fluent 语义 ＋ shadcn/ui 实现）下**，lucide 是 shadcn 生态的默认图标库，与 1.1 的组件层选型一致，故确认为本项目图标库；**原 L1 库级依赖登记口径不变**——仍按 4.11 的 L1 口径登记（据此纳入 4.10 的依赖审计与 SBOM，许可义务按 4.11.4 处理）；
- **网格与描边**：24×24 设计网格，统一描边 **1.5px**，圆头圆角；不允许混用实心图标（除非该图标本身只有实心形态，且需在同一排中做视觉重量配平）；
- **尺寸**：16px（行内状态、按钮内）、20px（工具栏、列表行首）、24px（空状态、对话框）；
- **颜色**：继承父级字色；**仅当图标承担状态含义时**才用 `--status-*-fg`（且该处必须有文字冗余）；
- **禁忌**：不用图标单独表达"新增／删除／变更"（与 3.7 的字形并用时，字形优先，图标只作辅助）。

### 8.2 空状态插图

- **风格**：线性单色插图，描边 `--n-300`、点缀 `--brand-500`（点缀面积不超过整图 10%）；
- **尺寸**：160×120（逻辑 px），居中于工作区上方，下方依次为标题（`--text-lg`）／说明（`--text-base`＋`--muted-foreground`）／主操作按钮；
- **配图口径（对应 6.2 的"空状态给出示例与'试用示例数据'"）**：插图内容与当前功能语义相关（例：CSV 分割功能展示"一叠纸分成两叠"），**不使用人物插画、不使用吉祥物、不使用渐变**；
- **一致性**：全部空状态共用同一套线性风格与描边粗细，不逐功能另创风格。
