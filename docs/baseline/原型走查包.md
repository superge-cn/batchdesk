## 1. 走查用线框版式约定

### 1.1 帧尺寸与网格

| 项 | 取值 | 说明 |
|---|---|---|
| 桌面帧 | 1440×900 | 主档；备选 1280×800 用于验证四区压缩 |
| 网格 | 4px | 与 U §2.3.1 同网格，线框层不改网格 |
| 四区宽度 | 顶栏 56／左导航 200（可折叠）／右参数区 320／底栏 折叠 40、展开 240／**中部工作区弹性** | 对照 6.1 的"左选做什么、中间放数据、右调参数、底部看结果" |
| 安全边距 | 各区内边距 16px | 与 U §2.3.1 的 `--space-4` 对齐 |

### 1.2 灰阶与占位文本

- **只用 3 级灰**：框线灰（对应 `--n-300`）／底色灰（`--n-200`）／文字灰（`--n-600`）。**不使用任何彩色**；
- **占位文本**：中文用 6–12 字等价长度（如"2024年度报名名单.csv"→ 用同长度占位串），数字用等宽占位（如 `1,234`），**不要用 lorem ipsum**（拉丁文长度与中文字宽差异会误导列宽评估）；
- **命名规范**：Figma 元件命名 `屏号-区域-元件`，如 `A-04-预览-差异行`；
- **标注**：每个屏右侧贴一张标注卡，写明"屏号／方案引用／U 引用／状态集合"。

### 1.3 状态表达约定（低保真 → 真实 token 映射）

低保真不用颜色，但状态必须仍可辨识——这恰好验证了 U §7 的"状态不能仅靠颜色"是否成立。线框层用四通道表达：

| 语义 | 线框表达（禁用颜色） | 真实实现映射 |
|---|---|---|
| 安全 | 实线描边 ＋ 字形 `✓` ＋ 文字 | U §2.1.3 `--status-safe-*` |
| 注意 | 虚线描边 ＋ 字形 `!` ＋ 文字 | `--status-warn-*` |
| 危险 | 双线描边 ＋ 字形 `✕` ＋ 文字 | `--status-danger-*` |
| 差异·新增 | 行首 `+` ＋ 浅底纹 | 复用 `--status-safe-*`（U §3.7） |
| 差异·删除 | 行首 `−` ＋ 删除线 | 复用 `--status-danger-*` |
| 差异·变更 | 行首 `~` ＋ 点状底纹 | 复用 `--status-warn-*` |
| 选中 | 左侧 2px 实心竖条 ＋ 勾选框 | `--accent` ＋ 竖条（U §3.3） |
| 悬停 | 整体浅底纹 | `--n-200` |
| 禁用 | 文字变浅 ＋ 右上斜线角标 | `--n-500` 文字 |
| 聚焦 | 2px 虚线外框，offset 2px | `--ring` 实线外环（U §7） |
| 进度 | 4px 横槽 ＋ 实心填充 ＋ 百分比数字（等宽） | `--brand-500` 填充 |

**禁止**：在线框里用红黄绿填充来表达上述任何语义（会使走查者按"颜色好不好看"提问，偏离流程评估）。

### 4.2 任务式问题清单（只问"你下一步会点哪里"）

规则：**不追问"好不好看""喜不喜欢"**；每次只问一句，问完记录走查员的第一个动作与其口述的理由。

| 屏号 | 问题（原话） | 观察什么 |
|---|---|---|
| A-01 | "这里有一个报名表 CSV，你要把它分成每人一份，你下一步会点哪里？" | 是否找到功能入口，是否需要提示 |
| A-03 | "你要切成每份 1 万行，你下一步会点哪里？" | 参数分组的可发现性 |

**样本要求**

| 项 | 要求 |
|---|---|
| 人数 | 5–8 人（与 U 1.1 步④一致） |

| 排除 | 参与过 U 第 1 章或本包编制的成员**不计入有效样本**（已知答案） |

**呈现方式（保证盲目性）**

- 同时给出 **2–3 个候选基调的低保真版本**（A 混合／B 纯 shadcn 默认风／C 纯 Fluent 复刻），三者用同一批屏号（取 §2 的 A-02、A-04、C-04 三屏即可），**仅换基调表达**，内容与结构完全一致；
- **不告知哪一版是当前选用**，版本顺序在受访者之间轮换（避免顺序效应）；
- 三问**分别单独问**、逐问记录，**不得合并成"你更喜欢哪一版"**（合并会退化为偏好投票，失去三问的区分能力）。

**三问（原话照读，不追加解释）**

| 问号 | 问题（原话） | 记录 |
|---|---|---|
| Q1 | "如果把重要文件交给它处理，哪一版让你更**放心**？" | 记该受访者所选版本 |
| Q2 | "哪一版看起来更**像你平时用的办公软件**（Office 那一类）？" | 同上 |
| Q3 | "如果每天都要用，哪一版你**更愿意天天打开**？" | 同上 |

**计票表模板**

| 问号 | A 混合基调 | B 纯 shadcn | C 纯 Fluent | 无明确选择 |
|---|---|---|---|---|
| Q1 更放心 | | | | |
| Q2 更像办公软件 | | | | |
| Q3 更愿意每天用 | | | | |

**判定规则（回填 U 1.1 步④）**

1. **A 在 Q1 与 Q2 中均占优** → 步④记"已复核，结论支持 A"，附录 B-U7 关闭；
2. **A 在 Q1 或 Q2 中不占优** → 触发 **U 1.1d 的退路评估**（把语义层映射回 shadcn 默认值），评估结论按 §5 处理流程回填 U 并升版；
3. **仅 Q3 落后** → 记为**观察项**，不触发退路（"每天用"更多反映习惯，与"放心／像办公软件"不同级）；
4. **无明确选择占比过半** → 判为**样本无效**，扩充样本重测，不据此下结论。

**纪律**：本节只记录选择与理由，**不做满意度打分、不记反应时长**（与 6 的"不做开放式试用统计"口径一致）。

## 5. 结论处理规则

三条归属规则＋一条专属规则（收到记录表后逐条套用）：

| 问题类型 | 处理 |
|---|---|
| **交互问题** | 按 **11.6** 的书面确认流程确认后，修改**方案**对应章节（6.x／7.x）；确认前不擅自改稿 |
| **视觉问题** | 回填 **U**（现行 U v1.1），出下一个版本（U v1.2）；本包随之更新 |
| **实现问题** | 记入**开发待办**，**不改任何文档** |
| **盲测结论**（4.4 专属） | 按 4.4 的判定规则回填 **U 1.1 步④与附录 B-U7**；若触发退路，按 U 1.1d 处理并升版 |

### 5.1 归属判定（先判归属，再走上面的处理）

三问判定树，按顺序问，命中即停：

1. **影响"什么时候发生／点了之后如何"吗？** → 是则 **交互**（须回方案）；
2. **只影响"长什么样"（颜色、字号、间距、形态）吗？** → 是则 **视觉**（须回 U）；
3. **方案与 U 都已定义、实现与定义不符吗？** → 是则 **实现**（只记待办）。

若三问都不命中（三方都没有定义）→ **不判为问题**，记入本包附录待确认，不自行发明规则（自检③）。
