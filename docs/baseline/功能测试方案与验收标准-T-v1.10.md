## 1. 测试范围与策略分层

### 1.1 三条线分别定义测试深度

| 线 | 深度定位 | 覆盖要求 | 出口挂钩 |

| 商业版 | 授权闭环专项＋回归复用单机版基线 | 8.1–8.9 授权专项全套；单机版基线按抽样回归，不重复全量 | 10.4 商业版首批/次批出口 |
| Web 版 | 核心子集＋双通道切换＋跨浏览器＋OPFS 配额边界＋承诺兑现反向验证；另含 **NEG 一条**：Web 版撤销/日志入口的文案须与 13.8 的显式声明一致，**不得出现与桌面版等价的暗示** | 13.4 核心子集功能用例；13.10 双通道全流程；13.10.1 三条隐私承诺反向验证；13.9 不承诺项负面用例 | 10.3 Web 版阶段出口 |

### 1.2 各线"不测什么"（负面清单）

**单机版阶段 0 不测**

- 授权激活、许可证校验、设备绑定、离线激活（阶段 0 以 `AlwaysAllowLicense` 顶替，见 12.4）——仅在商业版专项测；
- P1、P2 功能（C21–C42、C61、C46–C58、C62、C63）；
- 12.3 列出的 5 项延后功能（C46、C48、C51、C55、C57）；
- C61 的断线重连与网络盘性能曲线（P1）；阶段 0 只测 S01 在 UNC 查询超时后的降级路径（4.9）；
- 杀软/EDR 白名单验证（列为发布前手工抽检，不进用例集）。

**商业版不测**

- 单机版阶段 0/1 已通过的功能正确性（只做回归抽样，不做全量重跑）；
- 定价、支付渠道、发票与渠道结算（非本产品功能范围）；
- 服务端授权系统的容量与 SLA（属运维验收）。

**Web 版不测**

- 13.4"桌面专属"清单内的功能（F14、C21–C28、C40、C42、C61、C62）；
- 云端服务端的容量压测与成本核算（属服务端运维）；
- 移动端浏览器与平板适配（不在 13.x 范围）；
- 浏览器内核级渲染差异的像素级比对（只做功能可用性探测与降级提示验证）。

**P0★ 的口径澄清**：表中 P0★ 共 **24 行**（F01–F14 共 14 行＋C 系列★10 行），其中 **F14 属商业版专项**（阶段 0 以 `AlwaysAllowLicense` 顶替，见 12.4）；S01/S02 优先级标 **P0**（不标★），但用例数与 P0★ 同为 10–12。因此"25 项阶段 0 功能"＝F01–F13＋C 系列★10＋S01/S02；三类用例的强制口径只对这 25 项生效，F14 按商业版授权专项（第 4.2、附录 B5）单独验收。

**简化用例定义**：**○** 表示不单独构造完整链路，但必须覆盖该环节的关键判定——例如 F14 的回滚 ○＝"解绑/降级后功能位图正确收缩"，S01 的回滚 ○＝"预检不通过时任务零副作用"，C18 的回滚 ○＝"参数变更后预览失效、执行被阻断"。

**用例总量估算**（按"用例数"列逐行归档：10–12 档 26 行＝24 个 P0★ 行＋S01/S02；6–8 档 13 行**已含 C17b**；4–6 档 26 行＝C21–C42＋C61＋S04/S05＋F15；3–5 档 15 行）：26×10–12（约 286）＋13×6–8（约 91）＋26×4–6（约 130）＋15×3–5（约 60）＋C17a 3–4 ≈ **571 条**（按各档中值；全距 490–651）。C43–C45 随 F14 覆盖，不另计。

## 5. 缺陷分级与流转

### 5.1 四级定义

采用 D-T3 的**严格口径**：P0 要求"软兜底也失效"。

| 级别 | 定义 | 本产品语境示例 |
|---|---|---|
| **P0** | 数据不可逆丢失、进程崩溃、静默覆盖，**且**隔离目录/回收站、预览、撤销三道防线全部未生效 | ①批量移动中断后源文件已删但目标未写入，且无回滚记录；②覆盖已有文件且未进隔离目录、无备份；③并发场景下撤销映射错乱导致反向改名错文件 |
| **P1** | 核心功能不可用或结果错误，但数据仍可恢复/可撤销 | ①CSV 分片丢失表头（5.3 判定不成立）；②编码误判导致整批乱码且未提示（5.2）；③撤销按钮无效但映射记录完好，可人工恢复 |
| **P2** | 次要功能错误、体验缺陷、提示不达标 | ①进度条与实际偏差超预期但任务正确完成（7.5）；②错误提示仅一句话、缺诊断信息（4.6）；③冲突策略选择"询问"但未逐项提问（7.7） |
| **P3** | 文案、样式、易用性问题，不影响任务结果 | ①按钮文案与行为不一致；②快捷键与系统冲突（7.9）；③列表排序默认值不符预期 |

**判级纪律**：判 P0 前必须确认三道防线状态（隔离目录、预览、撤销），缺一即降为 P1；反之，任一防线生效但用户仍可能误判为"无损失"时，不得据此降级。

### 5.2 缺陷与需求变更的判别

| 情形 | 判定 | 处理 |
|---|---|---|
| 与方案已确认决策（基线 v1.6，含 v1.4/v1.5 已确认项）不符 | **缺陷** | 进缺陷库，按 5.3 流转 |
| 方案已定义但实现偏离 | **缺陷** | 同上 |
| 方案未定义、或需改方案才能判定 | **需求变更** | 记入附录 A → 方案变更流程，**不占用测试出口指标** |
| 测试理解与方案冲突 | 先查方案，再记附录 A | 不得自行判缺陷或改预期 |

### 5.3 流转与关闭

缺陷记录必填字段：编号、级别、功能编号、复现步骤、**环境组合编号（6.1）**、**语料编号（3.2，如适用）**、预期 vs 实际、截图/日志、影响范围。

关闭条件（三者缺一不可）：

1. 修复构建通过**原用例**；
2. 通过**横切套件**（B1＋B2 相关项）；
3. 若属 P0/P1，须补一条语料（3.3 沉淀规则）并回归通过。
