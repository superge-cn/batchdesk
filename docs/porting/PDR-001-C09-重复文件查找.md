## 3. 移植范围（只抽“分组/身份判定”算法）

| fdupes v2.4.0 函数/范围 | 处理 | 说明 |
|---|---|---|
| `checkmatch` 637–738 | **移植算法** | 同大小候选分组、快速签名/全量签名确认的核心流程；改写为纯函数 |
| `registerpair` 1128–1158 | **移植算法** | 已确认匹配项挂入重复组、组内排序；改写为纯函数 |
| `is_same_file` 556–612；`has_same_file` 615–635 | **移植判定规则** | 设备/文件标识、路径/硬链接判定；改为项目 `FileIdentity`，不直接 `stat` |
| `getcrcsignatureuntil` 419–467；`getcrcpartialsignature` 474–477；`getcrcsignature` 469–472 | **不移植代码** | 含 `fopen/fread/fclose` 与 MD5；保留“头部/尾部快速签名→全量签名”的策略，由项目流式读取＋哈希引擎实现 |
| `md5cmp` 479–491 | **不移植** | 摘要比较由项目哈希 crate/常量时间比较负责 |
| `grokdir` 305–417 | **不移植** | 目录遍历、过滤与 I/O；走 `scanDirectory`/FsAdapter |
| `hashdb.c`/`fmatch.c`/`confirmmatch.c` | **首版不纳入** | 缓存/数据库/确认流程与项目队列/预览模型不匹配；如确需索引，按项目自建 |
| CLI/ncurses/log/dir/fileaction/deletefiles 等 | **不移植** | UI、终端、日志、删除/动作、路径处理全部排除 |

**移植后形态**：

- 目标位置：`crates/kernel` 的纯函数层，输入为 `DuplicateCandidate`（大小、快速哈希、全量哈希、`FileIdentity`、路径标识）与分组参数，输出为重复组；**不读盘、不取时钟、不读环境**（不变量 1）。
- 文件扫描/读取/哈希由壳层与 FsAdapter 完成；哈希算法按方案 §5.10 的 BLAKE3 默认（交付兼容可选 SHA-256/MD5），**不使用 fdupes 的 MD5 实现**。
- 分组结果进入 `plan_c09`（对应 `planOperation("c09")`）生成 `PlanDocument`；清理动作仍走项目 C09 的隔离目录/二次确认/撤销，不移植 fdupes 的删除逻辑。

## 4. 契约适配

| 项 | 适配 |
|---|---|
| plan/apply | 移植算法只产生分组/候选；`planOperation` 生成计划，`applyPlan` 执行清理；纯函数不落盘 |
| 参数 | 大小下限/快速签名窗口/哈希算法/是否快速模式由项目参数定义；快速模式只输出“候选组”，不得直接清理（§5.10、11.6-20）；计划预览的保留策略支持最早/最短路径/最新；缺省 `earliest`（2026-10-29 用户确认，待基线收编，见 PENDING-DECISIONS/OQ-29） |
| 错误码 | 参数非法 E1002；权限/占用/网络错误 E2002/E2003/E2005；保护目录 E2009；不新增平行错误码 |
| 冲突/预检 | 走 C19/S01；移植代码不得自带冲突/预检/日志/删除实现（§4.11.2a③） |
| 硬链接 | `FileIdentity` 由 FsAdapter 提供（Windows 文件 ID/卷序列；Unix inode/设备）；不可用时降级为“按路径去重”，标记“需人工确认”，不自动纳入清理 |
| 0 字节/占位/无权限 | 0 字节单独分组并默认忽略；网盘占位跳过；无权限记录跳过（§5.10） |
| 并发/线程 | fdupes 为单线程；本项目并发/哈希调度走 C15/壳层，不移植线程模型 |
| 日志 | 走 C17；不移植 `log.c` |

## 5. 测试与证据

- T v1.12 C09 用例（6–8 条口径）；
- `fixtures/bench/C-6-重复文件集`：同大小异内容、同内容异名、硬链接三类；
- `fixtures/bench/C-6-重复文件集/assert_c09.py`：C09 只读与计划预览断言（Unix 主机、本地手动；CI 不生成 C-6），覆盖两阶段/三阶段/fast 候选/硬链接/只读性/`PlanDocument` 预览；
- 计划预览：`crates/kernel/src/plan.rs` 的 `plan_c09` 只生成 `PlanDocument`，不落盘；fast/candidate 组以 E1002 拒绝，身份未知组不进入计划；CLI `--plan` 的 `--keep` 缺省 `earliest`；
- apply/undo：`crates/cli/tests/apply_flow.rs` 使用真实文件系统验证计划文件 → apply（隔离 + Journal）→ undo（逆序恢复）；kernel apply 单测覆盖授权拒绝、blocked、fast 计划拒绝、非 delete 拒绝；
- 快速哈希窗口：基线 §5.10 只写“头部若干 KB＋尾部若干 KB”，未给数值；CLI 强制显式传入（fast 必填、full 可选用于预筛），**不设产品默认值**，取值登记 OQ-28；C-6 断言中的 4096 仅为测试参数；
- 额外用例：0 字节、无权限目录、网盘占位、快速模式“仅候选不得清理”、Windows 文件 ID 不可用回退；
- 性能：按方案 §9.1 的哈希/目录指标；C-6 数据集；不新增阈值；
- 证据：PDR 编号 + 台账行 + 文件头 + T 回归结果；MIT 全文见仓库根 [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md)。

## 6. 退路

- 若 `checkmatch`/`registerpair` 的适配（含硬链接/排序/快速签名策略）超过 §4.11.3 的 500–2000 行档或与项目哈希/并发模型冲突：**回退自建**，保留“大小→快速签名→全量哈希”三段式设计，不强行移植。
- 若后续发现 fdupes 的特定边界（硬链接/路径去重）不适合 Windows：改用 jdupes 的对应逻辑或自建，需更新本 PDR/台账。
