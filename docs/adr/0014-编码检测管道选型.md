# 0014. 编码检测管道选型：chardetng（主路径）＋ encoding_rs（编解码）

- **状态**：已采纳（2026-10-30；方案 §5.2 已定决策，本 ADR 只落工程选型与置信规则）
- **日期**：2026-10-30
- **决策者**：开发代理（按方案 §5.2 既定决策执行）
- **关联**：方案 §5.2（C01 四级检测流水线与置信策略）、§5.1（BOM 策略）、§3.2（>2 GB 流式）；设计 01 §7（E3001/E3002）；ADR-0010（依赖审计口径）；硬性不变量 9

---

## 1. 问题背景

C01/F01–F04/C02/C03/C10 全部依赖编码检测与转码。方案 §5.2 已把检测定为四级流水线（BOM → 严格 UTF-8 → chardetng → 平台先验），并点名"优先采用 chardetng……不自研替代该库的主路径"。工程上需要把该决策落成依赖选型与置信规则，否则文本类功能无法开工。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | `chardetng 1.0`（统计判定主路径）＋ `encoding_rs 0.8`（编解码） | **选用** |
| B | 自研统计打分作主路径 | 否决：方案 §5.2 明文"不自研替代该库的主路径，避免重复造轮子与回归风险" |
| C | 其他检测库（`chardet` 等） | 否决：脱离方案点名的 Firefox 同源实现，对中日韩多字节无专门处理保证 |
| D | 不引入依赖、仅 BOM+UTF-8 判定 | 否决：GBK/Big5/Shift-JIS 无法判定，C01 的核心场景（旧系统中文文件）不可用 |

## 3. 选择理由

- **许可核实（硬性不变量 9）**：`chardetng 1.0.0 = Apache-2.0 OR MIT`、`encoding_rs 0.8.42 = (Apache-2.0 OR MIT) AND BSD-3-Clause`（`cargo info` 实证），均落现有 `deny.toml` 白名单，双 lock `cargo deny` 全绿；此前对 chardetng 许可的疑虑（误记为 MPL-2.0）已排除，无需人工裁决。
- **纯函数与 WASM**：两库均为纯 Rust、无 I/O、无网络，kernel 不变量 1 与方案 13.5（WASM 复用）不受影响。
- **置信规则（本 ADR 新定，零数值阈值）**：用判定编码解码采样——a) 替换错误为零，且 b) 解码结果不含 `\t\n\r` 之外的控制字符（方案 §5.2 打分维度"非法字节率/控制字符比例"的无阈值化），两条同时满足 → 高置信自动采用；任一不满足 → 需人工确认（"绝不静默猜错"）。控制字符判据同时兜底两类误判：Latin-1 等全字节可解码编码对二进制样本的"零错误蒙混"，与纯 ASCII 形态二进制文件。
- **平台先验（④）**：仅作为报告说明与提示层（中文 Windows 对 GB18030、其余对 UTF-8 的对齐提示），不改变置信结论。
- **UTF-16 输出**：WHATwg encode 流程只定义到 UTF-8（encoding_rs 对 UTF-16 目标返回 UTF-8 字节，实测确认），故 UTF-16 输出按 Unicode 语义直接编码（`encode_utf16` + 字节序），BOM 按 §5.1"每片必须写"由调用方控制。

## 4. 后果与退路

- **后果**：kernel 新增两个依赖（传递依赖含 simdutf8/rustversion 等，均过 deny）；legacy 输出编码的不可映射字符暂按 encoding_rs 默认（WHATwg 数字实体），输出端逐字节策略待 C01 验收定稿；检测/转码当前为整段进出，>2 GB 的流式管道在 F01/C01 接线期实现（方案 §3.2）。
- **退路**：`SourceEncoding` 候选集扩充只需加 `from_encoding`/`to_encoding` 映射；若未来替换检测库，仅 `detect()` 第③步一处改动。
