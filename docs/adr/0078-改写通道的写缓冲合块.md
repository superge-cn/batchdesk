# 0078. 改写通道的写缓冲：把逐行 `write_all` 合块，代价是失败路径必须自己擦干净

- **状态**：已采纳（通道改造已落地；**修复后的 C-2 数值由 `fixtures/bench/results.md` R-19 承担，本 ADR 不预写数值**）
- **日期**：2026-11-07
- **决策者**：开发代理（工程实现决策；不改产品行为、错误码、阈值与线协议）
- **关联**：方案 v1.19 §9.1（大文件吞吐、内存占用恒定）、§4.8（10 MB–2 GB 纯流式）；[ADR-0055](./0055-C01流式转码编辑器与ContentRewriter明细返回位.md)（C01 的 64 KiB 逐块写出）、[ADR-0057](./0057-C03流式替换的重叠窗口与正则边界.md)（plain/cell 流式）、[ADR-0027](./0027-C02-换行转换流式重写与CSV引号保护.md)（C02 流式）、[ADR-0022](./0022-F10-目录清单CSV与流式写出.md)（F10 逐行写出同一条通道）；`crates/platform/src/fs.rs`（`rewrite_atomic_with`／`write_atomic_with`）、`fixtures/bench/results.md` R-13／R-18／R-14～R-16

## 1. 问题

2026-11-06 的 C-2 实测（同一台机、同一夹具、同一数据集）给出了一个不像磁盘的读数：

| 臂 | 写侧行为 | apply 吞吐 |
|---|---|---|
| C01 转码 | 按 64 KiB 块写出 | **86.9 MiB/s** |
| C02 换行 | 每行一次 `write_all` | 4.3 MiB/s（子档）／2.3 MiB/s（整档） |
| C03 plain／regex／cell | 每匹配两段写、每条记录一次写 | 3.9／4.9／5.6 MiB/s |

三组读数都与体积无关（256 MiB 与 2 GiB 同量级），也与系统争抢无关（并发会话把 loadavg 抬到 16–28 时读数不变）——
这不是"大文件慢"，是**每条记录一次 write 系统调用**：C02 整档要写 7,901.7 万行，就是 7,901.7 万次 `write`。

落点只有一处，而且是通道而不是某个重写器：`crates/platform/src/fs.rs` 的 `rewrite_atomic_with` 把
`fs::File::create(&temp)` 的结果**不加缓冲**直接交给回调（同文件的 `write_atomic_with` 同形，F10 的
清单写出器也逐行写）。重写器按行/按匹配写出是它的设计（流式、内存 O(1)），问题在于通道没给它缓冲。

§9.1 的"分割/转换类"吞吐档是 NVMe ≥200 MB/s、机械盘 ≥60 MB/s。2.3–5.6 MiB/s 与机械盘档差一个数量级，
而差异不来自介质——留着不改就是把实现缺陷写成产品结论。

## 2. 决策

**在通道处合块，不在四个重写器里各写一套缓冲。**

1. `rewrite_atomic_with` 与 `write_atomic_with` 交给回调的写侧改成
   `io::BufWriter::with_capacity(STREAM_CHUNK_BYTES, file)`，容量沿用本模块已有的
   `STREAM_CHUNK_BYTES = 64 KiB`（同一模块内单点定义，不为本次改动新增数字；
   也与 C01 转码器、`copy_range_atomic` 的块尺寸一致）。
2. 读侧**不动**：重写器自己按 64 KiB 块 `read`，再套 `BufReader` 只会多一次内存拷贝。
3. 改名前仍显式 `flush()`：缓冲的意义是"落盘时按块写"，不是"晚点写"。`BufWriter` 的 `Drop`
   会把残余缓冲回灌进 writer，所以失败路径的次序是**先 drop(writer) → 再删临时文件**——
   回灌进临时文件的数据随后被删掉，绝不会碰到目标路径。这条次序是本次改动唯一的新风险，
   已钉成断言（见 §4）。
4. 效果范围：走这条通道的所有改写臂都受益——C01、C02、C03 三臂、C14/C11/C12 等按记录写出的
   产物类、以及 F10 清单写出器。**没有**为任何一条臂单独加开关或阈值。

## 3. 为什么不选另外两条路

- **在每个重写器里手写输出缓冲**：四处重复同一套逻辑，将来新增改写臂一定会漏一处；
  而且改不了 F10 的清单写出器（它不实现 `ContentRewriter`）。通道处一次改完，臂侧零改动。
- **把重写器改成"整段算完再一次写"**：那正是 ADR-0055/0057/0064 一路拆掉的东西，
  内存回到 O(文件)，与 §4.8/§9.1 直接冲突。为吞吐牺牲内存恒定，方向反了。

## 4. 已接受的坑与边界

- **吞吐结论的证据只能是实测**：本机 `/proc/self/stat` 不导出 sysc/syscw（逐字段增量反查过：
  写 1000 次没有一个字段变化），`strace` 也不在依赖里。因此**没有**"数系统调用次数"的单测——
  写一条永远为真的断言就是本项目禁止的假绿。改动的效果只由 `fixtures/bench/results.md`
  R-13／R-18（修复前）与 R-19（修复后、同一夹具同一数据集）说话。
- 单测覆盖的是缓冲**引入的风险**，不是吞吐：
  `rewrite_atomic_with_buffers_many_small_writes`（逐字节写产物必须与整段写一致；
  中途失败时原文件一个字节不变；两条路径都不留 `.batchdesk-*` 临时文件）、
  `write_atomic_with_buffers_many_small_writes`（F10 式 3,000 行逐行写出）。
- 缓冲容量仍是实现细节而非产品阈值：AGENTS 的"数值阈值只引基线"约束的是性能/大小/保留期/并发
  这类判定值，这里沿用的是模块内已存在的块尺寸，**没有新增阈值**；如果将来要按介质调缓冲，
  那属于新的决策，得先有实测。
- Windows 侧同样成立（`BufWriter` 与文件系统无关），但**跨平台数值只能由 Windows 实机日给出**：
  NTFS＋杀软下的合块收益可能与 Linux 不同，R-19 属 Linux 预跑，不作毕业证据（ADR-0051）。
