# 0090. 模板来源字段 `origin` 与运行模式缺省

- **状态**：已采纳
- **日期**：2026-11-10
- **决策者**：产品所有者（OQ-45 裁决）
- **关联**：方案 v1.22 §15.2.3／§15.2.4；设计 03 §5.2（RecipeDocument v7）；[ADR-0089](./0089-C37多步模板执行口径与运行模式缺省.md)（被本篇取代）

---

## 1. 问题背景

方案 §15.2.3 要求多步模板「**本机新建模板默认一键**；导入模板默认逐步骤」。实现时发现没有可靠的判据：`RecipeDocument.sourceFormat` 的语义是「跨形态导入标记（§13.8）」（`desktop`／`web`），而 `saveRecipe`／`importRecipe` 两条路都未设置它——拿它当来源判据是语义误用，且现网模板一律为空。

[ADR-0089](./0089-C37多步模板执行口径与运行模式缺省.md) 当时取 §7.4 安全默认（一律逐步骤）并把缺口登记为 OQ-45。不做决定的代价：基线这句措辞永远无法实现，多步模板的一键永远要多点一次。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 用 `sourceFormat` 判来源 | **否决**：语义是跨形态而非来源，且两条保存路径都未设置 |
| B | 新增 schema 来源字段 `origin`（`local`／`imported`），升版 v7＋迁移＋基线修订 | **选用** |
| C | 维持 ADR-0089 的一律逐步骤 | **否决**：基线措辞与实现长期不一致，且用户已就此裁决 |

## 3. 选择理由

- 来源是**产品概念**（信任分级：本机新建可信、导入不可信），必须有明确载体；`sourceFormat` 承担不了。
- 迁移**不猜**（与 v4→v5 采样、v5→v6 正文同一口径）：v6 及更早模板迁移后 `origin` 留空＝来源未知，按导入默认（逐步骤）处理。把旧模板一律猜成 `local` 会让历史导入件获得一键资格，违反 §7.4。
- 导入侧**不信任载荷**：导出件里的 `origin` 只是这份模板的「历史」，导入副本一律改写为 `imported`。
- 运行模式本身仍是本机 UI 偏好（UiState `templatePrefs`，设计 03 §5.2／§11.2），`origin` 只决定**缺省**，用户可覆盖；含高风险步骤时仍由 `describeRecipe.oneClickAllowed` 禁一键。

## 4. 后果与退路

- **后果**：
  - 模板 schema 升到 v7；旧模板迁移后来源未知（保守），本机新建的新模板才享受一键缺省；
  - 导入模板（含从本机新建模板导出再导入的副本）默认逐步骤，需显式开一键；
  - 多了一道「来源」字段，导入/导出/迁移/界面四处都要承认它。
- **退路**：若产品改口径（例如导入模板也默认一键），只需改前端缺省判定与基线 §15.2.3 措辞，`origin` 字段与迁移保持不变；若改判「来源不可信、不区分」，删掉前端对 `origin` 的读取即可，字段留空不影响旧副本。
