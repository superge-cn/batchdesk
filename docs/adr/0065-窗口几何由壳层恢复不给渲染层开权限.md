# 0065. 窗口几何由壳层恢复，不给渲染层开窗口权限

- **状态**：已采纳（2026-11-04，设计 03 §11.2／§11.3 的 `window` 段）
- **日期**：2026-11-04
- **决策者**：开发代理（工程架构决策；不改契约字段与产品行为）
- **关联**：设计 03 §11.1–§11.3（UiState 的存储/schema/恢复规则）、设计 12 §1（capabilities 最小权限）、
  [ADR-0060](./0060-桌面壳CSP与capabilities的最小化取值.md)（capabilities 只有 `core:default` ＋ 6 项静态断言）、
  [ADR-0062](./0062-UiState的前端联动上次目录与上次页面.md)（`navigation` 段的前端联动走 `setUiState`）、
  `src-tauri/src/window_state.rs`、`src-tauri/src/lib.rs`（`setup` 恢复、`on_window_event` 落盘）

## 1. 问题

§11.3 要求「窗口矩形须在可用显示器内；离屏/显示器移除 → 居中主屏；面板宽度 clamp」。
两种落点：

- **前端**：`@tauri-apps/api/window` 读尺寸位置、`getCurrentWindow().setPosition()` 摆放，UiState 已有 `get/setUiState` 命令，看起来"顺手"。
- **壳层**：Rust 侧在窗口创建后直接读 `ui-state.json` 并摆放。

前端方案要先给 capabilities 加 `core:window:allow-set-size`／`allow-set-position`／
`allow-inner-position` 等一摞权限——而 ADR-0060 刚把 capabilities 收成只有 `core:default`
并用静态断言钉住。

## 2. 决策

**窗口几何归壳层**：`run()` 的 `setup` 里读 `UiState.window` → `window_state::decide_placement(saved, monitors)`
→ `set_size`／`set_position`／需要时 `maximize()`；关闭请求时把当前矩形写回 `UiState.window`。
capabilities 保持 `core:default` 不变，本批没有新增任何窗口权限。

三条理由：

1. **权限面**：窗口尺寸/位置是**产品行为**的一部分，但"谁能改窗口"是安全边界的一部分。渲染层是可以被 DevTools
   篡改的那一侧（不变量 11：浏览器内一切判定都不构成安全边界）。把 `setPosition` 交给 JS，等于为了省一段 Rust
   代码，永久扩大多面攻击面——而且一旦给出，收回来是破坏性变更（前端代码会依赖它）。
2. **信息拓扑**：离屏判定要遍历**所有**可用显示器的工作区，还要处理跨屏负坐标。壳层一次 `available_monitors()`
   就够；前端要多次 IPC 往返（每个显示器一次），或把整个几何塞进 JS 再算一遍——两份真相。
3. **时机**：恢复必须发生在窗口创建后、可见前，否则会"先在屏幕外闪现一下再被拽回来"。前端拿不到这个时机，
   它的第一个生命周期回调已经晚了。

## 3. 规则本体是纯函数，且可证伪

`window_state::decide_placement` 不依赖 Tauri 类型（输入是 `WindowState` ＋ `MonitorRect` 列表），所以 CI 能断言：

| 情形 | 结论 |
|---|---|
| 没有 `window` 段、没有尺寸、尺寸 ≤ 0、拿不到任何显示器 | `Nothing`（宁可不摆放） |
| 矩形被某台显示器**完整包含** | `Restore`（含跨屏负坐标的副屏） |
| 只露出一角（右下角超一像素） | 不算在内 → 居中（相交≠包含） |
| 离屏／显示器被拔掉／超大尺寸 | `Centered`：居中主屏并把尺寸压进该屏可用区 |
| 有尺寸无坐标 | `SizeOnly` |

7 项单测覆盖以上分支。真实窗口摆放**只能人肉核对**（本机缺 WebKitGTK／tauri-driver），这是本项的已知残余风险；
CI 的 desktop job 验的是纯函数与静态配置断言，不验真机窗口行为。

## 4. 落盘时机：只在关闭请求

`on_window_event` 收 `CloseRequested` 时写一次。拖动/缩放过程逐事件写盘等于把配置目录当高频写文件用，
而 §11.1 明确 UiState 是"可丢失的本机状态"——崩了下次回默认布局，是可接受的代价，换来零抖动写盘。
写失败只在 stderr 留码位行，不影响关闭。

## 5. 本批刻意没做：`layout` 与 `tables`

契约里有 `layout.sidebarWidth`／`aiPanelWidth`／`tables.columnWidths`，但**界面上还没有能改它们的把手**：
侧栏不能折叠/拖宽、面板不可调、列表没有可拖列宽与列头排序（`VirtualList` 只渲染，不承载列布局）。
"持久化一个没人能改的值"不是收口而是假绿，所以这两段等 UI 有把手时再接——
届时按 ADR-0062 的前端模式做（`lib/uiState.ts` 读改写、内存态同步），面板宽度另要补 §11.3 的 clamp。

## 6. 推翻条件

若将来产品明确要求渲染层自主摆放窗口（例如多窗口管理器交给前端调度），届时按 ADR-0060 的断言风格
**逐权限**扩 capabilities（只加 `allow-set-position` 这类真正需要的），并在 ADR-0060 的静态断言里
同步白名单——不是整体放开 `core:window:*`。
