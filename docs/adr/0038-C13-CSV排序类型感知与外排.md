## 1. 问题背景

方案 §5.15 对 C13 只有一句话："小文件内存排序；大文件外排（分块排序＋多路归并）"，§4.12 补"经典外排归并实现：分块排序＋多路归并的分块与缓冲区策略"。留白：类型感知的判定输入与回退、外排触发阈值（产品口径不设数值，§9.1 无 C13 阈值）、临时文件的 Journal 待遇。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 类型感知输入 | a) kernel 读盘自取；b) 壳层解析键列取值（有表头时排除表头行）→ kernel 纯函数推断 | **b**：不变量 1 |
| 类型判定 | a) 全部可解析数值→Numeric、全部 ISO 日期→Date、否则 Lexicographic；b) 逐字符启发式 | **a**：零阈值；空值不参与判定 |
| 执行期解析失败行 | a) 报错中断；b) 回退字典序 | **b**：不丢行、不中断，与 dirty rows 既有口径同源 |
| 外排触发阈值 | a) 产品默认值；b) 调用方显式 `--external-chunk-rows`（OQ-28 同口径） | **b**：§9.1 无 C13 阈值，不得另立；未传＝内存排序 |
| 外排实现 | a) 归并时逐块回读排序；b) 分块（内存排序写临时文件）→ k 路归并 | **b**（§4.12 明指"分块排序＋多路归并"） |
| 临时文件 | a) 进隔离目录＋记 Journal；b) 目标目录内 `.batchdesk-sort-*.tmp`、归并后尽力删除、不记 Journal | **b**：临时文件是实现细节非用户数据（与 ADR-0036 create_dir_all 同口径）；键值+行号绑定保证稳定排序 |
| 多键与稳定性 | a) 单键；b) 多键（声明顺序即优先级）＋键相等保持原行序（行号决胜） | **b**：稳定排序是保守默认 |

## 3. 选择理由

- **类型感知**：Numeric 用 `f64` 比较（值序而非字典序——测试对照 "10" 数值序在 "2" 后、"2" 在 "10" 前，与字典序相反）；执行期单行 `parse::<f64>` 失败回退字典序，不丢行不中断。
- **外排**：排序键与原行号绑定后分块（`rows.chunks(chunk_rows)`）内存排序写临时文件（`.batchdesk-sort-<size>-<n>.tmp` 于目标目录），k 路归并按 `compare_by_keys` 取最小（含行号决胜保持跨块稳定）；临时文件归并后尽力删除。
- **管道复用**：F07 同构（编码检测→RFC 4180 解析→变换→目标编码写出→Journal `WriteAtomic`/备份还原→C15 并发池资格）；表头不参与排序并在执行期重验（E2010）。

## 4. 后果与退路

- **后果**：外排临时空间≈两倍输入（临时块文件）；日期键要求 `yyyy-mm-dd` 否则退化为字典序（文件名解析日期未做，§5.15 的"来源：修改时间/文件名解析"仅实现 mtime 来源——修改日期来自 mtime 前缀）。
- **退路**：多键追加只需在 `--sort-column` 序列扩展；外排阈值未来若入产品口径，改由 ConfigDocument 下发（调用方显式传参的接缝已在）。
