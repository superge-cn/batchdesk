# 0058. 拉取式读取端口与 C13 外排流式归并

## 1. 问题

C13 外排（方案 §5.15）分两相：分块排序相与 k 路归并相。当前实现两相都整块驻留——

- **输入相**：`read_bytes(source)` → `transcode` → `parse_records`，源文件与全部记录同时在内存；
- **归并相**：`cursors: Vec<(Vec<Vec<String>>, usize)>` 把每个块文件**整块读回并全量解析**，k 个块同时驻留；
- **产物相**：归并结果先拼成一个 `String`，再整段转码写盘。

ADR-0055 §4 已登记根因：现有 `read_stream` 是 **push 型**端口（`FnMut(&[u8])`），只能表达「有数据就交给你」，不能表达「我只要下一条」；而 k 路归并天然是拉取式——比较 k 个游标、取最小、再要下一条，不能要求适配层把整个块一次推过来。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 归并读取 | a) 复用 `read_ranges` 逐条读块内记录；b) 新增**拉取式**读取端口 `open_read_stream` | **b**：a 要先知道每条记录的字节偏移，等价于先整块扫一遍（内存虽降、I/O 翻倍且端口语义被借用）；b 是归并相的直接表达，`std::io::Read` 已是内核既有词汇（`RewriteCallback` 在用） |
| 端口返回型 | a) `Box<dyn Read + Send>`；b) 传 `&mut dyn Read` 回调 | **a**：拉取式的要点就是「调用方决定何时读下一条」，回调型会退化成 push。`Send` 约束只要求实现方提供可跨线程句柄（`File` 满足），与 `FsAdapter: Send + Sync` 一致 |
| 端口缺省 | a) 缺省降级为 `read_bytes`＋`Cursor`；b) 缺省 E5001 | **b**：与 `read_stream`/`write_atomic_with` 同口径——静默降级会让「流式」名存实亡，且把 O(文件) 内存偷偷放回归并相 |
| 输入相 | a) 也给输入相造一个「转码拉取器」；b) 复用既有 push 型 `stream_csv_records`，在回调内做分块落盘 | **b**：输入相是顺序扫描，push 已足够；回调内缓冲到 `chunk_rows` 行即排序落块，内存 O(块行数＋单条记录)，无需新概念 |
| 产物相 | a) 拼 `String` 再整段转码；b) `write_atomic_with` ＋ `CsvStreamWriter` 逐条转码写出 | **b**：复用 ADR-0054 的输出管道，目标 BOM 在最前面写一次（同 F04/F07 口径） |
| 临时块文件清理 | a) 成功后逐个删（现状）；b) `Drop` 守卫，成功/失败都清 | **b**：归并中途出错（读失败、写失败、取消）时现状会留下 `.batchdesk-sort-*.tmp`；守卫把清理从「成功路径」变成「作用域退出」 |
| 归并选择 | a) k 路线性扫描取最小；b) 二叉堆 | **a**：`external_chunk_rows` 阈值下 k 很小（块数 = 行数/阈值），线性扫描常数更小且保持既有稳定性；堆优化留给确有 k 大头的场景 |

## 3. 实现

- **端口**（设计 04 §4.1 追加条目 v1.12）：`fn open_read_stream(&self, path: &str) -> Result<Box<dyn std::io::Read + Send>, KernelError>`；缺省 E5001。桌面 `CliFsAdapter`＝`File::open`＋`BufReader`，长路径收口与读取错误映射沿用 `read_bytes` 同一路径。
- **`csv_merge::CsvRecordStream<R: Read>`**：拉取式记录迭代器——内部 64 KiB 缓冲＋`RecordFeeder`，`next_record() -> Result<Option<Vec<String>>, KernelError>`，EOF 时冲刷尾部记录。与 `parse_records` 的等价性由 `RecordFeeder` 既有单测（ADR-0054）承接。
- **`perform_csv_sort`**：输入相改用 `stream_csv_records`（表头校验、E2010 消息与 retryable 不变），回调内累积到 `chunk_rows` 即排序落块；EOF 后若从未落块则内存排序（与旧行为等价），否则剩余行补落一块后进入归并相——每块一个 `CsvRecordStream`，逐条拉取取最小写出；产物经 `write_atomic_with`＋`CsvStreamWriter` 流式转码。临时块文件由 `ChunkCleanup` 守卫在作用域退出时删除。
- **稳定性**：块按输入顺序生成，归并同键时保留更早块（比较返回 `Equal` 时不替换 `best`），与旧实现「同键按原序」一致。

## 4. 已接受的坑与边界

- **归并相的内存单位是「k 条记录」**（每块一条游标）＋单条记录本身；块文件不再整块驻留——这是本 ADR 的净收益，也是它能落地的原因。
- **`open_read_stream` 目前只服务 C13 归并**：其它流式臂仍走 push 型 `read_stream`；两个端口并存不是冗余，而是「顺序扫描」与「按下一条取」两种访问模式的分别表达。
- **临时块文件仍写在目标目录**（`.batchdesk-sort-*.tmp`）：跨卷临时目录会引入「同卷才能原子改名」的新约束（设计 04 §4.1 同卷判定），不在本批范围；守卫只保证不残留。
- **块内排序的并列键**用块内序号兜底、跨块用块序兜底；这与旧实现「全局序号兜底」的结果一致（旧实现全局排序一次，靠的也是输入顺序），由等价性单测钉住。
- **未做**：`external_chunk_rows` 的自适应（块大小随内存预算调整）、归并的堆化、以及把 `open_read_stream` 用于 F04/F06 的输入侧——都不在本批。
