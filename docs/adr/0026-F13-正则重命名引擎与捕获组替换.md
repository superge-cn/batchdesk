# 0026 F13 正则重命名：regex 引擎、捕获组替换与共享计划核心

- 状态：已采纳
- 日期：2026-10-31
- 关联：[设计 01 §3.1/§5.1](../design/01-内核接口与IPC契约.md)、[设计 13 §2.1](../design/13-CLI契约.md)、[方案 v1.19 §5.5](../baseline/产品方案-v1.19.md)、[T v1.12 F13](../baseline/功能测试方案与验收标准-T-v1.12.md)、[TC v0.3 F13](../testing/测试用例库-TC-v0.3.md)、[ADR-0024](./0024-F12-批量重命名与两阶段计划.md)

## 1. 背景

F13 要求"正则捕获组改名、默认预览、留新旧映射可回滚"（方案 §5.5）。F12 已把重命名族的冲突扫描、长路径分级、两阶段临时名与 Journal 撤销打通；F13 只差"名称变换器"与正则引擎。工程上必须决定：选哪个正则引擎、捕获组替换语法如何校验、循环/大小写/冲突/长路径是否复用 F12，以及如何满足 TC 的"回溯风险样本"要求。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 用 Rust `regex` crate（有限自动机实现，线性时间）做匹配与 `$1`/`${name}` 展开 | **选用** |
| B | 自建回溯引擎或引入 PCRE 类库，配运行时超时/步数上限 | 否决：回溯引擎需要额外超时/步数机制才能防爆炸，攻击面与实现成本都更高；方案 §5.5 的"超时/步数上限"是防回溯爆炸的手段，不是必须暴露的 API |
| C | 只支持字面替换，不支持捕获组 | 否决：不满足 F13 的捕获组要求 |

## 3. 选择理由

- `regex` crate 使用有限自动机，匹配时间与文本长度线性相关，不存在灾难性回溯；TC 的"回溯风险样本"因此可直接由测试证明"快速返回"，不需要再发明超时数值（AGENTS 禁止自立阈值）。
- 编译失败（语法错误/超出引擎默认大小限制）在计划期返回 E1002，绝不进入 apply；计划即 dry-run，非法正则不会产生任何写入。
- 捕获组展开支持 `$1`、`${name}` 与 `$$`（字面 `$`）。引擎对不存在的组会**静默展开为空串**，在批量改名里等于静默删名字片段；因此在计划期校验模板引用，引用缺失返回 E1002，宁可让用户改模板，也不静默产生错误新名。
- 空正则匹配每个位置，替换结果几乎必然不是用户意图；与 F12 空 `find` 一致，计划期拒绝空 `pattern`；CLI 的 `--replace` 必须显式给出（空串是显式删除）。
- 作用范围 `full|stem|ext`、冲突扫描、长路径分级、两阶段临时名、保护目录与 Journal 撤销全部复用 F12 的 `plan_rename` 核心；F13 不另建一套重命名执行链。

## 4. 后果与退路

- 新增直接依赖 `regex 1.x`（MIT OR Apache-2.0）及传递依赖 `aho-corasick`/`regex-automata`/`regex-syntax`（均为宽松许可）；`cargo deny check licenses bans sources` 本地通过，advisories 由 CI deny job 复验。按不变量 9，PR 已记录引入理由。
- 设计 01 §3.1 的占位 `plan_regex_rename` 落为 `plan_f13`/`PlanF13Input`，与 F01–F12 命名一致；设计 13 §2.1 把 `f13` 纳入实验命令。
- F13 继承 F12 的剩余缺口：桌面 UI 预览、TC 的 PRE/EXE/RBK 人工用例逐条执行、Windows 实机 UNC/长路径矩阵；序号/模板规则仍属后续。
- 退路：若产品要求 PCRE 语义（后行断言/反向引用等），需要新 ADR 并重新评估回溯防护；当前 `regex` 不支持这些特性，属于明确的能力边界，不是缺陷。若产品要求"未知组静默为空"的引擎行为，删除模板引用校验即可，但仍建议保留预览。
