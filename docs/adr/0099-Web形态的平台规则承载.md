# 0099. Web 形态的平台规则承载：`OwnedNameRules`

- 日期：2026-11-18
- 状态：已落地（Wave 5 ③）
- 相关：设计 04 §2.1（平台事实不在内核推断）、设计 05 §2（导出面白/黑名单）、AGENTS 不变量 11；前置 [ADR-0098](./0098-WASM导出面骨架与零强制力feature.md)

## 问题

F12 的桌面输入 `PlanF12Input.name_rules: NameRules` 用的是**编译期静态切片**：

```rust
pub struct NameRules {
    illegal_chars: &'static [char],
    reserved_names: &'static [&'static str],
    ...
}
```

Web 形态（WASM）没法用——规则得**序列化进计划输入**（服务端下发或按目标卷选择），
而 `&'static [char]` / `&'static [&'static str]` **不可反序列化**。

三条路：

| 方案 | 评价 |
|---|---|
| ① 给 `NameRules` 加 serde、字段改 `Vec` | **否决**：判定热路径要付所有权/Clone，且改动所有既有构造点 |
| ② 只给 `NameRules` 加 serde，保留 `&'static` + `#[serde(with=...)]` 泄漏转换 | 可行但把泄漏细节埋进共享类型 |
| ③ **新增 owned 镜像类型**（本决策） | **采纳**：桌面/CLI 的静态切片一字不动 |

## 决策：`OwnedNameRules`

```rust
pub struct OwnedNameRules {           // 自有数据，可序列化
    pub illegal_chars: Vec<char>,
    pub reject_control_chars: bool,
    pub reserved_names: Vec<String>,
    pub trailing_dot_space: bool,
}
impl From<OwnedNameRules> for NameRules      // 转成静态切片（Box::leak）
impl From<&NameRules> for OwnedNameRules     // 反向（供 windows() 等构造）
```

- **判定逻辑与字段语义完全一致**，不另立口径；桌面/CLI 仍走 `NameRules::windows()/posix()`；
- `From<OwnedNameRules>` 用 `Box::leak`：规则**每批计划构造一次**、判定只读，泄漏量有界且不进热路径；
- `OwnedNameRules::posix()/windows()` 提供等价构造器。

## Web 输入的形状

```rust
pub struct WebPlanF12Input {   // 与 PlanF12Input 一一对应，仅规则承载不同
    ...,
    #[serde(default)] pub name_rules: Option<OwnedNameRules>,   // 缺省＝POSIX
    pub rule: serde_json::Value,                                 // 全局改名规则
}
impl TryFrom<WebPlanF12Input> for PlanF12Input   // 缺字段报错，不静默补默认
```

**缺省＝POSIX 语义**（保守：只拦 `/` 与 NUL，**不**推断 Windows 保留名/非法字符）——
浏览器无法可靠探测用户将写入的卷，猜错比保守更糟。

## 零强制力边界（不变量 11）

传入的是**平台事实**（名字合不合法），**不是授权判定**：
规则值由调用方声明，内核只做合法性比较，**不判「能不能用」**。
授权/配额判定仍在服务端（见 ADR-0098 的 `web-zero-force`）。
