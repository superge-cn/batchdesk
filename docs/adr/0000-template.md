# NNNN. 标题（一句话说清决策了什么）

- **状态**：提议 / 已采纳 / 已否决 / 已取代（Superseded by NNNN）
- **日期**：YYYY-MM-DD
- **决策者**：（角色或人名）
- **关联**：基线章节号（如方案 §4.11.3）或前序 ADR 编号（如 ADR-0001）

---

## 1. 问题背景

要解决什么问题、在什么约束下解决。
写清**触发条件**（为什么现在必须决定）与**不做决定的代价**。

> 自检：本节若出现"用户会不会……""这个功能该不该……"，说明这是产品问题，应走方案 §11.6，不是 ADR。

## 2. 候选与结论

列出真实考虑过的候选（通常 2–3 个，含"什么都不做"这个选项），每个候选写一句话定义，然后给出结论。

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | | **选用** / 备选 / 否决（理由） |
| B | | |

## 3. 选择理由

为什么是它。优先写**被排除项为什么不够好**，而不是罗列选用项的优点——排除理由才是半年后最容易被质疑的部分。

## 4. 后果与退路

- **后果**：这个决定会带来什么必须长期接受的约束（包括不好的那部分）；
- **退路**：什么条件下推翻它、推翻时的迁移成本是什么、退路是否需要改架构。

## 5. 关联

- 引用的基线章节号；
- 相关 ADR（被本篇取代／取代本篇／与本篇互补）；
- 相关代码或目录位置。
