# 0031 C11 CSV 去重：内存哈希判重、键序列化与切片边界

- 状态：已采纳
- 日期：2026-10-31
- 关联：[设计 01 §3.1/§5.1](../design/01-内核接口与IPC契约.md)、[设计 13 §2.1](../design/13-CLI契约.md)、[方案 v1.19 §5.15](../baseline/产品方案-v1.19.md)、[ADR-0018](./0018-F06-CSV合并列对齐与来源列.md)、[ADR-0020](./0020-F08-CSV抽取数量行与前后窗口.md)

## 1. 背景

C11 要求 CSV 整行或指定列拼键去重、保留首次出现（方案 §5.15），主要风险是"键选择不当造成误去重"。工程上必须决定：判重在内存还是外排、键如何无歧义序列化、无表头时列名键如何处置，以及本切片与已建 CSV 解析/计划/执行基础设施的复用边界。基线一句话思路中的"流式"与误去重风险直接相关：键列选错时用户必须在预览期看到将删除多少行，而不是执行后才发现。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 整文件解码后内存 `HashSet` 判重；键为 JSON 数组序列化；无表头拒绝列名键；预览期给出 uniqueRows/duplicateRows 与告警 | **选用** |
| B | 外排判重（分块哈希＋溢出文件＋多路归并） | 否决：引入临时空间与排序语义，C11 的数据规模定位在 CSV 合并族同级（F06 同为整文件内存），外排收益不抵复杂度；登记为缺口，出现真实大文件需求时再立切片 |
| C | 键用分隔符拼接字符串 | 否决：字段值可能含分隔符，`a|b` 与 `a` + `b|` 拼键碰撞，造成静默误去重 |

## 3. 选择理由

- **键序列化**：`serde_json::to_string` 把整行或选中字段序列化为 JSON 数组字符串（`["1","a"]`），天然免分隔符歧义与引号转义歧义；`HashSet` 插入成功即首次出现，顺序天然保持输入序，无需二次排序。
- **无表头拒绝列名键**：列名键依赖表头行存在；无表头时列名会静默退化为"找第一行数据当表头"，正是误去重的典型来源，计划期 blocked E3004 并提示改用 1-based 序号。
- **预览期统计即证据**：`PlanCsvDedup` 携带 `dataRows/uniqueRows/duplicateRows/dirtyRows`，计划 reason 写明"N 数据行 → M 唯一、K 重复"；有重复发 `duplicates-removed` Caution 警告、零重复发 `no-duplicates` Safe 警告、脏行发 `column-drift` Caution 警告——键选错的代价在 apply 之前可见。
- **复用既有管道**：解析/写出复用 F06 的 `parse_records`/`write_record` 与 `source_block`/`target_block`（保护目录 E2009）；编码检测/分隔符嗅探/脏行统计复用 `csv_merge_inspect` 的平台检查（新增 `csv_dedup_inspect` 返回完整记录）；apply 侧复用通用执行器的 E2010 复核、`write_atomic`、`backup_to_quarantine` 备份与 Journal 撤销，撤销语义按设计 01 §8（新建产物 reverse=Quarantine、覆盖 reverse=`WriteAtomic{dataRef}`）。
- **表头与脏行**：表头单独保留不参与判重；字段数与列宽不一致的脏行只计数告警、不静默修正——与 F05/F06/F08 的 CSV 族口径一致。

## 4. 后果与退路

- 设计 01 §3.1 增加 `csv-dedup` 动作与 `plan_c11`、§3 增加 `csvDedup` 载荷；设计 13 §2.1 把 `c11` 纳入实验命令。
- 已知缺口（必须登记、不得表述为产品完成）：整文件读入内存（内存 O(文件)，无外排）；重复行不做"保留末次/自选行"策略（基线只要求保留首次）；输出记录终止符规范化为 LF（与 F06/F07/F08 同口径）；TC PRE/EXE/RBK 人工用例与 UI 预览未做。
- 退路：外排化时保留 `dedup_records` 纯函数签名，在 apply 侧替换为分块哈希＋溢出文件实现；键序列化换成显式长度前缀拼接不影响计划载荷（`keyColumns` 只存 index/name，不含序列化细节）。
