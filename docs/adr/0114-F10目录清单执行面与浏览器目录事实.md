# ADR-0114：F10 目录清单的执行面与「浏览器目录事实」口径

- 状态：已采纳·A3-12 落地（2026-11-22）
- 相关：ADR-0105（计划能力分档）、ADR-0108（执行沙箱）、ADR-0109（改写器端口）、ADR-0113（改名族：目录第一层条目）；设计 02 §2.1／§3.1.1／§3.4；设计 01 §2（F10 `DirectoryLister`）
- 影响范围：`crates/kernel/src/memfs.rs`（`insert_dir`）、`crates/wasm/src/listing_mem.rs`（新增 `MemoryDirectoryLister`）、`crates/wasm/src/exec.rs`（`stage_dirs`／`stage_listing`＋`directory_lister` 注入）、`crates/wasm/src/lib.rs`（两个新导出）、`web/src/lib/web/facts.ts`（`listingTrees`）、`web/src/lib/web/planChannel.ts`（`planF10`）、`web/src/lib/web/applyChannel.ts`（F10 staging 分派）、`web/src/lib/wasm/{contract,worker,client}.ts`（两个新 op）、`web/src/FeaturePages.tsx`（`webDirectory`）

## 1. 背景

A3-11 收口时，计划面 21／25、执行面 21／21。剩 4 个不可计划的视图里，F10 目录统计一直记作 `directory-walk`——按功能名联想，认为「清单要遍历整个目录树，浏览器没有目录遍历 API，所以做不了」。

回到执行臂核对后发现归因不准：F10 的执行动作是 `listing`，它要的是 `DirectoryLister` **端口**（设计出入口在 `kernel::listing`），而端口吃什么由端口实现决定，不由浏览器决定。桌面端口 `platform::listing` 用 `std::fs::read_dir` 递归读真实目录；浏览器没有这个能力，但用户选目录时 `webkitRelativePath` 已经把**每个文件的相对路径**交出来了——文件数、目录数、最大深度都能从这些路径推出，清单的行内容也够写出（名字、层级、大小、修改时间）。

这与 A3-9 纠正 C08 的「port-missing」是同一类错误：按功能名联想（`listing` 就想当然等于「要目录树」），没回到执行臂与实际输入去核。真正缺的不是能力，是「让端口改吃浏览器给的事实」＋「让界面让用户选整个目录」。

## 2. 决策

### 2.1 端口放 WASM，事实由浏览器注入（不进 kernel、不伪造目录树）

`MemoryDirectoryLister` 实现 `kernel::listing::DirectoryLister`，放在 `crates/wasm/src/listing_mem.rs`。它**不遍历沙箱目录**——沙箱 `MemoryFs` 里没有真实的目录树结构可遍历。它读的是 `stage_listing` 登记的事实（`[{root, files:[{path,size,mtime}]}]`），按与桌面 `platform::listing` **同一套口径**写出清单：UTF-8 BOM、同名表头、每层名字排序、深度优先、层级从 1 起、目录大小 0、目录修改时间留空。

端口放 wasm 而非 kernel：kernel 是纯函数层（不变量 1），`DirectoryLister` 是 I/O 端口，实现归属与 `MemoryArchiveService`（ADR-0112）一致。

### 2.2 目录存在性由 `stage_dirs` 单独登记，缺失与端口缺失分开报

执行器在 `perform_listing` 前预检 `stat(源)` 要求源是目录，所以 `Sandbox` 新增 `stage_dirs` 只建**根**目录（`MemoryFs::insert_dir`，幂等，占位是文件时报 E2007）。不建子目录：`MemoryDirectoryLister` 不读沙箱树，多建反而是假事实（沙箱里凭空多出目录，而浏览器里它们可能根本不存在）。

于是有两种失败，必须分得开：

| 情形 | 报错 | 含义 |
|---|---|---|
| 只登记事实、没建根目录 | 逐条 `E2001` | 源的目录事实缺失（用户文件层面） |
| 建了根目录、没登记事实 | 逐条 `E5001` | 端口缺失（接线层面） |

### 2.3 `listingTrees` 从文件路径推出摘要与清单行

`web/src/lib/web/facts.ts` 的 `listingTrees(files)` 一次遍历同时产出计划摘要（`files`／`dirs`／`maxDepth`）与清单行（`rows`），计划与执行共用它——两处口径不会各自漂移。`planF10` 把摘要送进 `plan_f10`，`stage_listingFacts` 把 `rows` 送进沙箱。

`dirs` 只数**非空**目录（空目录没有文件路径，看不到）；`mtime` 取 `File.lastModified`（毫秒），内核列是纳秒故 ×1e6；目录的修改时间留空（浏览器不给目录的 mtime）。

### 2.4 `targetOccupied` 恒 false 是「如实」，不是「弱化」

沙箱每次执行前 reset，目标 CSV 在沙箱里本来就不存在。计划对齐它真正的执行环境（与 C04/F12 的 `existingTargets`、F07–F09 的输出路径派生同理）。

### 2.5 界面 `webDirectory`：桌面多行、浏览器目录选择

F10 的桌面 `roots` 是**多行路径文本域**（多个根目录一行一个）。若为了 Web 把它改成 `kind: "directory"`，桌面就被降级成单行输入——这是拿 Web 的交互限制改桌面。新增 `FieldSpec.webDirectory`：桌面仍渲染多行 textarea，浏览器渲染目录选择器（`webkitdirectory`），并加双语提示说明「空目录与占位文件看不到、目录修改时间留空」。

## 3. 替代方案与取舍

| 方案 | 结论 |
|---|---|
| 前端自己写一份 CSV 生成逻辑、绕过 WASM 执行 | **拒绝**：清单格式必须与桌面逐字节一致（BOM／表头／排序／层级），复制一份必然漂移；且要绕过 plan/apply 两段与 Journal，违反硬性不变量 2 |
| 让 `MemoryDirectoryLister` 去遍历沙箱目录树 | **拒绝**：`MemoryFs` 没有可遍历的目录树结构；而且浏览器给的事实里目录存在性与文件内容是两回事，混在一起会产生假事实（见 2.2） |
| 用 `showDirectoryPicker()` 取真目录句柄 | **不用**：需要安全上下文与用户手势，Chromium-only；`webkitdirectory` 已给出本决策需要的全部事实，且与 C07/C08/C04/F12 的交互一致 |
| F10 继续标 `directory-walk` 不支持 | **拒绝**：执行臂要的是端口不是目录树，浏览器事实够用；这是归因错误不是能力缺口 |

## 4. 后果

- Web 计划面 **21 → 22**／25，执行面 **21 → 22**／22（F10 全链路：选目录 → `plan_f10` → `stage_dirs`＋`stage_listing` → 真执行 → 产物 CSV 下载 → 撤销）。
- 剩余不可计划 3 个：C09（`content-hash`）、F11（`directory-walk`，且产物是空目录无法交付）、F13（前端无视图入口，走 `pending-wiring` 兜底）。
- 已知边界（如实记录，不当作完成）：
  - 空目录看不到（`webkitdirectory` 只给文件，没有相对路径）；占位文件与符号链接分不出（两类计数恒 0）。
  - 目录的修改时间留空（浏览器不暴露）；目录大小恒 0（与桌面口径一致）。
  - Web 侧 `targetOccupied` 恒 false（沙箱为空，见 2.4）。
- 推翻条件：若产品要求「浏览器里统计磁盘上真实目录（含空目录、精确目录时间）」，需要目录授权＋OPFS 落盘（ADR-0108 §1 的推翻条件），届时 `MemoryDirectoryLister` 的事实来源与界面提示要一并重做。
