# 0047. 参数变更失效落在入口层，取消回滚按执行臂断言

- **状态**：已采纳（2026-11-02，开发代理按台账既定方向实施）
- **日期**：2026-11-02
- **决策者**：开发代理
- **关联**：ADR-0045（Vitest 骨架与挂载缺陷）、ADR-0046（Playwright 真浏览器层）；方案 §7.3、§7.4、§7.7；设计 12 §3.1；AGENTS 硬性不变量 2／11

---

## 1. 问题背景

两条都是映射表逼出来的：

- **旧计划仍可执行**。方案 §7.3（v1.19 原文）："参数改动会使既有预览失效，需重新预览（防止'改了参数却执行了旧计划'这一最危险的状态错位）"。界面上此前只有"没有计划就不能执行"的禁用态：预览成功后再改参数，执行/撤销按钮依旧亮着，点下去执行的是**上一次预览**的那份计划。TC 配方 P4／E3 要断言的正是这条，映射表里它挂 ◐。
- **取消只在队列层测过**。ADR-0045 补了六臂（copy／move／edit-content／split／csv-extract／create-dir），但映射表的 E4 行仍大面积 ◐，理由是"本执行臂未单独断言"——N:1 与流式那一类臂（merge／csv-merge／csv-rows／csv-range／content-rewriter／listing）当时没有取消回滚用例。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 失效判定放在哪一层 | a) 前端比较"表单快照 vs 生成计划时的快照"；b) 壳层 applyPlan 再收一次参数并算指纹比对；c) kernel 在计划文档里存参数哈希 | **a**。计划本身是不可变产物，apply 执行的就是被预览的那份，不存在"参数变了但内核照旧执行"的漏洞；错位只发生在**入口**——用户以为新参数生效。b 要把每个 kind 的参数面再传一遍（IPC 面积＋serde 兼容负担），c 要动设计 01 的计划 schema，二者都为一条交互规则付架构成本 |
| 快照的粒度 | a) 逐字段 diff；b) 整份"影响计划的参数"做签名 | **b**：C09 工作台签名为 `{root, keep, quickWindowBytes, protectedDirs}`（即 `planOperation` 的实际入参集；保留期/永久清理/日志脱敏开关作用于执行与清理，不改变计划内容，故不入签名），功能页用整份 `form`（App.tsx `planSignature`／FeaturePages.tsx `plannedForm`）。任何入参变化都判失效，宁可多拦不可漏拦 |
| 失效后的呈现 | a) 静默禁用按钮；b) 禁用＋`role="status"` 提示"参数已改，请重新预览" | **b**：不可解释的禁用等于新缺陷；文案位置在执行区顶部（`data-testid="plan-stale"`） |
| 取消回滚断言的粒度 | a) 每个功能一条用例；b) 每个**执行臂**（PlanAction／载荷分支）一条用例 | **b**：同一臂的代码路径共享取消检查点，逐功能重复只增加时长不增加覆盖。`cancel_rolls_back_applied_entries_in_each_write_arm`（六臂）＋`cancel_rolls_back_the_batch_and_streaming_write_arms`（merge／csv-merge／csv-rows／csv-range／content-rewriter／listing 六臂），rename 臂沿用 ADR-0045 之前已有的 `cancel_mid_batch_rolls_back_applied_entries` |
| 哪些臂仍不算覆盖 | Delete（C09 隔离目录）、archive 专用执行器（C10 走 `apply_archive_plan`）、单条内部 mid-stream（C02/C03 流式重写中途） | **明确不升级**，映射表对应行保留缺口文字 |

## 3. 选择理由

- **不违反不变量 11**。强制力边界说的是"授权与功能判定"必须在执行路径里复核；§7.3 这条是交互时序规则，kernel 侧没有可被绕过的"判定"可复核。CLI 用户显式传入 planId，执行的仍是那份计划——不存在静默改参。因此入口层阻断是正解，不是把安全边界推给了前端。
- **失效判定要能被断言**。Vitest 用例「改参数后旧计划立即失效：提示出现且执行/撤销被禁用」证调用形状，Playwright `e2e/stale-plan.spec.ts` 两条（C09 工作台改保留策略、F12 功能页改前缀）证真实浏览器里按钮确实关闭且勾选确认也无效——后者是修复前的失败路径。
- **臂级断言写在 `generic_apply` 测试模块**：`TestFs` 的取消端口（`cancel_ports(after)`）在第 N 条条目进度上报后置位，`assert_cancelled(outcome, arm)` 断言落在条目边界；每条臂各断言"已应用条目回滚、未完成项无半成品、Journal 不残留 Applied"。

## 4. 后果与退路

- **后果**：CI 的 web job 现跑 Vitest 7 项＋Playwright 10 项；kernel 单测 **370 项**（`cargo test --workspace --all-features` 合计 **561 项**）。映射表 E4 行 19 条，其中 16 条 ✅、3 条 ◐（C02-EXE-04 mid-stream、C10-EXE-05 archive 臂、C15-EXE-05 并发/介质自适应）。
- **代价**：入口层阻断可被"绕过前端直接调 IPC"跳过——这是 UI 语义的固有边界，已如实记在映射表与本文；若日后要求内核拒绝执行与当前参数不符的计划，需要走设计 01 的计划 schema 变更（届时本文标 Superseded）。
- **退路**：Delete 与 archive 两臂的取消断言可沿用同一形状补（`apply_generic_plan` 的 Delete 分支与 `apply_archive_plan` 各加一条），属测试补齐、不改产品代码。
