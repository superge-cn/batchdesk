# 0054. 流式 CSV 执行臂与增量记录供给器

- **状态**：已采纳（2026-11-03，A 类流式改造第 2 批）
- **日期**：2026-11-03
- **决策者**：开发代理（工程实现决策；产品行为与阈值不变）
- **关联**：方案 v1.19 §5.15（CSV 家族）、§9.1（内存指标）；设计 01 v1.44 §5；设计 04 v1.11（`read_stream`）；ADR-0017…0020（F05/F06/F07/F08 设计）、ADR-0031/0032（C11/C12 设计）、ADR-0053（`read_stream`＋`StreamTranscoder` 底座）；`crates/kernel/src/csv_merge.rs`、`crates/kernel/src/csv_filter.rs`、`crates/kernel/src/csv_dedup.rs`、`crates/kernel/src/generic_apply.rs`

## 1. 问题

ADR-0053 只改了 F04（字节拼接型合并）。CSV 家族的五个执行臂仍是"整文件读入 → `parse_records` 全量解析 → 内存里构建整个输出 → 一次转码写出"：F06 合并 O(所有输入＋产物)、F07/F08/C11/C12 O(单输入＋产物)。方案 §9.1 的"超大文件内存占用恒定"对它们同样成立，且 C11/C12 的判重键集合本身就是必要驻留——能省掉的是**文件字节与输出产物**的驻留。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 记录解析 | a) 在原始字节上跑 RFC 4180 状态机再逐记录解码（F05 的做法）；b) 先流式解码成 UTF-8 文本块，再在文本上跑增量状态机 | **b**：a 依赖"0x22/0x0A 不会出现在多字节序列内部"这一编码性质（UTF-8/GB18030 成立、UTF-16 不成立），b 对一切支持的源编码都正确，且复用 ADR-0053 的 `StreamTranscoder`，解码语义与整段路径天然一致。代价是解码/再编码各一遍——与旧实现（整段解码＋整段编码）同量级 |
| 增量解析器 | a) 每块独立 `parse_records`；b) 新增 `RecordFeeder`（跨块状态机） | **b**：记录会跨块。`RecordFeeder` 与 `parse_records` 共用同一组助手与语义（引号转义、引号内换行、`\r\n`/裸 `\r`、空行、尾部记录冲刷），由等价性单测按 1/3/整段三种分块钉住 |
| 输出编码 | a) 逐记录转码写出；b) 输出继续攒大字符串最后转码 | **a**：每条渲染好的 UTF-8 行经输出侧 `StreamTranscoder`（UTF-8→目标）即时写出。完整记录都在字符边界结束，逐条转码与整段转码逐字节一致；目标 BOM 仍由调用方在最前面写一次（ADR-0053 同口径） |
| 源大小复核 | a) 维持 F06 的预读校验；b) 流式累计比对 | **b**：累计读取字节超过 `file.size` 立即 E2010（中止读取），EOF 后核对短缺——判定与消息同旧实现；F07/F08/C11/C12 旧实现本就无执行期大小校验（条目级指纹复核在 precheck），保持 `None` 不加码 |
| 内存口径 | — | 除 C11 判重键集合（O(唯一键)，固有）与 F08 last-N 环形缓冲（O(N 条记录)，固有）外，全部 O(块＋单条未完记录) |

## 3. 实现

- `csv_merge::RecordFeeder`：`new(delimiter)`＋`push(bytes) -> Vec<Vec<String>>`（本批完整结束的记录）＋`finish() -> Vec<Vec<String>>`（尾部记录）。
- `generic_apply::stream_csv_records(view, StreamCsvInput, on_record)`：`read_stream` → `StreamTranscoder`（源→UTF-8）→ `RecordFeeder` → 逐条回调；输出侧 `CsvStreamWriter`（UTF-8→目标 `without_bom`＋E3005 写错误映射）。
- 五臂改写：F07 按选择序抽列、F08 first 直通/last 环形缓冲、C11 `key_of`（改 `pub(crate)` 复用）判重、C12 `RowPredicate`（从 `filter_records` 抽出的单行判定器，整段路径同源）、F06 逐文件流式＋首记录表头映射。表头 E2010 消息与 retryable 逐臂保持原文。

## 4. 已接受的坑与边界

- **有表头而源里没有记录**：整段路径对空源报 E2010（`split_first` 失败）；流式版在流结束后按 `has_header && !header_checked` 补同一错误，行为一致。
- **空文件不核表头**（F06）：整段路径 `split_first → None` 时跳过表头核对，流式版同样跳过。
- **first-N 不提前停读**：`read_stream` 端口没有"中途停止"信号，提前停需要新端口语义；本批保持读完全源（内存已恒定，I/O 量与旧实现相同）。
- **输出换行仍规范为 `\n`**：C11/C12/F07/F08 的既有口径（不保留源 CRLF）不变，本批不夹带行为变更。
- **记录跨块**由等价性单测覆盖（`TestFs` 3 字节分块，记录边界全部被切开）；真实适配器 64 KiB 同理。
- **未动**：C01/C03/C13/C14 仍整文件读入（A 类剩余）；`perform_csv_range`（F09）本就按区间读取；合并进度粒度（单条 entry）未变。
