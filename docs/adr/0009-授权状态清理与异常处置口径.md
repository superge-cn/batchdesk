# 0009. 授权状态清理与异常数据处置口径

- **状态**：已采纳（2026-10-28 用户确认）
- **日期**：2026-10-28
- **决策者**：产品所有者确认 2026-10-28
- **关联**：ADR-0003（授权数据完整性与输入校验）§4 待办①、设计契约 [10-日志与诊断契约](../design/10-日志与诊断契约.md) §4、方案 §9.7／§8.2／§8.5、`docs/OPEN-QUESTIONS.md` OQ-12

---

## 1. 问题背景

ADR-0003 §4 留下一个待办：§9.7 的“一键清理”与授权/试用状态的关系未在基线写明；同时 §8.2／§8.5 的异常处置（损坏、篡改、时钟回拨）需要明确是否会影响试用期。若“一键清理”把授权状态一起删掉，用户可通过清理重置试用；若损坏数据被容错吞掉，可能 fail-open。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A 一键清理包含授权/试用状态 | 所有本地数据统一清除 | 否决：等于提供免费重置试用的入口 |
| **B 一键清理不含授权/试用；异常数据不延长试用** | 清理只覆盖配置/日志/备份/隔离目录；授权状态独立加密保存；损坏/篡改一律 fail-closed | **选用** |
| C 把授权状态也纳入用户可清理范围，但加二次确认 | 折中 | 否决：仍然可重置试用，且与 §8.5 防篡改目标冲突 |

## 3. 选择理由

- **B 与 ADR-0003 一致**：可疑篡改→降级 G0 + 审计；非篡改损坏→恢复通道；两条路径都不得延长/重启试用。
- **B 与 §9.7 的用户预期一致**：一键清理面向配置、日志、备份、隔离目录；授权状态是“不可丢失”的数据，单独加密、单独恢复。
- **不选 C**：二次确认不能阻止“删除即重置”的收益，反而增加误操作风险。

## 4. 后果与退路

- **后果**：① 一键清理的实现不触碰 LicenseService 自管的授权/试用状态；② 日志/诊断/支持包导出同样不含许可证载荷；③ 异常处置按“不延长试用”执行；④ 需在方案 §11.6 补一行并回填 §9.7/§8.2/§8.5 措辞。
- **退路**：若产品未来提供“彻底重置”入口，必须单独设计（明确告知会丢失授权、需重新激活），不复用一键清理。
