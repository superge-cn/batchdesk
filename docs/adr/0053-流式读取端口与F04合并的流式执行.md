# 0053. 流式读取端口与 F04 合并的流式执行

- **状态**：已采纳（2026-11-02，A 类流式改造第 1 批）
- **日期**：2026-11-02
- **决策者**：开发代理（工程实现决策；产品行为与阈值不变）
- **关联**：方案 v1.19 §5.15（F04 合并）、§9.1（内存指标）；设计 01 v1.43 §5 `merge`；设计 04 v1.11；ADR-0016（F04 设计与 BOM 策略）、ADR-0050（替换计数口径）；`crates/kernel/src/fs.rs`、`crates/platform/src/fs.rs`、`crates/kernel/src/encoding.rs`、`crates/kernel/src/generic_apply.rs`

---

## 1. 问题

F04 合并的执行器把每个输入 `read_bytes` 整文件读入、`transcode` 整段转码，再拼进一个 `Vec` 写目标——峰值内存 ≈ **所有输入之和＋产物大小**。方案 §9.1 要求"超大文件内存占用恒定"，而 F04 是阶段 0 里最直接的违例；映射表 `TC-F04-EXE-05` 因此只能标 ⛔（"大文件流式合并未做"）。

适配层当时只有"整读"（`read_bytes`）与"流式写"（`write_atomic_with` / `rewrite_atomic_with`），没有"流式读"，所以执行器即使想流式也没有入口。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 读取口 | a) 复用 `read_ranges` 按区间轮询；b) 新增 `FsAdapter::read_stream(path, callback)`；c) 让合并改用 `rewrite_atomic_with`（它只支持单文件原地） | **b**：区间轮询要调用方自己算偏移、且不知道文件何时结束；`rewrite_atomic_with` 是"同一文件读改写"，语义不匹配。回调式端口最贴合"逐块喂给解码器"的用法 |
| 缺省实现 | a) 退化为 `read_bytes`；b) 返回 E5001 | **b**：静默退化会让"流式"变成名义上的，测试也发现不了。不支持就不支持，调用方按契约拒绝 |
| 转码 | a) 每块独立 `transcode`；b) 新增 `StreamTranscoder`（跨块保持解码器状态） | **b**：多字节字符会跨块（GB18030/UTF-8 皆然），逐块独立解码必然在边界产出替换字符。解码器必须跨块复用 |
| 目标 BOM | 每个源各写一次 / 只在产物最前面写一次 | 只在产物最前面写一次（与 ADR-0016 一致）；`StreamTranscoder` 不写 BOM |
| 块大小 | 产品阈值 / 适配层细节 | **适配层细节**：桌面 64 KiB（与区间复制一致）。不写进基线、不新增可配参数 |

## 3. 实现

- `FsAdapter::read_stream(path, &mut FnMut(&[u8]) -> Result<(), KernelError>)`：桌面适配器按 64 KiB 读并回调；回调返回错误立即中止并原样上抛。
- `encoding::StreamTranscoder`：`push(chunk, out)` 解码并按目标编码追加；`finish(out)` 冲刷尾部不完整序列并返回 `StreamTranscodeSummary { replacement_count, had_bom_input }`。语义与整段 `transcode` 对齐：`Abort` 下解码出错立即 E3002，`ReplaceAndCount` 累计 U+FFFD（口径同 ADR-0050），源 BOM 由 `new_decoder_with_bom_removal` 剥离。
- F04 合并臂：`write_atomic_with(target, |writer| { 写一次目标 BOM；for source { read_stream → StreamTranscoder → writer } })`。逐源累计读取字节数与 `source.size` 比对，变化即 E2010（与原实现同判定）。写错误映射为 E3005。

## 4. 已接受的坑与边界

- **`decode_to_string` 不是"无限追加"**：dst 容量不足时返回 `OutputFull` 且只消费部分输入。第一版直接调用导致输出为空（单测当场抓到）；现按块扩容循环消费，超长行/大块不会丢字节。
- **块边界**：测试桩刻意用 3 字节块把 GB18030 双字节字符切开，覆盖跨块状态；真实适配器 64 KiB 同理。
- **只改了 F04**：F06/F07/F08/C01/C03/C11/C12/C13/C14 仍整文件读入（A 类剩余），按功能分批。它们的共同底座（`read_stream`＋`StreamTranscoder`）已就位。
- **没有回退路径**：不支持 `read_stream` 的适配器（当前只有测试桩与未来 WASM）跑 F04 会得到 E5001。这是有意的——降级为整读会掩盖内存问题。
- **进度粒度**：合并进度仍只到单条 entry，不随字节推进；本批不解决。
