# 0033 C15 任务内条目级并发：分块有界池、资源键不相交与 Journal 计划序

- 状态：已采纳
- 日期：2026-10-31
- 关联：[设计 01 §4/§5.1](../design/01-内核接口与IPC契约.md)、[方案 v1.19 §5.12/§7.10](../baseline/产品方案-v1.19.md)、[ADR-0025](./0025-F12计划级长路径分级与重命名族语料断言.md)

## 1. 背景

C15 要求"任务之间串行、任务内部条目级并发"（方案 §5.12），并发默认值按介质自适应、用户可调 1–16。当前实现（Wave 0 桌面任务队列 + kernel 执行器）任务间已串行，但任务内部执行器是严格串行的逐条循环。工程上必须决定：并发放在哪一层、条目间依赖如何不破坏撤销链（Journal 顺序是撤销语义的根基）、取消与部分失败语义如何保持，以及并发默认值未落地前的安全缺省。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | kernel 执行器内置**分块有界池**：独立条目按计划序收块（块大小＝并发上限、资源键不相交），块内 `std::thread::scope` 并发执行、按计划序 join 与记账；`entry_concurrency=1`（缺省）走原串行路径零变化 | **选用** |
| B | 长驻工作线程＋完成序记账（channel 驱动） | 否决：完成序记账让 Journal 顺序不确定（同批撤销顺序漂移）、进度 `done` 语义与报告对位复杂化；分块池在批量场景吞吐差距有限 |
| C | 壳层把计划拆成子计划并发派发 | 否决：plan/apply 两段式与 S03 幂等恢复、配额退还都以"整计划一个 Journal 流"为前提，拆计划破坏撤销与恢复语义（硬性不变量 2/4） |

## 3. 选择理由

- **并发边界**：只有 1:1 且条目间无顺序依赖的动作类可入池——`copy`/`edit-content`/`csv-dedup`/`csv-filter`/`csv-extract`/`csv-rows`/`delete`；`rename`/`move`（批内依赖与两阶段）、`split`/`merge`/`csv-merge`（多源汇聚）、`listing`/`create-dir`（目录层级序）一律串行。
- **资源键不相交**：条目的规范化源路径＋目标路径为资源键集合；与块内已有条目键相交（如同源两次 edit-content）→ 先收块再处理，绝不并发触碰同一文件。跨动作类的冲突（A 条目的目标是 B 条目的源）由同一集合拦截。
- **记账纪律**：Journal/配额/进度记账全部留在主线程（`&mut dyn JournalStore` 不可跨线程）；工作线程只拿 `WorkerView`（fs＋内容变换端口，全 `Send + Sync`）。分块按计划序 join 后逐条 `append_with_kind`——Journal seq 顺序与串行路径完全一致，撤销按 seq 逆序的既有语义不变。
- **报告对位**：回滚错误标注按"报告下标＝计划条目下标"定位；并发路径用按计划序的槽位填充报告，收尾时按序收敛（取消时未处理条目不产报告，与串行路径一致）。
- **取消与致命错误**：取消＝停止派发＋等待在途块安全收尾（原子写不落半成品）＋既有回滚；收块期间取消生效也停止派发。致命错误（Journal 写失败且不可逆）先收完块内结果再中止——成功条目必须进 Journal，不允许"已落盘未记账"。
- **缺省安全**：`entryConcurrency` 缺省 1＝原串行路径（行为零变化，既有 325 项测试直接回归）；上限 16、单任务条目上限 20 万都是方案 §5.12 既定值，执行层统一复核（不信任壳层入口）。

## 4. 后果与退路

- 设计 01 v1.28：`ApplyOptions` 追加 `entryConcurrency`（1–16，缺省 1）；执行期限额（20 万条目 E3007、并发范围 E1002）；执行期进度追加条目明细 `message`（双层进度的条目层）。
- 已知缺口（必须登记、不得表述为产品完成）：**介质自适应默认值未做**（SSD 4/机械盘 2/CPU 密集核数−1 需平台介质探测，自动档仍缺）——缺省 1 保持串行，参数可显式传 1–16；**C09 专用执行器（`apply_plan`）与 C10 归档执行器未接并发**（仅通用执行器 `apply_generic_plan` 支持）；队列待执行任务上限 50 的"引导排队"属 UI 展示层未做；运行中调参"下一批生效"（方案 §7.10）未做；致命错误自动暂停（磁盘满→暂停）未做。
- 退路：完成序池（候选 B）可在 `flush_chunk` 内部替换实现——分块接口（收块/资源键/结算）不变；介质自适应默认值落地时只需改壳层传参，kernel 契约不动。
