# 0005. 配置文件格式定版 JSON（排除 TOML）

- **状态**：已采纳（2026-10-27 用户评审确认）
- **日期**：2026-10-27
- **决策者**：用户评审确认 2026-10-27（起草：AI 协作）
- **关联**：[ADR-0004](./0004-类型契约单一来源.md)（类型单一来源）、设计契约 [01-内核接口与IPC契约 §2](../design/01-内核接口与IPC契约.md)（线协议命名）、[03-配置schema与迁移契约 §3/§10](../design/03-配置schema与迁移契约.md)（存储拓扑与挂账项）；方案 §4.5（配置管理）、§9.5（配方带版本）

---

## 1. 问题背景

配置文档（ConfigDocument）与配方（C37）需要落盘格式。篇 03 §3 当前按 JSON 描述但未正式冻结，§10 挂账"格式定版"。触发条件：ADR-0004 已把类型单一来源定在 Rust serde + specta 导出链上，**落盘格式必须与该链同源**，否则会出现第二套序列化事实（同样的结构两种文本形态），漂移从这里开始。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A：JSON（serde_json，camelCase，与线协议同源） | 配置即线协议 DTO 的直接序列化 | **选用** |
| B：TOML（toml crate） | Rust 生态常见的人工友好配置格式 | 否决 |
| C：INI / 自定义格式 | 最简键值对 | 否决 |

## 3. 选择理由

- **排除 B**：引入第二序列化依赖与第二套命名约定——TOML 社区惯用 kebab/snake-case，与线协议 camelCase 冲突，序列化时必须维护映射层；配方的 `paramsSnapshot` 是任意嵌套结构（篇 03 §5），TOML 对异构嵌套的表达天然别扭；Web 形态（OPFS + JS）消费 JSON 零转换，TOML 还需浏览器侧解析器。收益侧只剩"人工编辑友好"，但配置的正确入口是设置页（§6.7），该收益无效。
- **排除 C**：无 schema 生态、无嵌套与转义标准，与 ADR-0004 的 schema 生成链完全不兼容。
- **选 A 的核心理由**：serde 成为**唯一**序列化事实——配置落盘、IPC 线协议、specta 导出三处共用同一套类型与命名；schema 校验、迁移、契约测试全部复用同一工具链。

## 4. 后果与退路

- **后果**：配置文件人工编辑不如 TOML 舒适——接受：JSON 仍可读可改，改坏时走篇 03 §6.1-3 的损坏兜底（留副本 + 回默认档），不静默丢失。
- **退路**：若未来出现确需 TOML 的场景（如 CLI 手写配置，C40 类），迁移动作收敛为"新增 toml 读取层 + `configVersion+1` 一次迁移函数"，无架构级返工。

## 5. 关联与采纳执行清单

- 本 ADR 为**追认冻结**：篇 01 §2 与篇 03 §3 已按 JSON/camelCase 描述，采纳即视为定版，篇 03 §10 对应待决项关闭；
- 无新增依赖、无代码动作；若评审改向 TOML，则本 ADR 标记已否决并按 §4 退路执行。
