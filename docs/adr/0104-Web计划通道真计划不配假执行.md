# 0104. Web 计划通道：真计划不配假执行（C02 纵切）

- 日期：2026-11-21
- 状态：**已采纳**（A3-1 纵切落地：`web/src/lib/web/planChannel.ts` ＋ `FeaturePages` 的 C02 分支；A3-2 横向铺开到 16 个视图，分档判据见 [ADR-0105](./0105-Web计划能力矩阵按事实齐备度分档.md)）
- 相关：设计 02《Web 双通道传输契约》§2（事实采集层）/§3.1（OPFS/配额未实现）、设计 05 §2（导出面）、[ADR-0102](./0102-字节级探测算法下沉kernel.md)（字节级事实）、[ADR-0103](./0103-C10-Web侧条目清单零依赖中央目录读取.md)；AGENTS 不变量 11（Web 零强制力）

## 背景

A2 系列把 25 个 `plan_*` 全部导出到 WASM，但浏览器里功能页的 `planOperation` 只有两条路：

```ts
isTauri() ? invoke("planOperation", …) : mockPlan(input)   // ← 浏览器走的是假计划
```

于是出现第三种状态：**导出了、但没有生产消费者**。界面上的「计划预览」在浏览器里
是假数据，而真算法就在同一个包里躺着。

同时，Web 形态的 `apply` 并不存在：OPFS FsAdapter 未实现（设计 02 §3.1），
且设计 02 §2 已明确「产物仅存 OPFS，用户文件只读引用」——Web 侧不存在
「原地改名/移动用户文件」的语义。

## 决策

1. **新增计划通道层**（`web/src/lib/web/planChannel.ts`）：`File` → 事实（`facts.ts`）
   → `plan_*`（WASM）→ `PlanDocument`。只搬运，不判定（设计 05 §0）。
2. **先接 C02 一条**：25 个入口里 C02 的计划输入只需「头部样本＋整段字节」，
   不依赖目录遍历/目标占用/平台文件名规则等浏览器采不到的事实——语义最完整，
   适合当纵切样板（与 A1 选 C01 同理）。其余视图保持原路径，逐个接入。
3. **真计划不配假执行**：WASM 真计划（`planOrigin === "wasm"`）在界面上
   **禁用执行/撤销/回滚预演/存模板**，并显示 `feature.execute.webOnly` 提示。
   理由是「真计划 + mock 执行」比「假计划 + mock 执行」更危险：前者会让用户
   以为一个从未发生的写入已经完成。
4. **无文件时保持降级**：浏览器里未选文件（或 WASM 未装载）时仍走既有 mock 路径，
   不改变现有行为与测试口径；WASM 不可用单独报 `E5002`（能力缺失），不混进 `E9001`。

## 替代方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 继续让 mock 出计划 | 25 个导出永远没有消费者；界面预览与真实内核行为脱节 |
| 一次性把 25 个视图全接 | 每个功能的事实采集与参数映射不同（目录遍历/目标占用/哈希/压缩包），一轮铺完无法逐条验证；先纵向跑通一条再横向复制 |
| 真计划 + mock 执行 | 制造「已执行」假象，比现状更危险；撤销还会对不存在的任务发请求 |
| 浏览器里直接 `apply` 写 OPFS | 执行器不存在（设计 02 §3.1）；且「用户文件只读」意味着多数动作在 Web 语义下不成立 |

## 后果

- 界面出现第一种「只读计划」形态（`data-testid="web-plan-readonly"`）；后续每个视图
  接入时沿用同一 `planOrigin` 机制，不需要各自实现禁用逻辑。
- 事实采集窗口缺省 4096 字节（与壳层 `read_head` 同口径），大文件只读头部样本 +
  整段字节；整段读取的内存上限仍归 §13.10.2 的建议档，超出提示属后续切片。
- 证据：`planChannel.test.ts` 6 项（事实形状/原样交回/E5002/内核码/空文件拒绝）、
  `FeaturePages.webPlan.test.tsx` 2 项（真计划链路 + 执行链禁用；无文件时仍走 mock）；
  反向验证：去掉执行按钮的 `planOrigin === "wasm"` 条件，UI 用例实测变红。
