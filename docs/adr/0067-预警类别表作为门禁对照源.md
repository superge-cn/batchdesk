## 1. 问题

第 ⑩ 项门禁（[ADR-0061](./0061-错误文案的界面分层与错误码映射表.md) §8 之后补的）只覆盖 `status`／`state` 两族字段，
而集中报告里的告警类别 `warning.kind` 一直是内核 slug 直接当标题显示（`parent-is-file`、`column-drift`……）。
要把它收进界面文案，先要有一个**类别清单**能当对照源：

- `PlanWarning.kind` 是 `String`（设计 01 §2），不是 Rust 枚举——没有类型层的全集；
- 契约里此前**没有任何一处**枚举过这些类别，它们只散落在 `crates/kernel/src/**` 的构造点；
- 没有对照源就没有自校型门禁（第 ⑧ 项之所以能逐码对齐，是因为设计 06 §2 有码位表）。

所以本批第一件事不是写文案，而是**把既有事实显式成表**。

## 2. 候选与结论

| 议题 | 候选 | 结论与理由 |
|---|---|---|
| 对照源放哪 | a) 设计 01（DTO 的家）；b) 设计 06 §2A（错误码与用户文案契约）；c) 代码侧枚举（把 `kind` 改成 Rust enum） | **b**。这份清单的用途是给**界面文案**找对照物，06 已同构地承担 §2 码位表，门禁第 ⑧/⑪ 项在同一个脚本里同一种读法；a 会让文案门禁去解析接口契约，两件事耦合；c 是**更大的一步**——`kind` 改枚举会波及每个 plan 模块与既有 wire 测试，且它改变的是内部类型而非本轮要解决的露出缺陷，另批再做 |
| 表格粒度 | a) 只列类别与 key；b) 再加语义与缺省风险级 | **b**。语义列按内核 `suggestion` 原意写中文，评审时能认出类别；风险级取实测快照，但**判定仍以 `PlanWarning.riskLevel` 为准**（本表不另立判据，避免自立数值/口径） |
| 界面显示什么 | a) 类别标题＋建议行都本地化；b) 只本地化类别标题，建议行仍显示内核文本 | **b**（本批范围）。`suggestion` 是内核 format 出来的明细，常含路径与计数；把它换成界面文案要么逐类模板化（等于重做一遍集中报告），要么脱敏（改基线 §4.6 的三层提示口径）。两难已登记进设计 06 §5 待决，与 [OQ-38](../OPEN-QUESTIONS.md) 同族，属产品行为，**开发代理不自行定案** |
| 映射查不到时 | a) 直接显示 slug；b) 显示「未登记的预警类别（{kind}）」 | **b**。a 会让契约漂移伪装成一条正常文案；b 把它摆成看得见的缺陷，同时不丢信息（第 ⑪ 项本就要求两侧对齐，正常路径不会走到这里） |

## 3. 实现

- **表**：设计 06 §2A 收录 **61 个类别**，逐条实测自 `crates/kernel/src/**` 中所有 `PlanWarning { … }` 构造点
  （脚本按花括号配对解析 `kind` 与 `risk_level`，抽取表与内核不一致时生成器直接断言失败）。**类别集合未增未改**。
- **映射**：`web/src/warnings.ts` 的 `WARNING_KIND_KEYS`（slug → `warning.<camelCase>.title`），
  key 由 slug 的 camelCase 派生，并有 `warningKindTitle()` 的缺陷态兜底。
- **文案**：`locales/{zh-CN,en-US}.json` 各加 61 条 ＋ `common.warningUnregistered`（511 → **573** key）。
  标签按语义改写成短语——界面那是行首标题，放不下整句；明细仍来自内核。
- **门禁**：`check_locales.py` 第 ⑪ 项做三方逐类对齐（表 ↔ 映射 ↔ 两语言包），key 形态也校验同源，
  并要求语言包不得出现映射外的 `warning.*` 文案；自校＝表解析为空即报「门禁自校失败」。
  `KEY_DOMAIN_RE` 增 `warning` 域，第 ⑥ 项（引用 key 必须存在）随之覆盖它。
- **界面**：C09 工作台与 23 功能页的集中报告标题改走 `warningKindTitle(t, warning.kind)`；
  语气色仍取 `warning.riskLevel`（判定不变，只换标题文本）。

## 4. 已接受的坑与边界

- **表在内核之后写**：新增类别若没同步 §2A，编译与测试都不会红——红的是第 ⑪ 项（映射有、表没有）。
  前提是这个门禁每次 CI 都跑（web job 与两个测试 job 各一处）。
- **只挡得住「有没有对齐」，挡不住「语义写得对不对」**：表里的中文语义列是人写的概括，错了我自己发现不了，
  需评审；这也是把它放进契约文档而不是塞进代码注释的原因。
- **建议行仍是内核英文**：本批不动它（§2 表里已注明），因此集中报告在中文界面里仍是「中文标题＋英文明细」的混合形态——
  刻意如此，不是遗漏；统一要等产品对 §5 待决表态。
- camelCase key 由 slug 派生：改名（如 `column-drift` → `column-count-drift`）会同时换 key，
  两语言包旧 key 会被「映射表外文案」那条抓出来，不会留下死文案。

## 5. 验证

- **先红**：`FeaturePages.warnings.test.tsx` 的两条断言改前失败——
  `Unable to find an element with the text: 父级位置是文件`（当时界面就是 `parent-is-file`），
  以及未登记类别那条找不到「未登记的预警类别（brand-new-category）」。改后 3 条全绿。
  同时改掉旧断言本身：它此前把 `parent-is-file` 这个 slug 当期望文案钉进测试，等于把缺陷固化成契约。
- **门禁反向证明六路，全部 exit 1**：① 删映射中一个类别 →「§2A 有 1 个类别没进 warnings.ts 映射」；
  ② 映射里加一个假类别 →「有 1 个类别不在设计 06 §2A 表里」；③ 从语言包删一条文案 →
  「zh-CN 缺预警类别文案：warning.columnDrift.title」（附带 key 集合一致性也红）；
  ④ 语言包塞一个映射外 `warning.*` key → 红；⑤ 把表清空 → 「预警类别表解析为空：门禁自校失败」；
  ⑥ 映射 key 与表不同源 → 「warnings.ts 用 columnDriftX，设计 06 §2A 表定的是 columnDrift」。
  还原后 exit 0。
