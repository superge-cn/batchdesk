# 0088. loadRecipe 的路径槽位与本地 UI 边界

- **状态**：已采纳
- **日期**：2026-11-09
- **决策者**：产品所有者（选择「用户选配方＋用户填槽」）
- **关联**：设计 14 v1.2 §6/§12；ADR-0077；ADR-0080；ADR-0087

---

## 1. 问题背景

设计 14 v1 把 `loadRecipe` 列为模型工具，但配方套用需要 `recipeId` 与路径槽位
`pathParams`：让模型选择配方需要发送配方名称/描述，让模型填写路径需要发送/生成路径，
两者都会扩大数据出境面。OQ-40① 已实现 `loadRecipe` 命令与路径槽位表，缺的是 AI 侧口径。

## 2. 裁决

2026-11-09 用户选择 **用户选配方＋用户填槽**：

1. AI 面板提供「套用处理模板」入口，跳到**本地模板库**（`TemplatesPage`）；
2. 用户在本地列表选配方、填路径槽位、生成预览；配方名/步骤/路径**不发送给模型**；
3. `loadRecipe` 仍是壳层命令，但只由本地 UI 调用，**不属于模型工具 allowlist**；
4. AI 工具 allowlist 保持 `scanDirectory` + `planOperation` 两项。

## 3. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 用户选配方＋用户填槽，AI 不接触配方元数据/路径 | **选用**（零新增出境面；复用既有模板库槽位表单） |
| B | 模型选配方、用户填槽 | 否决（需发送配方名称/描述，新增出境面与同意文案） |
| C | 模型从用户文字提取路径 | 否决（路径进模型输出，与默认不发送路径冲突最大） |
| D | 不启用 | 否决（本地模板库已有可用套用流程，只缺入口） |

## 4. 实现

| 层 | 改动 |
|---|---|
| 前端 | `AiPanel` 新增 `onOpenTemplates` 与「套用处理模板」按钮＋说明；点击关闭面板并切到 `templates` 视图。配方选择/槽位表单/预览全部复用 `TemplatesPage`。 |
| IPC | 无新增命令；`loadRecipe` 仍由 `TemplatesPage` 调用。 |
| AI 编排 | `ALLOWED_TOOLS` 不变；模型输出 `loadRecipe` 仍按 E6004 拒绝（不在 allowlist）。 |
| 数据边界 | 配方名/步骤/路径/内容不出端；多轮历史仍只含用户文字（ADR-0087）。 |

## 5. 后果与已知限制

- AI 不参与配方选择；用户需要自己知道要用哪份模板。这是数据最小化的直接代价。
- 模板库的套用判定/降级仍以 `describeRecipe` 为准，AI 面板不重复一套逻辑。
- **未完成**：真实模型 staging 验收（人工）。
