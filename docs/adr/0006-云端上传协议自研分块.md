# 0006. 云端上传协议：自研轻量分块（排除 tus）

## 1. 问题背景

篇 02 §4.2 已冻结云端上传的 REST 草案（`createUploadSession → chunks → complete`，块序号 + 校验和，幂等重放安全），§7 挂账"是否采用现成断点续传规范（如 tus）或自研"。触发条件：云端通道服务端可后置（§13.1 硬约束 3），但传输协议决定服务端骨架，必须在服务端动工前定案——事后换协议 = 全量返工。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A：自研轻量分块协议 | 按篇 02 §4.2 冻结规格：会话 + 块 index + 块校验和 + complete 聚合校验 | **选用** |
| B：tus v1.0.0 协议 | 标准 resumable-upload 协议，配 tus-js-client + tusd 服务（或自实现） | 否决 |
| C：单请求整传 | 不分块，一次 PUT 完成 | 否决 |

## 3. 选择理由

- **排除 B 的核心理由——互操作价值为零**：tus 的全部价值在"任意第三方客户端/服务端互认"；本产品客户端（自家 web/）与服务端（自家唯一后端）都是单一实现，无第三方接入诉求。而代价真实：tusd 作为第二服务组件必须与任务级沙箱生命周期（§13.7 每任务独立容器、结束即销毁）耦合，增加镜像复杂度；校验和在 tus 是可选扩展而非核心，仍要自写；协议状态机（Upload-Offset 协商、并发 PATCH 守卫）成为外部黑盒，排障与测试都要按它的口径来。
- **排除 C**：§13.9 已承诺"性能低于桌面，进度可见、可取消"，弱网与较大文件下整传必然整包重试；断点续传是云端通道的存续前提，不是优化项。
- **选 A 的核心理由**：篇 02 §4.2 规格已满足断点续传的全部必要性质（见 §5 最小性质清单），实现面是服务端三个端点 + 客户端一个会话封装；上载体量引用方案 §13.7 成本量级假设（月 2TB 量级、单任务数十 MB 级），不构成引入标准协议的规模理由。白名单/配额/删除 SLA 等服务端中间件反正自研（§13.7），tus 不减免其中任何一项。

## 4. 后果与退路

- **后果**：协议正确性责任自担——并发块写入、offset 对账、校验和、会话过期全部自建并测试（§5 清单即验收标准）；不享受 tus 生态的后续演进与工具。
- **退路**：传输层适配点已收敛——客户端只有 `BlobRef` 会话封装一处（篇 02 §2/§4.3），服务端只有 `/v1/sessions` 三个端点；若未来弱网/规模超出自研能力（如需要并发分块竞速、全局限速），迁移 tus 只替换这一层，**命令契约（篇 01/02）与 kernel 零改动**。迁移触发条件写死：弱网重试成功率或服务端带宽利用率持续不达标（指标口径引 §9.1/§13.10.2）。

## 5. 自研协议最小性质清单（验收即测试锚点）

| # | 性质 | 说明 |
|---|---|---|
| P1 | 幂等重放 | 同 index 同 body 重放不产生重复或损坏；块以 index 幂等覆盖 |
| P2 | 断点续传 | 客户端可查询已确认块集合（GET 会话），仅补传缺失块 |
| P3 | 块级校验和 | 校验失败仅作废该块（E5012，retryable），会话保留 |
| P4 | 会话过期 | 过期后块写入返回 E5005；客户端重建会话补传未确认块；过期取值引用 §13.10.2 配置项 |
| P5 | complete 聚合校验 | 服务端结算总长与块完整性后方可入沙箱执行（§13.7 白名单/魔数校验在前） |

错误码 E5012（E5 段追加）：上传分块校验失败，retryable = true——已同步篇 02 §5 码位表。
