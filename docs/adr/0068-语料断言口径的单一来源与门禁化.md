# 0068. 语料断言口径以断言台账为单一来源并门禁化

- **状态**：已采纳
- **日期**：2026-11-05
- **决策者**：开发代理（工程实现决策；不涉及产品行为、功能范围或数值阈值）
- **关联**：T v1.12 §3.2／§4.2；OQ-08；`crates/kernel/tests/assertions.tsv`；ADR-0051、ADR-0067（同为"建对照源再做门禁"）

---

## 1. 问题背景

2026-11-04 语料收口后，`crates/kernel/tests/assertions.tsv` 已是 **23 asserted／1 partial（K08）／0 pending**，`corpus.rs` 也有台账覆盖测试。但同一个事实在 CI 注释、`AGENTS.md`、`fixtures/README.md`、人工语料台账、测试分册、`docs/README.md`、追踪表、开发计划、TC v0.4 里各抄了一份，其中十份仍写着「16 条 pending」「20 asserted／4 partial」「E03 待接」「逐条断言 harness 尚未实现」。照这些文字读，会得出"harness 根本没建"的错误结论——而它并不是产品判断，只是没人同步。

既有门禁只核 tsv 与 `corpus.rs`，**文档里手抄的第二份数字没有任何东西看**。触发条件：一次状态变化已经漏同步到十处，且每次语料收口都要人肉重复一遍；不做决定的代价是台账持续失真，而且失真是静默的——CI 全绿也不报。

> 本节不出现"用户会不会……"：这不是产品问题，是同一事实多份副本的工程问题。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 全仓扫所有 `.md` 的 `N asserted／partial／pending` 并比台账 | **否决**：CHANGELOG、ADR 正文、`DEVELOPMENT-PLAN` §6.1 状态表、manifest 落地记录、映射表批次留痕都是**带日期的历史快照**，按 `check_docs.py` 文件头约定必须原样保留；全仓扫会把它们全判红，等于逼着人篡改历史 |
| B | 白名单「当前陈述」文件 + 锚点行 + 以 tsv 实算值比对，附过期措辞黑名单与探测器自校 | **选用** |
| C | 什么都不做，下次收口时人工逐处同步 | **否决**：本批已实测人工同步会漏十处，且漏了没有反馈 |

## 3. 选择理由

选 B 的关键是**排除 A 的代价**，不是 B 多聪明：历史记录里那些「19 asserted／4 partial／1 pending」是当时真值的证据，改掉它们会让台账失去可追溯性，而门禁本该保护台账、不是逼人抹平台账。因此 B 把受检面收窄到两层——白名单文件；对历史行极多的 `DEVELOPMENT-PLAN`、`docs/testing/README` 再收窄到明确写「当前口径」的锚点行。`fixtures/README.md` 更进一步：它自己写着"不复制条数与编号，避免与门禁数据源漂移"，于是本批不是把它的数字改对，而是**把数字副本删掉、改成指回单一来源**——这比修正数字更贴合该文件原有的约定。

C 被排除的理由是它已经被证伪：这批漂移正是前几次"人工同步"留下的。

## 4. 后果与退路

- **后果**：① 新增或改动「当前陈述」文件时必须把它列入白名单，否则不受检查；② manifest 的历史行不得去掉 `> **落地记录` 前缀；③ 门禁只认 `N asserted／partial／pending` 形态与一份明确的过期措辞黑名单，换写法会让**探测器自校**先报"没有正例＝核对失效"，不会静默假绿；④ 正则要求数字前不紧邻字母，否则 `E03 pending` 会被读成「3 pending」（本批实测踩过）；⑤ **不新增 CI 步骤**，挂在既有「文档一致性」步骤里，改流水线属人类确认（沿用 2026-11-05 功能码清单门禁的边界）。
- **退路**：若断言台账换载体，改 `ASSERTION_TSV` 常量与解析即可，迁移成本是一个函数、不动架构。若 K08 收口使分布变为 24/0/0，门禁会要求所有当前陈述同步——这是**预期行为**，不是误报；届时同步文档即可，无需改门禁。

## 6. 验证与边界

- **正例**：`python3 scripts/check_docs.py` exit 0，成功输出含「语料断言口径以 assertions.tsv 为单一来源」。
- **反向证明三路（均 exit 1 且报对原因，还原后 exit 0）**：① `AGENTS.md` 写回 `20 asserted／4 partial` → 报数字漂移并给出 tsv 实值；② CI 注释塞回「标 pending／其余 16 条自动化语料」→ 报过期措辞并点名行号；③ 把 tsv 的 K08 翻成 `asserted` → 全仓当前陈述一起报漂移，证明门禁真以 tsv 为准而非硬编码 23/1/0。
- **边界**：不检查历史行、不检查 ADR 正文、不改产品口径、不把 K08 说成已收口；`docs/design/01` 与 `12` 的修订记录里「`retryTask` 未实现」属 2026-10-29 当时的状态，是历史留痕，**本批刻意不改**（TRACEABILITY §2 已改口为已建）。
