# 0109. Web 执行面扩到九视图 ＋ 改写器端口在沙箱内构造

- 日期：2026-11-22
- 状态：**已采纳**（A3-7 落地：`crates/wasm::exec` 按计划 kind 构造 `TranscodeRewriter`／`LineEndingRewriter`／`ReplaceRewriter`；执行档位从 3 个视图扩到 **9 个**（C01–C03、F01–F06）；未接的 10 个按 `target-in-place`／`relative-paths`／`port-missing` 分类拒绝）
- 相关：[ADR-0108](./0108-Web执行沙箱与产物下载.md)（沙箱与产物下载，本文是它的第一批扩展）、[ADR-0105](./0105-Web计划能力矩阵按事实齐备度分档.md)（计划分档）、[ADR-0055](./0055-C01流式转码编辑器与ContentRewriter明细返回位.md)／[ADR-0056](./0056-桌面壳edit-content重写器装配与TranscodeRewriter上提.md)（C01 流式转码）、设计 02 §3.1.1、方案 §5.2／§5.3（转码与查找替换）

## 背景

A3-6 把执行面接到沙箱上时，只接了 F01/F02/F03，理由是「其余视图的执行臂要额外端口」。A3-7 逐个核对后，这个理由只对了一半：

1. **C01/C02/C03 要的改写器端口，实现本来就在 kernel 里**：`encoding::TranscodeRewriter`、`line_endings::LineEndingRewriter`、`replace_content::ReplaceRewriter`，三者都是 `from_plan(&PlanDocument)` 构造的纯逻辑（读计划参数快照，不碰磁盘）。platform 里只有 `FsDirectoryLister`。也就是说，Web 缺的不是「实现」，而是**没有人把这三者交给沙箱执行器**。
2. **合并/分片族的动作不需要任何端口**：`Merge`（F04/F06）、`Split`（F01/F02/F03/F05）只走 `FsAdapter` 的读写与区间复制。`MemoryFs` 已实现全部所需方法，因此这些视图在 A3-6 之后其实**已经能跑**，只是档位没登记。
3. **CSV 1:1 族（F07–F09、C11–C14）看着能跑，其实跑不了**：实测这些视图的计划把 `target` 指向**源文件自身**（Web 计划通道没有把表单的 `outputDir` 传下去），执行时目标已存在，`skip` 策略把整条跳过（E2007），`overwrite` 则等于原地覆盖源文件。**这是计划侧缺陷，不是执行器能力问题**。
4. **C07 的路径口径对不上**：目录选择给的是相对路径（`webkitRelativePath`），staging 只登记裸文件名，源路径匹配不上；F10 要 `DirectoryLister`、C08/C10 要 `ArchiveService`，这些端口确实没在 Web 装配。

## 决策

### 1. 改写器在沙箱内按 kind 构造，构造失败即失败

```rust
let rewriter: Option<Box<dyn ContentRewriter>> = if plan.kind == C01_KIND {
    Some(Box::new(TranscodeRewriter::from_plan(&plan)?))
} else if plan.kind == C02_KIND {
    Some(Box::new(LineEndingRewriter::from_plan(&plan)?))
} else if plan.kind == C03_KIND {
    Some(Box::new(ReplaceRewriter::from_plan(&plan)?))
} else {
    None
};
```

- **用 `from_plan` 而不是在 wasm 里重解析参数**：CLI 里原本有一份 `generic_plan_encoding` 做同样的四个参数解析，再拷一份到 wasm 就是第三份（ADR-0106 在 C07 上刚修过同一类漂移）。
- **`?` 直接冒泡**：参数快照缺 `target` 时 `from_plan` 报 E1001，执行**在写盘之前**就失败。若改成「拿不到改写器就原样复制」，产物看起来正常、内容却没变——比报错更坏。
- 计划与执行读的是**同一份参数快照**（`plan_c0X` 写进 `plan.params`），所以「预览说会转成 GB18030」与「执行出来的字节」不会各算各的。

### 2. 执行能力按「动作需要什么」判定，不按「视图做过什么」

登记表从「视图名单」升级为「动作 → 端口需求」：

| 动作 | 额外端口 | 可执行 |
|---|---|---|
| `edit-content`／`transcode` | 改写器（kernel 内实现） | C01/C02/C03 |
| `split`（含 `csv` 载荷） | 无 | F01/F02/F03/F05 |
| `merge`（含 `csv_merge` 载荷） | 无 | F04/F06 |
| `csv-extract`／`csv-rows`／`csv-dedup`／`csv-filter`／`csv-columns`／`csv-sort` | 无，但**计划把输出指向源**（见 §3） | 否 |
| `listing` | `DirectoryLister` | 否 |
| `archive`／`extract` | `ArchiveService` | 否 |
| `move`／`create-dir` | 无，但**相对路径口径**（见 §3） | 否 |

判据是**动作**：同一个动作在不同视图下需要的端口相同，用视图名单去记会漏（F05 的 `csv` 分片走的是 `split` 动作，不在 CSV 1:1 族里）。

### 3. 未接的 10 个视图按「缺什么」分类拒绝，不合并成一句「还没做」

`webApplySupport` 的 `gap` 从单一 `not-wired` 扩成四档：

| gap | 视图 | 含义 |
|---|---|---|
| `target-in-place` | F07–F09、C11–C14 | 计划把输出指向**源文件自身**（表单的 `outputDir` 没进计划）。执行时目标已存在 → `skip` 自我跳过、`overwrite` 原地覆盖源文件。修计划通道才能执行。 |
| `relative-paths` | C07 | 目录选择的相对路径没进 staging（只登记裸文件名）。 |
| `port-missing` | F10、C08、C10 | 执行臂要 `DirectoryLister`／`ArchiveService`。 |
| `not-wired` | 其余（含未知视图） | 保守兜底，不猜成能执行。 |

**为什么不用 `overwrite` 硬跑 `target-in-place` 的视图**：计划里写着「输出 = 输入」，强制覆盖只是把错误藏起来——用户看到「成功」，产物却顶掉了源文件；而计划预览里也没有「输出到哪」这一栏可核对。缺的是计划侧的字段，就该在计划侧修。

### 4. 已接的视图不做「逐视图」的白名单，而做「逐个动作」的证据

9 个视图背后是 3 类动作（`edit-content` 三态改写、`split`、`merge`），Rust 侧逐类各有一项端到端用例；视图名单只是这些动作的投影。新增视图时先问「它的计划里出现哪些动作」，再看这些动作有没有用例。

## 后果

- 浏览器可执行视图从 **3 个扩到 9 个**：C01 编码转换、C02 换行转换、C03 查找替换、F01–F03 分片、F04 文本合并、F05 CSV 分片、F06 CSV 合并。它们执行的都是内核原路径（不变量 2），产物从 Journal 取路径后下载，撤销 `products-only`。
- **发现一处计划通道缺陷并如实登记**：F07–F09／C11–C14 的表单有 `outputDir`，但 `plan_c1X`／`plan_f0X` 的线协议没有这个字段，计划因此写「输出 = 源文件」。这违反 ADR-0105「不产弱化计划」的口径——修法在计划侧（补字段 + 按 `outputDir` 生成目标路径），已写进台账与 TRACEABILITY 的剩余缺口，不在本文范围。
- C07 的执行还差一步「相对路径进 staging」：`stagedPath` 现在返回 `file.name`，而 C07 的计划源路径带子目录。属下一批。
- 证据：`crates/wasm --test exec_sandbox` **4 → 11 项**（新增 C01 转码字节、C02 原地改写与撤销还原、C03 多处替换、F04 合并顺序、F05 每片带表头、F06 表头只写一次、参数缺失先失败）；vitest **40 文件／325 项**（`applyChannel` 12→14：档位改为 9 个 + 三档缺口、C02 裸文件名口径）。
- 反向验证（实测红）：① 不装改写器 → C01/C02/C03 三条全红；② C03 分支改用 `LineEndingRewriter` → C03 用例红（参数缺失）；③ 从 `WEB_APPLY_VIEWS` 删掉 `c02` → 档位断言、C02 staging、C02 UI 三条红。

## 备选方案

- **把三个改写器搬到 platform 再共用**：没必要——它们已经是纯函数、已在 kernel，platform 里只有依赖真实目录句柄的 `FsDirectoryLister`。
- **在 wasm 里重写一份参数解析**：CLI 已有一份 `generic_plan_encoding`，再写一份就是三处漂移（C07 刚踩过）。`from_plan` 是唯一来源。
- **对 `target-in-place` 的视图一律用 `overwrite` 执行**：会把「输出=源」的错误固化，用户无从发现；且覆盖源文件在桌面语义里是需要显式确认的危险动作。
- **把 F07–F09／C11–C14 也算「可执行」但标注「产物会覆盖源」**：等于承认错误计划可用。缺字段就补字段。
