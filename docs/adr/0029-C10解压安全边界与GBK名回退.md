# 0029 C10 解压：ZIP 库选型、GBK 名回退与安全边界

- 状态：已采纳
- 日期：2026-10-31
- 关联：[设计 01 §3.1/§5.1](../design/01-内核接口与IPC契约.md)、[设计 06](../design/06-错误码与用户文案契约.md)、[设计 13 §2.1](../design/13-CLI契约.md)、[方案 v1.19 §5.11/§4.9](../baseline/产品方案-v1.19.md)、[T v1.12 Z01/Z02](../baseline/功能测试方案与验收标准-T-v1.12.md)

## 1. 背景

C10 要求 ZIP 解压兼容 GBK 名、拒绝路径穿越、限制解压炸弹（方案 §5.11/§4.9）。Z01/Z02 是冻结语料：Z01 是无 UTF-8 标志的 GBK 文件名，Z02 含 `../` 越界条目。工程上必须决定 ZIP 库、原始文件名读取、路径校验位置、限额来源与 Journal 撤销方式；若库不能读取原始名或不写标志位，按方案要求优先换库而非上层打补丁。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | `zip 9.1.3`（MIT）+ 原始名 `name_raw` + 自家 GBK 回退；kernel 校验路径/限额；逐文件 Journal | **选用** |
| B | 用 zip 库的 `name()`/`enclosed_name` 直接解压 | 否决：`name()` 对无 UTF-8 标志的非 ASCII 名按 CP437 解码，Z01 会乱码；`enclosed_name` 只能防穿越，不能做 GBK 回退、限额与逐文件 Journal |
| C | 自写 ZIP 解析/解压 | 否决：压缩格式细节与安全边界成本高于成熟库；本切片只需读取原始名与条目数据 |

## 3. 选择理由

- `zip` 9.1.3 暴露 `ZipFile::name_raw()` 与通用标志位；平台以 bit 11 判断 UTF-8，未设置且非 ASCII 时用 `encoding_rs`（经 kernel `transcode`）按 GB18030 回退，Z01 可正确显示并产生 `gbk-filename-fallback` 告警。ASCII 名不触发回退。
- 路径安全在 kernel 纯函数层完成：拒绝绝对路径、盘符、`..`、NUL、Windows 保留名/结尾点空格；目标必须 `is_under` 输出根目录。越界条目**跳过并告警**，不误伤同包安全条目（Z02）。
- 解压炸弹限额没有基线数值（方案只要求"限制"）；CLI 强制显式 `--max-total-bytes` 与 `--max-ratio`，无产品默认值（遵循 AGENTS 数值阈值纪律）。超限整包 blocked E3007，不写任何文件。
- 执行期逐文件/逐目录写 Journal：新文件 reverse=`Quarantine`，新建目录 reverse=`RemoveDir`；撤销按 Journal 逆序清理，复用统一 `undo`，不新建撤销框架。压缩包本身在计划期按大小指纹复核（E2010）。
- 本切片只做**解压**；压缩、GBK 名写入、密码/加密包与 7z/RAR 留给后续切片。设计 01 原先把 C10 解压描述为 1:N entries；本切片用"每压缩包一条 summary entry + 执行期逐文件 Journal"以复用现有 Plan/Apply 与撤销链，属已登记的契约偏差（后续若需逐条目预览/重试再拆 1:N）。

## 4. 后果与退路

- 新增 `zip 9.1.3`（MIT）与 `flate2`（MIT/Apache-2.0，rust_backend/miniz_oxide）；`cargo deny licenses/bans/sources` 通过，advisories 由 CI deny job 复验。仅启 `deflate-flate2`，不引入加密/其他压缩后端。
- 设计 01 §3.1 增加 `plan_c10`；§5.1 记录 C10 解压 summary entry 偏差；设计 06/01 增加 E3007；设计 13 §2.1 把 `c10 --extract` 纳入实验命令。
- 已知缺口：仅解压；压缩与 GBK 名写入未做；不支密码/加密包/非 stored|deflated 条目（E3003）；每压缩包一条报告（不逐文件报告/重试）；解压取消在条目/文件边界检查，已写 Journal 的文件可撤销；Windows 实机长路径/占用验收未做；TC PRE/EXE/RBK 人工用例未逐条执行。
- 退路：压缩与 GBK 写入可复用同一 `ArchiveService` 端口新增 `compress`；若要把报告细化到文件级，把计划拆成 1:N entries 并给 `PlanEntry` 增加 archive payload，执行器改为逐条目调用；不影响现有路径安全与 Journal 语义。
