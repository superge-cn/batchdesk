# 0098. C03 单元格模式的记录终止符保持：流式推断＋两趟改写

- **状态**：已采纳
- **日期**：2026-11-13
- **决策者**：开发代理（缺陷修复；判定口径引方案 §5.14「CSV 的结构保护」）
- **关联**：方案 v1.22 §5.14（「走 CSV 解析器，安全但仅支持结构化替换」「替换后校验列数一致性」）；TC-C03-EXE-04；`fixtures/bench/results.md` R-16

---

## 1. 问题背景

TC-C03-EXE-04 的缺口原文：

> CSV 单元格模式会把记录终止符规范化为 LF，源 CRLF 未保留（C-2 集 32 MiB 子档实测到同一行为：末条无终止符的记录被补 1 个 LF，产物＋1 字节、记录数＋1）。

真机复现确认（`id,name\r\n1,"a,b"\r\n2,foo\r\n3,bar`，30 字节）：
产物变成 `id,name\n1,"a,b"\n2,FOO\n3,bar\n`（28 字节）——**三处 CRLF 全被改成 LF，末条还凭空多了一个终止符**。

这正是方案 §5.14「结构保护」的反面：单元格级替换号称"走解析器、安全"，却把文件骨架给改了。**CRLF 与 LF 在 Windows 上是两种不同的文件形态**（Excel、旧工具链、某些签名校验都敏感），静默改掉是数据损坏级别的问题。

## 2. 候选与否决理由

| 议题 | 候选 | 结论 |
|---|---|---|
| 终止符从哪来 | a) 计划期采样统计后写进 `params`；b) **执行期流式推断** | **b**：a 要为 C03 加计划参数、改 `PlanC03Input`／壳层采集／`FEATURE_PARAM_MAP`，且采样窗口可能漏掉末尾的 LF-only 行；b 在重写器本来就要逐块读的地方顺手统计，零新增契约 |
| 何时知道结果 | a) 边读边按当前多数派写、最后不回头；b) **先缓冲、EOF 定档后统一改写** | **b**：终止符必须**整文件一致**（混排的文件本身是坏 CSV）。代价是内存 O(输出)——但 C03 单元格模式此前就已经是 O(输出)（`pending` 缓冲早就在了），不是新增代价 |
| 怎么改写 | a) 边扫边写；b) **先收集下标、再按片段拼** | **b**：a 在改写后长度变化时会错位（CRLF 比 LF 长 1 字节），实测会漏换某条记录的终止符——本 ADR 实现中真实踩到过 |
| 扫描用谁的规则 | a) 自己数 `\n`；b) **与 `RecordFeeder`／`RecordTerminator::infer` 同一套引号规则** | **b**：引号内的换行是字段数据（T01 已钉住必须保留），自己数会把 `"a,b"` 这类带分隔符的引用字段的换行算成终止符 |
| 改动范围 | a) 给 `write_record` 加参数；b) **新增 `write_record_with_terminator`，原函数保留缺省 LF** | **b**：F06/C11/C12/C13 四处调用方行为完全不变（零回归面） |

## 3. 决策

1. **`csv_merge` 新增 `RecordTerminator` 与 `TerminatorState`**：`infer(data, &mut state)` 逐块累计 CRLF/LF/CR 计数，`finalize(&state)` 按多数派定档（全 0 取 LF）。
2. **引号内换行不计入**：`infer` 的状态机与 `RecordFeeder::push` 同构（`at_field_start`／`in_quotes`／`after_quote` 三个状态逐条对齐），跨块的引号也能正确识别。
3. **`write_record_with_terminator(fields, delimiter, terminator, out)`**；原 `write_record` 保留、内部委托、缺省 LF。
4. **`rewrite_cells` 流程**：逐块 `infer` ＋ 记录写入时统一用 LF → EOF 后 `finalize` 定档 → `rewrite_terminators` 把**引号外**的 LF 换成目标终止符。
5. **末条无终止符不补**：`drain_finish()` 冲出的尾部记录用 `write_record_body`（不带终止符）写出——源末尾没有换行，产物也不该凭空多出一条空记录。
6. **`rewrite_terminators` 两趟法**：先扫出所有引号外 LF 的下标，再按 `[record_start, hit)` 片段写出、片末补目标终止符。

## 4. 后果

- **内核**：`csv_merge.rs` 加 `RecordTerminator`／`TerminatorState`／`write_record_with_terminator`；`replace_content.rs` 的 `rewrite_cells` 改为"缓冲→定档→改写"，新增 `write_record_body` 与 `rewrite_terminators`。
- **接口**：`write_record` 签名**未变**，F06/C11/C12/C13 产物形态零变化。
- **测试**：CLI `apply_flow` 新增 `c03_csv_cell_mode_preserves_crlf_record_terminators`（全 CRLF 源＋末条无终止符，断言产物逐字节）；既有 T01 用例继续通过（它 LF/CRLF 混排，改前恰好掩盖了 bug）。

## 5. 残余

1. **C03 单元格模式现在是 O(输出) 内存**（`body` 缓冲）：与改动前的 `pending` 同量级，非新增代价；若将来要优化成流式，得先解决"终止符 EOF 才知道"的矛盾（可改为两遍读文件）。
2. **混排终止符的文件按多数派统一**：源里 CRLF 与 LF 混排本身是坏 CSV，统一成多数派是确定性行为；不做逐行保持（那会让"一条记录一种终止符"的产物更难解释）。
3. **plain／regex 模式不受影响**：它们不改结构（原文照抄），本来就保留源终止符。
