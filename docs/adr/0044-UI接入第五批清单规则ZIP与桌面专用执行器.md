# 0044. UI 接入第五批：清单/规则/ZIP 的壳层接入与 c10 桌面专用执行器

- **状态**：已采纳（2026-11-01，开发代理按台账既定方向实施）
- **日期**：2026-11-01
- **决策者**：开发代理
- **关联**：ADR-0036（C07）、ADR-0037（C08）、ADR-0029/0030（C10）、ADR-0040…0043（UI 接入前四批）；设计 01 §4.1/§4.3；设计 12 §3.1

---

## 1. 问题背景

阶段 0 的 25 个功能到 ADR-0043 后只剩三项没有桌面路径：C07（清单驱动移动/复制）、C08（按规则归档）、C10（ZIP 解压/压缩）。三者各有特殊性：C07 的输入是**清单文件**（需编码感知解析并逐行采集存在性/大小/目标占用），C08 的输入是**规则链文本＋目录树事实**，而 C10 不仅有计划面，还缺**桌面执行器路由**——`run_apply` 此前把所有非 c09 计划一律交给通用执行器，ZIP 归档走的是 kernel 专用执行器 `apply_archive_plan`（逐文件 Journal、压缩产物单条 Journal），落在通用执行器上会丢失该语义。台账因此把"c10 ZIP 桌面执行"记为暂缓项。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 模块划分 | a) 三个 kind 各一模块；b) 合为 `src-tauri/src/plan_manifest.rs` | **b**：三者共享"目录/文件校验＋限额显式传入＋事实采集"骨架，同模块内分三入口即可；与 `plan_kinds.rs`（文本/编码族）、`plan_csv.rs`（CSV 家族）、`plan_ops.rs`（处理族）并列 |
| C08 规则输入形态 | a) 结构化 JSON 规则对象；b) 沿用 CLI 的 `<子目录>\|<type>:<params>` 行文本 | **b**：规则语法是既有 CLI 契约（设计 01 v1.32 的判定器链），壳层再造一套 JSON 形状会形成两套规则 DSL；壳层复制 `parse_archive_condition` 保持四类条件（`ext`/`mtime`/`size`/`name`）语义一致 |
| C07 清单解析 | a) 只支持逗号；b) 与 CLI 同源 `csv_dedup_inspect`（编码感知＋分隔符嗅探，采样窗口＝文件大小） | **b**：清单可能来自 F10 导出（UTF-8 BOM）或用户手建 GB 编码，编码感知是方案 §5.8 的既有要求 |
| C10 桌面执行路由 | a) 让 ZIP 计划落到通用执行器；b) `run_apply` 增加 `kind == C10_KIND` 分支走 `apply_archive_plan`＋`ZipArchiveService` | **b**：专用执行器负责逐文件/压缩产物的 Journal 记录与撤销语义（ADR-0029/0030），通用执行器无 `Archive` 动作臂，落到它会静默失去撤销粒度 |
| C10 解压限额 | a) 壳层给默认值；b) `maxTotalBytes`/`maxRatio` 必填、缺失即 E1001 | **b**：AGENTS"数值阈值只引用基线既定值"，方案 §5.7 未给默认数值，壳层不得自行补值 |

## 3. 选择理由

- **判定仍留 kernel**：路径穿越拦截、GBK 名回退、E3007 限额、首中生效规则链、C19 同名冲突、E1003/E2001/E2009 全部由 `plan_c07`/`plan_c08`/`plan_c10`/`plan_c10_compress` 决定；壳层只做参数装配与事实采集（不变量 1/2/3）。
- **C10 分支的可复核性**：新增壳层测试 `zip_compress_plan_executes_through_the_desktop_queue_and_undoes`，压缩两个源文件（含子目录）→ 断言产物存在且含 2 条文件条目 → undo 断言产物已离开原路径（reverse=Quarantine）。这条测试直接证明"桌面走的是专用执行器且撤销语义生效"，而不是仅证明路由可达。
- **视图收敛**：web 注册表加 c07/c08/c10 三页后，导航达 **23 功能视图**；连同 C09 与内嵌的 C05/C06 预览命令，阶段 0 的 25 个功能全部具备桌面 UI 路径（C18 为横切干跑，由 plan 命令本身承担）。

## 4. 后果与退路

- **后果**：`parse_archive_condition` 在 CLI 与壳层各有一份（同一语法两处实现）；漂移风险由 C08 的 kernel 单测与 apply_flow 集成测试兜底。若后续规则语法扩展（全条件求值、内容关键字匹配，ADR-0037 已登记待补），应把该解析下沉到 kernel 或 platform，由两端共用。
- **退路**：`run_apply` 的 c10 分支是纯路由追加，若专用执行器需要并入通用执行器（设计 01 演进），删除该分支即可，计划结构与前端不变。
