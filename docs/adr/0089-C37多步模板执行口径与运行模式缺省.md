# 0089. C37 Phase B 多步模板的执行口径与运行模式缺省

- **状态**：已取代（Superseded by [0090](./0090-模板来源字段与运行模式缺省.md)）
- **日期**：2026-11-09
- **决策者**：AI 工程实现（产品缺口登记 [OQ-45](../OPEN-QUESTIONS.md)）
- **关联**：方案 §15.2.3／§15.2.4；设计 03 §5.2；ADR-0077、ADR-0080、ADR-0081

---

## 1. 问题背景

方案 §15.2.3 要求多步模板「一键执行：**本机新建模板默认一键**；导入模板默认逐步骤；首步始终先预览确认。后续每步先 plan，风险闸门通过后自动 apply」。落地时发现两个约束：

1. **没有可靠的「本机新建 vs 导入」标记**。`RecipeDocument.sourceFormat` 的语义是「跨形态导入标记（§13.8）」（`desktop`／`web`），而 `saveRecipe` 与 `importRecipe` 两条路都没有设置它——用它当来源判据是语义误用，且对现网模板一律为空。
2. **无法预生成所有步骤计划**。第 2 步的输入（`source: previous`＝上一步实际产物）在第 1 步执行前不存在，所以「一键」只能在首步确认之后逐步推进，不能一次性把整串计划都生成好。

不做决定的代价：多步模板要么永远不能一键（功能缺口），要么靠猜「这份模板是新建的」来默认一键（把导入的不可信模板也自动跑起来，违反 §7.4 信任模式）。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 用 `sourceFormat` 判别来源 | **否决**：语义是跨形态而非来源，且两条保存路径都未设置，现网模板全为空 |
| B | 新增 schema 字段（如 `origin: local/import`）并升版迁移 | **否决（本切片）**：schema 升版＋迁移＋基线修订属产品/契约变更，走方案 §11.6；登记 OQ-45 提请人工裁决 |
| C | 运行模式存 UiState `templatePrefs`（设计 03 §5.2 既定），**缺省逐步骤**，一键由用户显式开启；含高风险步骤时一键不可用 | **选用** |

## 3. 选择理由

设计 03 §5.2 已把「运行模式（一键/逐步骤）」定为**本机 UI 偏好**、存 UiState、不写进 `RecipeDocument`／导出；因此「本机新建默认一键」在实现上只能靠一个来源标记撑起来，而它不存在。

- **缺省逐步骤**是 §7.4 信任模式的直接推论（默认任何批量写必须先预览，仅低风险且可全量回滚可跳过），也与「导入模板默认逐步骤」同向；对**本机新建**模板则比基线保守——这是明知不完美的取舍，见 OQ-45。
- 候选 B 能精确实现基线措辞，但代价是 schema 升版（v7）、迁移样本、基线 §15.2.4 修订与已落盘模板的默认值回填；在人工裁定前不擅自改契约。
- 一键仍然**可用**：用户逐模板显式开启后持久化在 `templatePrefs`，含高风险步骤时由 `describeRecipe.oneClickAllowed` 禁用。

## 4. 后果与退路

- **后果**：
  - 本机新建的多步模板也默认逐步骤，比基线多一次点击；
  - `templatePrefs` 可重置，重置后一切回到逐步骤（安全方向，不产生误自动执行）；
  - 一键自动推进要求每一步的输入/输出槽位都能自动取到；取不到（`source: original` 的后续步、上一步无产物、需要输出目录）即停下降级逐步骤——不猜输出位置（§15.2.4「输出目录应用时重选」）；
  - 任务终态非 `completed`（含 `partial-failed`／`failed`／`cancelled`／`interrupted`）即停止后续步骤，不自动跨步回滚；已完成步骤各自 `undoPlan(planId)`。
- **退路**：若人工裁定新增「来源」字段，改动面是——保存/导入时写入标记、前端缺省改为「显式偏好 > 来源缺省 > 逐步骤」、基线 §15.2.3 措辞与迁移样本同步。UiState 偏好仍然生效，不需要改架构。
