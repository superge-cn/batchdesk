# 0024 F12 批量重命名：基础规则、冲突扫描与两阶段计划

- 状态：已采纳
- 日期：2026-10-31
- 关联：[设计 01 §3.1/§5/§8](../design/01-内核接口与IPC契约.md)、[方案 v1.19 §5.13](../baseline/产品方案-v1.19.md)、[TC v0.3 F12/R02/R03/R04/R06](../testing/测试用例库-TC-v0.3.md)

## 1. 背景

F12「批量重命名文件或文件夹」要求规则化改名、两阶段执行解决循环与冲突
（方案 §5.13）。本切片聚焦基础规则集（前后缀、字面查找替换）与冲突边界；
正则捕获组归 F13，序号/模板等进阶规则后续补齐。工程上必须解决：

1. 目标名非法字符/保留名/结尾点空格要在预览期拦截；
2. 批内重名、现存重名、仅大小写不同要分别暴露；
3. 循环（A→B、B→A）和仅大小写改名必须走临时名；
4. 无环链式改名应按拓扑序直接执行；
5. 撤销只依赖 Journal 的新旧路径映射。

## 2. 决策

1. **基础规则**：`prefix`、`suffix`、`find`（字面替换）＋`scope=full|stem|ext`；
   `stem` 保留扩展名，`ext` 只改扩展名；空 `find` 拒绝。规则使名称不变时只
   发 `no-change` 告警、不产生条目。序号/正则/模板规则不在本切片。
2. **输入与预览**：CLI `f12 --dir <dir>` 取目录直接子项（文件与文件夹，跳过
   符号链接）；计划期逐项计算新名，`invalid-target-names` 以 E1002 blocked
   条目集中呈现（非法字符/保留名/结尾点空格/空名/路径分隔符）。
3. **冲突**：目标名与现存项冲突按 `existing-target`、批内重复按
   `within-batch`、仅大小写不同按 `case-only` 标记并默认 skip；本批次将移走
   的源路径从现存占用中剔除后再扫描。源/目标命中保护目录按 E2009。
4. **两阶段计划**：构建 source→target 依赖图；无环时按拓扑序生成直接
   `rename` 条目（先腾空目标）；有环或大小写折叠后源/目标相同（仅大小写）
   时，为全部有效条目生成临时名阶段（`.batchdesk-rename-{planId}-…`）＋目标
   阶段。临时名只用于计划/执行，不进入最终产物。
5. **执行与撤销**：复用 `PlanAction::Rename`，允许文件/目录；每条 Journal
   forward=`Rename{from,to}`、reverse 为逆改名；两阶段条目按计划顺序执行，
   撤销按 Journal 逆序恢复。失败保留已完成项并由报告说明，可整批撤销。
6. **CLI**：`f12 --dir <dir> (--prefix|--suffix|--find)`，`--replace`、`--scope`、
   `--plan-id`、`--protected-dir`、`--json`；计划即 dry-run，apply 才落盘。

## 3. 后果

- 设计 01 §3.1 增加 `plan_f12`；§8 明确两阶段 rename 的 Journal 反向语义；
  设计 13 升 v0.7，把 `f12` 纳入实验命令清单。暂无新 FsAdapter 能力。
- 两阶段批次会临时产生额外条目/改名次数；换来循环与大小写改名的可撤销性。
- 规则集仍是基础子集：正则（F13）、序号、模板、R01/E03/E01 的完整验收、
  UI 预览与冲突交互后续补齐。
