# 0020 F08 CSV 抽取指定数量行：前/后 N 窗口与 1:1 产物

- 状态：已采纳
- 日期：2026-10-30
- 关联：[设计 01 §3.1/§5](../design/01-内核接口与IPC契约.md)、[方案 v1.19 §5.15](../baseline/产品方案-v1.19.md)、[TC v0.3 F08/T04](../testing/测试用例库-TC-v0.3.md)

## 1. 背景

F08「CSV 抽取指定数量行」取前 N 行即时截断、取后 N 行用环形缓冲（方案 §5.15），
与 F07 同属 1:1 变换：每个输入产出一个新文件，源文件不变。工程上必须定义：

1. 前/后窗口的表示、N 的边界（0、超过总行数）；
2. 表头是否计数与是否保留；
3. 行内容（含列数漂移）是否原样输出；
4. 编码、撤销与执行期复核。

## 2. 决策

1. **新增 `csv-rows` 动作**，不复用 `csv-extract`（列选择语义不同）。每个输入一条
   entry（1:1），`PlanEntry` 追加可选载荷
   `csvRows{encoding,size,delimiter,hasHeader,columns,columnCount,dataRows,
   window,count,targetEncoding,invalid,dirtyRows}`；`window ∈ first|last`。
2. **N 按数据行计数，不含表头**：有表头时输出始终保留表头（规范化后的表头字段）；
   无表头时不写表头。N=0 合法：有表头时产物仅表头，无表头时产物为空。
3. **N 超过数据行数不报错**：输出全部数据行，并给出 `count-exceeds-rows`（Safe）
   告警；`dataRows` 记录计划期行数供预览展示。
4. **后 N 使用有界选择**：执行期以 `VecDeque` 环形缓冲保留末 N 条已解析记录，
   选择内存 O(N)；但本切片仍先整文件读入解码，流式"读全文件"路径为缺口。
5. **行内容原样输出**：数据行字段数与表头不一致时按原字段写出并计数上报
   （`csv-row-width-mismatch`），不补空/不截断（T04）。
6. **编码与分隔符**：`targetEncoding` 必填；输入先解码到 UTF-8 解析，输出再编码，
   BOM 只写一次；输出分隔符沿用输入分隔符。输出行尾统一 `\n`。
7. **apply 复核与撤销**：逐输入复核普通文件、占位、保护目录与源大小
   （`expected.algorithm="size"`，变化 skipped + E2010）；执行期重新规范化表头并与
   计划载荷比较，变化报 E2010（条目 failed，不写半成品）。Journal
   forward=`WriteAtomic{dataRef:None}`／reverse=`Quarantine`；覆盖既有目标时先
   `backup_to_quarantine`、reverse=`WriteAtomic{dataRef}`。
8. **CLI 输出模式**：`--first N` 与 `--last N` 二选一（均允许 0）；`--output` 仅允许
   单输入，`--output-dir` 可多输入并沿用源文件名；批量目标重名 E1002，已存在目标按
   `existing-target` + 默认 skip 处理。

## 3. 后果

- 设计 01 §5 增加 `csv-rows` 动作与 `csvRows` 载荷；契约版本升至 v1.14。
- 后 N 在预览阶段看不到"尾部内容"的时间复杂度代价；大文件仍会阻塞读取，需后续
  流式实现（与 F05/F06/F07 同一批缺口）。
- 输出会规范化引号与行尾，不保留源文件的 CRLF/原始引号风格；需要逐字节保真时
  应选择其他能力或等待后续版本。
