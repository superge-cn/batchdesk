# 0027 C02 换行转换：流式重写、CSV 引号保护与二进制魔数排除

- 状态：已采纳
- 日期：2026-10-31
- 关联：[设计 01 §3.1/§5.1](../design/01-内核接口与IPC契约.md)、[设计 04 §4.1](../design/04-文件系统适配层契约.md)、[设计 13 §2.1](../design/13-CLI契约.md)、[方案 v1.19 §5.15](../baseline/产品方案-v1.19.md)、[T v1.12 C02/K06](../baseline/功能测试方案与验收标准-T-v1.12.md)

## 1. 背景

C02 要求"流式识别 CRLF/LF/CR 并统一替换，兼顾跨块边界"（方案 §5.15），TC 还要求 CSV 引号内换行不误改、K06 二进制文件不得进入文本管道。现有 `edit-content` 执行器用整段 `ContentEditor`（字节进、字节出），会把大文件整体读入内存；F10 的 `write_atomic_with` 只有写回调、没有源读取。工程上必须决定：如何在不整读文件的前提下做有状态换行转换，以及 CSV 结构与二进制排除放在哪一层。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 新增 `ContentRewriter` 端口＋`FsAdapter::rewrite_atomic_with`，由适配层提供源/目标流，kernel 做字节状态机 | **选用** |
| B | 沿用整段 `ContentEditor`，把文件全读入内存再转换 | 否决：与 C02 "流式改写不整读"的大文件要求冲突，且 C03 还要复用同一流式通道 |
| C | 在平台层实现换行转换，kernel 只做计划 | 否决：CSV 引号状态、跨块边界与计数属于领域规则，应留在纯函数层并可直接单测 |

## 3. 选择理由

- `rewrite_atomic_with` 与既有 `write_atomic_with` 对称：适配层负责长路径、临时文件、flush、原子改名与失败清理；kernel 只读写流，不碰磁盘（不变量 1/8）。源文件在改名成功前保持不变，调用方已先 `backup_to_quarantine` 并写 Journal。
- 字节级状态机只处理 `\r`/`\n` 与 CSV 引号；UTF-8/GB18030/Big5/Shift-JIS/Latin1 的尾字节范围都不包含 `0x0A/0x0D/0x22`，因此不整段解码即可安全转换。UTF-16 的换行是双字节，超出本切片范围：计划期 blocked E3001 并提示先走 C01 转 UTF-8。
- CSV 只转换引号外的记录终止符；引号内 `\r`/`\n`/`\r\n` 原样保留，跨块与 `""` 转义由 `pending_cr`/`pending_quote` 状态覆盖。文本结构不做引号判断，转换所有换行。
- 二进制排除集中到 `kernel::binary` 魔数嗅探（PNG/JPEG/GIF/PDF/ZIP/GZIP/7z/RAR/ELF/PE/BMP/TIFF/SQLite/OLE），计划期 blocked E3001；K06 语料因此由 partial 转 asserted，C03 可直接复用。
- 目标换行必须显式给出（`--to crlf|lf|cr`），无产品默认；结构默认 `auto`（`.csv`/`.tsv` 为 CSV，其余文本），可显式覆盖。计划 `params` 记录 target/structure/platformPrior/source 快照，apply 侧据此重建流式重写器。

## 4. 后果与退路

- 设计 01 §3.1 增加 `plan_c02`；§5.1 记录 C02 的 edit-content/params 语义；设计 04 §4.1 增加 `rewrite_atomic_with`；设计 13 §2.1 把 `c02` 纳入实验命令。
- 新增 `ContentRewriter` 端口后，C01/F04 仍走原 `ContentEditor` 整段路径；C02 优先流式重写。后续 C03 可复用 `ContentRewriter` 做块读＋模式重叠窗口。
- 已知缺口：流式重写过程中的取消只在条目边界生效（与 F10 目录遍历一致）；UTF-16 源 blocked（需先 C01）；文件 plan→apply 变化仍只按 `expected.size` 复核，未对改写前内容做哈希再校验。
- 退路：若后续要求 UTF-16 换行转换，新增解码→换行→重编码的流式重写器即可，`ContentRewriter`/`FsAdapter` 接口不变；若要求无临时文件的原地改写，需另评估 Windows 替换语义，不影响计划层。
