# 0032 C12 CSV 过滤：判定器编译、数值类型解析与 keep/drop 语义

- 状态：已采纳
- 日期：2026-10-31
- 关联：[设计 01 §3.1/§5.1](../design/01-内核接口与IPC契约.md)、[设计 13 §2.1](../design/13-CLI契约.md)、[方案 v1.19 §5.15](../baseline/产品方案-v1.19.md)、[ADR-0031](./0031-C11-CSV去重内存判重与键序列化.md)、[ADR-0028](./0028-C03-查找替换整段变换与CSV单元格保护.md)

## 1. 背景

C12 要求"按包含、不包含、数值比较筛选行"（方案 v1.19 §2 功能表），§5.15 一句话思路为"条件表达式解析为判定器，流式逐行求值输出"，主要风险是"数值比较的类型解析"。工程上必须决定：条件算子集合与形状、非数值单元格的判定归宿、筛选方向（保留还是剔除）、以及与 C11 已建管道的复用边界。若不固定"非数值单元格"的语义，`ne`（数值不等）会把无法解析的行当作"不等→匹配"，造成静默误剔除/误保留。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 算子固定为基线点名的 contains/not-contains＋eq/ne/gt/ge/lt/le；单条件每计划；非数值单元格对一切数值算子不满足判定并计数告警；`--mode keep\|drop` 显式选向 | **选用** |
| B | 自建表达式文法（与/或/括号/多条件组合） | 否决：基线只点名三类算子，文法形状属产品行为（§11.6 范畴），本切片不代行；AND/OR 组合登记为缺口 |
| C | 非数值单元格按"不等/不包含"处理或静默跳过 | 否决：正是基线点名的类型解析风险——不可解析的单元格不应悄悄落入任一分支，必须可见（计数＋`non-numeric-cells` 告警）且保守（不满足判定，含 `ne`） |

## 3. 选择理由

- **算子面收敛在基线**：功能表"包含、不包含、数值比较"直译为 `contains`/`not-contains` 与六个数值比较算子；数值比较用 `f64` 解析（`1e3`/前导 `+` 按 Rust 语义），计划期校验比较值必须可解析（E1002），执行期比较值不再二次解析失败。
- **非数值单元格保守归宿**：任何数值算子（含 `ne`）对不可解析单元格一律"不满足判定"，计数进 `nonNumericCells` 并发 `non-numeric-cells` Caution 警告；缺失字段（脏行短行）按空单元格走同一路径。用户在预览期即可看到有多少行会因类型问题被排除。
- **keep/drop 显式化**："筛选行"不隐含方向；`mode` 写入计划载荷与 params 快照，apply 不猜方向。matchedRows/keptRows 双计数让预览直接回答"会删多少、会剩多少"。
- **复用 C11 管道**：扫描复用 platform `csv_dedup_inspect`（编码检测/分隔符嗅探/表头/脏行＋完整记录）；解析写出复用 `parse_records`/`write_record`；保护目录/编码未确认/重复输出目标/空文件阻断与 E2010 执行期表头复核、`write_atomic`、覆盖备份/新建 Quarantine 撤销全部同 C11（设计 01 §8）。表头行不参与判定、始终保留。
- **contains 大小写敏感**：按字节精确子串匹配，不引入大小写折叠——C11 判重、F06 表头规范化均以精确/规范化为界，大小写折叠选项留待产品确认。

## 4. 后果与退路

- 设计 01 §3.1 增加 `csv-filter` 动作与 `plan_c12`、§3 增加 `csvFilter` 载荷；设计 13 §2.1 把 `c12` 纳入实验命令。
- 已知缺口（必须登记、不得表述为产品完成）：整文件读入内存（基线"流式逐行求值"未做，与 F06/F07/F08/C11 同缺口）；单条件每计划（AND/OR/括号组合未做）；contains 大小写折叠选项未做；输出记录终止符规范化为 LF；TC PRE/EXE/RBK 人工用例与 UI 预览未做。
- 退路：多条件组合时 `PlanCsvFilter.condition` 扩展为 `conditions` 数组（追加式字段），`filter_records` 的单条件判定器保持纯函数签名不变；流式化时以行流替换整文件 `parse_records`，判定器与计划载荷不受影响。
