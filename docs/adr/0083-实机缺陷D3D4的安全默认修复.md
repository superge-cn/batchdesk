# 0083. 实机缺陷 D3/D4 的安全默认修复：复制先落同目录临时文件、磁盘预检按落盘卷分组

- **状态**：已采纳（代码、测试与文档同步落地；D1/D2/D5 仍开放，见 §4）
- **日期**：2026-11-08
- **决策者**：开发代理（工程实现决策；不改产品行为、错误码码位、数值阈值与线协议）
- **关联**：方案 §4.5（安全默认：删除进隔离目录）、§4.7（文件系统适配层收口）、§4.9（UNC 断线与降级）、§9.1（磁盘安全余量）；[设计 04](../design/04-文件系统适配层契约.md) v1.14、[设计 12](../design/12-前端与桌面壳架构.md) v0.25；`crates/platform/src/fs.rs`（`copy_file_atomic`／`copy_via_temp`／`move_file`／`backup_to_quarantine`）、`crates/kernel/src/preflight.rs`（`DiskSpaceCheck`／`PreflightInput.disks`）、`src-tauri/src/lib.rs`（`preflight_gate`／`add_disk_requirement`）；实机证据 `E:/batchdesk-shijiri/b1/r05/`、`E:/batchdesk-shijiri/b1/e04/`（仓库外留档，索引见 `fixtures/corpus/manual-results.md`）

## 1. 问题（两条实机缺陷，同一批安全默认）

### D3：`FsAdapter::copy` 非原子，断线留下 0 字节目标

2026-11-08 的 R05 实机（C07 复制 3000 条到 SMB 共享，t≈2.9s 停止 LanmanServer）暴露的不是"失败"，而是**静默的数据损伤**：

1. `CliFsAdapter::copy` 直接调用 `std::fs::copy`。在 Unix 上该调用会先创建目标文件再读源；断线时源读取失败，目标路径上留下 **0 字节文件**。
2. 下一轮重放时，`resolve_target` 按 `ConflictPolicy::Skip` 判定"目标已存在"，该条被跳过。
3. 任务终态 `completed`，全量 SHA256 对账 3000 条里唯一不符的就是这个 0 字节文件。

同一根因还波及两条相邻路径：覆盖复制在失败时会先破坏既有目标；跨卷移动走复制时同样可能留下半成品。`backup_to_quarantine` 的 `.bak` 也可能只剩半截。

### D4：S01 磁盘预检只接 c09，其它写入计划零磁盘判定

2026-11-08 的 E04 实机（F: 填至剩 1 MiB，F11 建档 40 条）显示：前 31 条成功、后 9 条失败（E2004／os 112，父目录失败的子目录级联 E2001），**S01 预检完全没有阻断**，产生了 31 条副作用。落点在 `src-tauri/src/lib.rs`：

- `preflight_gate` 里磁盘需求采集被 `if plan.kind == "c09"` 包住；
- 其余写入型计划（f11 建档、f12 改名后的目标卷、C07 跨卷移动/复制、F01–F10 的产物等）根本没有 `disk-space` 判定项；
- kernel 的 `PreflightInput` 只有一个 `Option<DiskSpaceCheck>`，形状上就只够 c09 一个隔离卷。

## 2. 决策

### D3：复制先写同目录临时文件，校验字节数后再改名

1. `CliFsAdapter` 新增 `copy_file_atomic(from, to)`：
   - 临时文件落在**目标同目录**（`.<prefix>-{pid}-{id}`），保证后续 `rename` 同卷；
   - 注入点 `copy_via_temp(source, temp, target, copy)` 先 `metadata(source).len()`，再执行复制，**写入字节数不等于源大小时报 E2008 并删除临时文件**；
   - 只有完整写入后才 `fs::rename(temp, target)`；改名失败同样删除临时文件，目标保持原样。
2. `copy_file_atomic` 成为三条路径的唯一实现：
   - `copy`（含覆盖与新建）；
   - 跨卷 `move_file`；
   - `backup_to_quarantine` 的 `.bak`。
3. **不先删除既有目标**：`fs::rename` 在 Windows 与 Unix 上都可替换既有文件（本机 Windows 实测 + CI 双平台回归）。先删会把"改名失败"升级成"目标丢失"，与 D3 的修复目标相反。
4. 短写与断线都只可能留下临时文件（且清理路径会删掉它），最终目标路径要么是旧的完整内容，要么是新的完整内容。

### D4：磁盘判定按"实际落盘的卷"分组，内核逐卷出判定项

1. `DiskSpaceCheck` 增加 `path: Option<String>`（判定项可点名卷/路径）；`PreflightInput.disk: Option<DiskSpaceCheck>` 改为 `disks: Vec<DiskSpaceCheck>`。
2. `run_preflight` 对每个 `DiskSpaceCheck` 各生成一条 `disk-space` 判定，任一不足即 `task_blocked`（行为与原单卷版一致，只是从一条变多条）。
3. 壳层 `preflight_gate` 不再看 `plan.kind`，改为遍历计划条目、按动作推导空间需求，并用 `add_disk_requirement` 按 `same_volume` 合并到"目标卷"分组：
   - `Delete`：同卷进隔离目录不额外占空间；跨卷按源大小计入隔离卷；
   - `Move`：同卷不改名占空间；跨卷按源大小计入目标卷；
   - `Transcode`／`EditContent`：同卷原地重写按临时产物峰值计入（`temp_peak`），跨卷按源大小计入目标卷；
   - `CreateDir`：只需余量下限，`required = 0`；
   - 其余 `Copy` 等写臂：按源大小计入目标卷；
   - `Rename`：同卷改名，不产生空间需求。
4. **不新增任何数值阈值**：余量下限与比例仍由调用方按方案 §9.1 传入（`margin_floor_bytes`／`margin_ratio`），本次只改"判定几次、判在哪个卷"。

## 3. 为什么不选另外两条路

- **D3 只加重试/恢复后校验**：重试解决的是"下一次"，解决不了本次已经把 0 字节文件留在目标路径；而且重放会因"目标已存在"跳过。必须先保证失败不产生可见半成品。
- **D3 把整文件读进内存再写出**：与方案 §4.8／§9.1 的内存恒定要求冲突，大文件复制会 O(文件)。临时文件方案是流式且内存恒定。
- **D4 继续按 `plan.kind` 白名单逐个接**：每新增一个功能就要记得加一次，漏接是默认结果（D4 本身就是这么来的）。按动作/卷推导把"漏接"变成编译期必须处理的分支。
- **D4 在 kernel 里判断卷**：kernel 不得做平台 I/O（不变量 1）；`same_volume` 属适配层能力，卷分组只能在壳层/适配层做，kernel 只消费注入的 `Vec<DiskSpaceCheck>`。

## 4. 已接受的坑、边界与仍开放的缺陷

- **D3 的崩溃窗口**：临时文件写完后、改名前的进程崩溃会留下一个 `.batchdesk-copy-*` 临时文件（目标仍是旧的完整内容）。临时文件是可清理的半成品，不会伪装成用户文件；启动清理不在本次范围。
- **D3 的改名失败**：`fs::rename` 仍可能因目标被独占锁定/只读属性而失败。此时目标保持原样、临时文件被删除，错误按 E2008 响亮上报——不会静默成功。
- **D3 的跨卷移动**：复制成功但删源失败时，两侧都保留完整内容（可重试），代码会尝试删掉刚复制出的目标并报错；这不是"数据损伤"，但会留下一次可重试的失败。
- **D3 不覆盖 `copy_range_atomic`／`write_atomic_with` 的既有 Windows 预删**：那两条通道已有独立语义与测试，本次按最小改动半径不动；它们同属"临时文件+改名"族，若后续发现同类问题按新语料另批处理。
- **D4 仍是预检期判定**：预检与实际执行之间磁盘余量可能变化，执行期 E2004 仍是最后防线；本次不承诺"预检通过就一定不会中途满盘"。
- **D4 的余量口径沿用既有实现**：`disk_margin_bytes` 仍按 `required_bytes × ratio` 计算比例余量，`temp_peak` 单独相加（kernel 既有测试不变）。是否需要把 `temp_peak` 纳入比例基数属数值口径，留待人工裁决，不在本 ADR 自定。
- **D1／D2／D5 仍开放**：断线有限重试/退避/暂停（D1）、Windows 网络错误码映射（D2）、c09 隔离移动与 Journal 追加的原子性（D5）均不在本次范围；D3 只保证"复制失败不产生可见半成品"，不代替重试策略。
- **故障注入只证明失败路径的形状**：`copy_via_temp` 的测试用可控闭包模拟短写与 `ConnectionReset`，不模拟真实 SMB 断线；真实断线回归仍以 R05 实机复跑为准（人工）。
