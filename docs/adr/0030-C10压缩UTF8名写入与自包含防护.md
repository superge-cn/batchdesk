# 0030 C10 压缩：UTF-8 名写入、内存组包与自包含防护

- 状态：已采纳
- 日期：2026-10-31
- 关联：[设计 01 §3.1/§5.1](../design/01-内核接口与IPC契约.md)、[设计 13 §2.1](../design/13-CLI契约.md)、[方案 v1.19 §5.11](../baseline/产品方案-v1.19.md)、[ADR-0029](./0029-C10解压安全边界与GBK名回退.md)

## 1. 背景

C10 解压切片（ADR-0029）已覆盖 Z01/Z02 与安全边界；压缩仍缺 ZIP 写入、目录结构、自包含防护与 Journal 撤销。`zip 9.1.3` 的 `ZipWriter` 要求 `Write + Seek`，而 `FsAdapter::write_atomic_with` 只提供 `&mut dyn Write`；同时方案的"兼容旧系统 GBK 名"选项需要写原始名，但该库公开 API 只接受 UTF-8 `ToString` 名（原始名字段非公开）。本切片必须在不破坏既有解压链的前提下补齐压缩，并明确能力边界。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | `ZipWriter` 写入内存 `Cursor<Vec<u8>>`，完成后 `FsAdapter::write_atomic` 落盘；UTF-8 名；目录递归；自包含/已存在/保护目录计划期处理 | **选用** |
| B | 给 FsAdapter 增加 `rewrite_atomic_with` 的 Seek 版本或平台临时文件流式写 | 备选：可降低内存峰值，但需要新增适配器能力与 Windows 替换语义测试，本切片先用 A 保证行为正确 |
| C | 通过非公开字段或 fork zip 库写 GBK 原始名 | 否决：依赖内部字段/fork 维护成本高；方案要求库不满足时优先换库，但当前没有同时满足读写与原始名的成熟替代；GBK 创建选项登记为后续缺口 |

## 3. 选择理由

- 内存组包让压缩与现有 `write_atomic`（临时文件＋原子改名）和 Journal 语义天然一致：新产物 reverse=`Quarantine`，撤销复用统一 undo；不需要为压缩引入第二套落盘路径。代价是内存 O(输出 ZIP)，已登记为缺口。
- 目录递归保留相对结构（根目录名 + 子路径），空目录也写目录条目；同名源根/同名条目直接 E1002，避免静默覆盖。符号链接跳过（不跟随），后续可加报告。
- 自包含防护在 kernel 计划期完成：输出等于任一源、或位于源目录内 → blocked E1002；目标命中保护目录 → E2009；目标已存在 → skip（默认不覆盖）。执行期再次检查目标存在与保护目录，保持 plan→apply 一致。
- 文件名默认 UTF-8（`start_file` 对非 ASCII 名自动置 UTF-8 标志），与解压的 bit 11 判定闭环；GBK 名写入选项受库公开 API 限制暂缓，不静默伪造。

## 4. 后果与退路

- 设计 01 §3.1 增加 `plan_c10_compress`；§5.1 明确 C10 压缩为每输出一条 `archive` summary entry（N:1）＋执行期一次 `write_atomic`；设计 13 §2.1 扩展 `c10 --compress`。
- 已知缺口：内存 O(输出)、GBK 名写入/旧系统兼容选项、密码/加密输出、时间戳/权限保留、zip64 大文件策略、逐文件报告/重试、符号链接报告、Windows 实机与 TC 人工/UI。
- 退路：若内存峰值不可接受，新增平台 `write_zip_atomic_with`（临时文件 + Seek）替换 `compress` 的 `Vec<u8>` 返回；若获得可写原始名的库，替换 `ArchiveService::compress` 实现并保留计划/安全校验。
