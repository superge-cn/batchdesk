## 1. 问题背景

ADR-0077 把 `loadRecipe {recipeId, pathParams}` 的命令面落地后，防漂移断言实测出「快照形状≠请求形状」：快照按 ADR-0072 存的是**计划自带那份**（`plan.params`），而路由结构体要的是**请求形状**——c01 缺必填 `sampleWindow`、c02/c03 缺 `sampleBytes`、c03 的计划键叫 `replace` 而路由要 `replacement`。OQ-41 三选一（改快照口径／加映射表／宣布部分不支持），产品所有者裁②：**保持快照＝计划形状，逐功能补映射表**；附带裁决：采样窗口/采样字节**算参数、进模板**（schema 升 v5，不进快照）。

## 2. 落地前的一次全量清点（改变了问题的形状）

凭 OQ-41 登记的三类差异直接动手会漏掉大半。动手前把 24 个功能逐个核了一遍（内核各 `plan_*` 写进 `plan.params` 的键 ↔ 壳层路由结构体的字段），结论：

1. **机械映射可套用的有 17 个**。除 OQ-41 登记的三类外还有：`platformPrior→prior`（c01/c02/c03）、`targetEncoding→target`（f04/f05-family/f08/f09/f10）、f05 的 `rowsPerPart→rows`、c12 的 `mode→filterMode`、f05/c03 计划把「自动」写成 `delimiter:"auto"` 字面量而路由只认具体分隔符、c10 的 `maxRatio` 计划里是格式化字符串而路由要 `f64`。
2. **顺带钉出三处计划参数形状缺陷**（都在内核计划生成器）：
   - **f04/f06 把输出绝对路径存在 `target` 键下**——`strip_paths` 按键名剔除，`target` 不在 `PATH_PARAM_KEYS`，于是保存/导出的模板违反不变量 13 带出本机路径；且别的功能里 `target` 是目标编码，同名不同义正是 OQ-41 陷阱的成因。修法＝计划参数键改名 `target→output`（CLI 的 `generic_plan_encoding` 只跑非流式 edit-content 计划，f04/f06 的 merge 动作不经过它，改名对 CLI 安全；语料不断言这两个键）。
   - **c10 压缩计划不写 `mode`**——套用通道按快照 `mode` 分流路径槽位，缺 `mode` 的压缩模板会被当解压处理。修法＝压缩计划补 `mode:"compress"`（加法键）。
   - **c10 `maxRatio` 计划里是 `format!` 字符串**——路由要 `f64`。修法＝**映射层**确定性转换（`parse_f64`，解析失败报错不猜），不动 `PlanParamValue`（它带 `Eq` 且被 `PlanDocument` 派生链使用，加 `Float(f64)` 级联太大）。
3. **七个功能的变换正文根本不在计划参数里**：f06（来源列语义）、f07（列选择）、c08（归档规则）、f11（清单正文）、c12（过滤条件）、c13（排序键）、c14（拆分/合并规格）——计划只存计数（`ruleCount`/`rowCount`/`fileCount`…），正文在功能页的表单里、从没进过 `plan.params`。映射表补不出正文；套用＝要么路由报错要么**静默输出与模板意图不符的结果**（c11 按键列去重落在空键列会被当整行去重，是同类静默错）。产品所有者裁决②时这三个类还没有名字，这是②路线自身的边界，不是工程能调和的——本轮**如实拒绝**（理由写进映射表，`describeRecipe` 预声明、界面不给按钮），「正文进模板」登记 [OQ-43](../OPEN-QUESTIONS.md) 待单独裁决（它实质是把 OQ-40 被否的②路线按功能收窄重提）。

## 3. 决策

1. **配方 schema v5**：`TemplateStep` 增 `sampling: Option<RecipeSampling>`（`sampleWindow/sampleBlocks/sampleBytes` 三个可选键，值 ≥1，`deny_unknown_fields` 键集封闭）。**快照不动**——ADR-0072 的「参数快照＝计划自带那份」原样保留；采样口径单独成块（方案 v1.20 §15.2.1 收编，R125）。v4→v5 迁移**无字段可补**：旧模板 `sampling=None`，套用时由映射表按缺省补（迁移不猜值，同 v3→v4 的「不猜功能」）。
2. **映射表 `FEATURE_PARAM_MAP`（`src-tauri/src/recipe_apply.rs`）**：每功能五类声明——`renames`（纯改名）、`unset_if`（剔「auto」字面量）、`parse_f64`（字符串数值化）、`sampling`（路由必填但计划不携带的键；`Some(缺省)`＝必填补缺省、`None`＝可选转发）、`refuse`（正文缺失＝静态拒绝原因）。缺省值 4096 取自**界面既有占位**（`FeaturePages` 的 `|| 4096`），方案 §5.2 明写不设数值窗口，缺省不是新阈值。
3. **判定单源 `assess`**：`describeRecipe`（界面要不要给按钮）与 `build_invocation`（真组装请求）共用同一份静态评估——拒绝原因、槽位选择（c10 按快照 `mode` 分流）、守卫只写一遍，不可能出现「describe 说能套、loadRecipe 却报错」的两套口径。
4. **两条按快照内容的守卫**（静态拒绝的补充，都在 `assess`）：c11 快照 `key=="columns"` 拒（空键列会被路由当整行去重＝静默错）；c10 快照带 `compression` 却无 `mode` 拒并提示**重存**（旧版压缩模板；重存即修，因为内核现在随计划写 `mode`——与七类的永久拒绝不同）。
5. **`describeRecipe` 新命令**：`{recipeId} → RecipeApplySpec`（`applicable/reason/feature/kind/required[]/outputs[]`）。新增命令而非扩展 `getRecipe`：不改变既有命令的返回契约。设计 03 §7 与设计 01 §4.4.2 同步入册。
6. **两处副本就门禁化**（ADR-0075/0076 手法）：浏览器 mock 的 `APPLY_SLOTS`/`REFUSED_FEATURES` 与壳层两张表由 `check_docs.py` 新增的**配方套用表核对**逐键盯住（自校锚点：槽位 ≥24、拒绝清单恰 7 项）。
7. **界面**：模板列表逐条取 `describeRecipe`；可套用才渲染「套用」按钮 → 对话框按槽位表渲染输入（单值输入框、多值多行文本）→ `loadRecipe` 出**预览计划**（方案 §15.2.2，不执行）→ 预览面板（统计＋集中警告＋条目 `VirtualList`）→ 「执行此计划」显式走 `applyPlan`。已绑定但拒绝的模板展示原因；未绑定维持既有「未绑定」提示。

## 4. 验证

- 内核：`cargo test -p batchdesk-kernel` **437 项**（+4：v5 往返/省略、v4→v5 迁移、采样零值拒绝＋未知键拒绝）；f04/f06/c10 改键后 24 条语料断言全过（语料不断言这三个参数键）。
- 壳层：`cargo test --manifest-path src-tauri/Cargo.toml --offline` **69 项**（53→69：映射表 8 项新测试＋漂移断言改写；c03 断言由「钉住失败」翻转为「钉住映射后成立」，既有注释里那句"将来裁决后这条要一起改"兑现）。
- web：`tsc --noEmit`、`vite build`、Vitest **120 项**（TemplatesPage 套用三态：可套用出预览/显式执行/拒绝给原因；保存采集采样值且快照不含采样键）、Playwright 模板页 **2 项**（含浏览器夹具走完整套用→预览→执行链）。
- 门禁：`check_docs.py`（含新增配方套用表核对）、`check_locales.py`（661 key×2）、fmt/clippy/deny、`cargo test --workspace`——证据与本 ADR 的台账回填见 DEVELOPMENT-PLAN §6.1 同日行。
- 过程教训（同 ADR-0077 §4 的流程结论）：壳层测试改动后必须**最后一次**全跑——本轮先红 3 项（断言写了快照里不存在的键＋拒绝功能到不了槽位注入），修正后全绿；`cargo test` 的退出码曾被管道掩掉一次（AGENTS 门禁条款的活例）。

## 5. 边界与不做的事

- 七类正文缺失功能的模板**本轮不可套用**（OQ-43）；它们的槽位/采样表项保留，裁决后直接接上。
- CSV 族的 `prior`/`source` 不随计划保存（f06–f14 的计划不记检测先验），套用时按无先验重新检测——映射表只搬快照里存在的值，不替计划补记；要钉死编码请在功能页确认后使用。
- c10 静态表核对只覆盖解压基态；压缩槽位按快照 `mode` 动态分流，由壳层单测覆盖。
