# 0100. 条目内（字节级）进度：双层进度的条目层落地

- **状态**：已采纳
- **日期**：2026-11-13
- **决策者**：开发代理（契约增量；需求引方案 §7.5 与 §9.1）
- **关联**：方案 v1.22 §7.5（双层进度：任务总进度＋**当前条目进度（大文件可见）**）、§9.1（>2 GB 档「进度按字节估算，允许预估进度」）；设计 01 §2.2、§4.3；TC-F04-EXE-05

---

## 1. 问题背景

TC-F04-EXE-05 的缺口里有一条：「大文件流式合并已落地……**合并进度仍只到单条 entry**」。

F04 合并是 **N:1**：整条任务只有一条 entry。内核的进度契约只有条目计数（`done/total`＝已完成条目／总条目），于是合并一个大文件时，界面上的进度条**长时间停在 0/1**——用户看不到任何进展。

方案 §7.5 明确要求「双层进度：任务总进度……＋**当前条目进度（大文件可见）**」，§9.1 进一步要求 >2 GB 档「进度按字节估算，允许"预估进度"而非精确进度」。契约里没有承载这一层的字段，属实现缺口。

## 2. 候选与否决理由

| 议题 | 候选 | 结论 |
|---|---|---|
| 在哪一层加 | a) 复用 `message` 塞字节文本；b) **给 `ProgressEvent` 加 `entry_done`/`entry_total`** | **b**：a 要把结构化数据塞进给人看的字符串，界面再解析回来，且 `message` 已被定义为「条目层明细＝源路径」（设计 01 v1.28） |
| 事件语义怎么区分 | a) 加 `kind` 枚举；b) **用 `entry_total.is_some()` 区分条目内／条目边界** | **b**：不加新枚举，`None`＝边界事件（只更新条目计数、清掉上一段字节进度），`Some`＝条目内事件（只更新字节字段、不动 `done/total`）。字段缺省即向后兼容 |
| 谁上报 | a) 派发循环按字节累计；b) **执行臂在自己读块的地方报** | **b**：只有执行臂知道「处理了多少字节」（F04 逐源读块、F09 区间流式读）；派发循环看不到条目内部 |
| 并发下怎么共享 sink | a) 只让主线程报；b) **`WorkerView` 带 `&dyn ProgressSink`** | **b**：`ProgressSink: Send + Sync`（progress.rs 已有该 bound），`&dyn` 共享即可跨工作线程；与 `cancel` 端口同一处理方式 |
| 进度条怎么算 | a) 用字节进度替换任务百分比；b) **任务百分比仍按条目数，字节进度另起一行显示** | **b**：条目计数是任务级口径（方案 §7.5 的「任务总进度」），字节是条目层；两者不同量纲，混在一个百分比里会让 1 条 entry 的任务永远 0% |

## 3. 决策

1. **契约**：`ProgressEvent` 增 `entry_done: Option<u64>`／`entry_total: Option<u64>`（serde 缺省省略，旧快照／旧事件不受影响）。
2. **上报**：`WorkerView` 增 `task_id` 与 `progress: Option<&dyn ProgressSink>`（从 `ExecContext` 灌入）；执行臂在读块回调里调 `report_entry_progress(view, entry_done, entry_total)`。
3. **F04 合并**：`entry_total`＝各源字节之和（计划期已探明，属方案 §9.1 允许的"预估"口径），每读一块累加 `entry_done` 并上报。
4. **壳层**：`TaskSummary` 增同名字段；`record_progress` 按 `entry_total.is_some()` 分流——条目内事件只更新字节字段，条目边界事件更新条目计数**并清空**字节字段（避免下一条目张冠李戴）。
5. **界面**：进度行在 `phase · done/total` 之后追加 `已处理/总量` 的人类可读字节（IEC 单位：KiB/MiB/GiB）；条目边界事件到达即消失。

## 4. 后果

- **内核**：`progress.rs` 加字段；`generic_apply.rs` 的 `WorkerView` 加 `task_id`／`progress`，新增 `report_entry_progress`，合并臂逐块上报；所有既有 `ProgressEvent` 构造点补 `None`。
- **壳层**：`TaskSummary` 加字段；`record_progress` 分流；测试补字段。
- **前端**：`ProgressEvent`／`TaskSummary` 类型加字段；`listenTaskProgress` 分流；新增 `formatBytes`；进度行渲染字节进度。
- **不变**：任务级 `done/total` 语义不变；旧快照（无该字段）反序列化正常。

## 5. 残余

1. **只有 F04 接了字节进度**：F09（区间流式）与 F01/F02/F03（分片，本就 1:N）未接；F09 若需要可复用同一 helper。
2. **上报频率未节流**：内核按块上报（64 KiB 一块），壳层沿用既有的 `PROGRESS_COALESCE_WINDOW` 合帧，不会淹没通道。
3. **`entry_total` 是预估值**：源在计划→执行之间变化时由既有的 E2010 条目级失败兜底（不静默改口径）。
