# 0037. C08 按规则归档：判定器链与命中统计口径

- **状态**：已采纳（2026-11-01，开发代理按方案 §5.9 条款落工程语义）
- **日期**：2026-11-01
- **决策者**：开发代理（方案 §5.9 条款已定，本 ADR 只落实现口径）
- **关联**：方案 §5.9（C08 详设：判定器链首中生效、高危规则三重防护）、§5.8（移动引擎复用）；设计 01 §5（`move` 动作复用）；设计 04 v1.5（FsAdapter 能力）；硬性不变量 1/2/4

---

## 1. 问题背景

方案 §5.9 定了 C08 的骨架（规则集→判定器链首中生效→复用 5.8 移动引擎→未命中默认留原位），留白：条件的求值输入、命中统计形态、高危规则的工程阈值、"全条件求值"模式与内容关键字匹配的范围。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 条件求值输入 | a) kernel 读盘自取（扩展名/mtime）；b) 壳层采集文件事实（相对路径/大小/修改日期）→ kernel 纯函数求值 | **b**：不变量 1（kernel 不读盘）；事实经 `platform::listing::collect_tree_files` 采集 |
| 日期比较 | a) 解析为时间戳；b) `yyyy-mm-dd` 字符串字典序 | **b**：ISO 日期字典序即时间序，零解析成本；mtime 取 RFC 3339 前 10 字符 |
| 高危规则阈值 | a) 不设；b) §5.9 示意值 50% | **b（>50% 触发 Danger 级 `high-hit-rule` 警告）**：基线有"如 50%"示意，引用而非另立 |
| 命中统计形态 | a) 结构化报表 DTO；b) 警告行（`rule-hits` 每规则命中数＋最多 3 个样例） | **b**：预览信息经既有 PlanWarning 通道零新 DTO；结构化报表随 UI 接入另行评审 |
| "全条件求值"模式 / 内容关键字 | 本切片实现 | **待补**（登记台账）：首中生效已满足 §5.9 缺省语义；内容关键字默认关闭且有性能代价，延后需带采样上限设计 |
| 未命中去向 | a) 仅留原位；b) 留原位＋可配"未分类"目录 | **b**（`--unclassified-dir`，缺省留原位）；未分类 move 条目 reason 明示 `unclassified` |

## 3. 选择理由

- **复用 C07 引擎**：命中与未分类条目全部为 `move` 动作（1:1），执行/撤销/跨盘校验/子目录自动创建全部继承 ADR-0036 的 Move 臂——C08 零新执行机制，回滚语义与 §5.8 完全一致。
- **警告即预览**：§5.9 要求"每条规则命中数与样例条目"＋高危提示，PlanWarning 通道（`rule-hits` Safe / `high-hit-rule` Danger）让 CLI `--json` 与未来 UI 面板直接消费，不需要并行报表结构。
- **事实快照**：计划基于 `collect_tree_files` 快照；计划后消失的文件记 `walk-missing` 警告且不进计划（apply 期 Move 对缺失源按 E2001 失败报告，双保险）。

## 4. 后果与退路

- **后果**：规则求值在 kernel 内存中完成（文件事实已在内存）；目录级归档（把整个子目录当单位）未做——本切片按文件粒度；未命中"留原位"的文件在计划中不可见（只有警告计数）。
- **退路**：新增条件类型只需扩展 `ArchiveCondition` 枚举与 `evaluate` 一处匹配；"全条件求值"模式可在 `PlanC08Input` 追加字段（只增不改）。
