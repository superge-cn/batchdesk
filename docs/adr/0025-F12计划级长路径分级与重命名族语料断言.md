# 0025 F12 计划级长路径分级与重命名族语料断言

- 状态：已采纳
- 日期：2026-10-31
- 关联：[设计 01 §5.1](../design/01-内核接口与IPC契约.md)、[ADR-0024](./0024-F12-批量重命名与两阶段计划.md)、[方案 v1.19 §5.13](../baseline/产品方案-v1.19.md)、[T v1.12 R01–R04/R06](../baseline/功能测试方案与验收标准-T-v1.12.md)、[TC v0.3 F12](../testing/测试用例库-TC-v0.3.md)

## 1. 背景

F12 切片落地时把长路径分级留作缺口（ADR-0024 §3），R01–R04/R06 五条重命名/路径语料因而停在 pending：分级判定函数已在 `kernel::preflight`，但 `plan_f12` 不调用它，预览期既没有 200–259 警告，也没有 ≥260 的跳过与指引；R02–R04 的样本是"源文件＋映射表"，而 `plan_f12` 只接受规则驱动，缺少把样本送进计划的入口。触发条件是要把"重命名族的验证欠账"收口，否则 T 的路径/重命名套件无法给出可复核证据。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 计划层接收壳层探测的 `longPathSupported`，复用 `preflight::path_length_level` 分级；超长且未开启时条目 `resolution=skip`＋`long-path-disabled` 警告 | **选用** |
| B | 计划期不判定，只依赖 S01 预检在 apply 前整任务阻断 | 否决：预检是任务级报告，预览表无法逐条标注"哪一项会跳过"，T R01 要求预览期分级 |
| C | 超长且未开启时用 `entry.blocked` 阻断条目 | 否决：目标名本身合法，阻断语义会让 `stats.blocked` 混入环境原因；`resolution=skip` 已是"计划内跳过"的既有机制，apply 零副作用 |

## 3. 选择理由

- kernel 是纯函数层（不变量 1），不能读注册表；把 `LongPathsEnabled` 探测留在壳层、以 bool 入参，和 S01 `preflight` 的既有分层一致。
- 分级数值只引用方案 §5.13，实现复用 `path_length_level` 与 `PATH_SAFE_MAX_CHARS`/`PATH_WARN_MAX_CHARS`，不另立阈值。
- `resolution=skip` 与 existing/within-batch 冲突的跳过走同一执行路径，apply 不新增分支；`long-path-disabled` 警告携带"开启 LongPathsEnabled 或缩短目标路径"的指引，满足 §5.13 的预览提示要求。
- R02 的判定点是"大小写折叠比较"，`scan_conflicts` 就是 `plan_f12` 使用的计划级冲突引擎；R03/R04 用样本每行作为单条 `plan_f12` 输入，走真实计划入口；R06 用 `try_normalize`＋计划冲突去重验证前缀归口。

## 4. 后果与退路

- 设计 01 §5.1 的"路径超长三级分级"落点改为 `resolution=skip`＋警告（原表述 `entry.blocked` 与 §5.13 的"跳过"语义不一致）；`PlanF12Input` 新增 `longPathSupported`，计划 `params` 记录该快照。
- R04 样本修正：原 `年度报表 .txt` 是词干空格（整名以 `.txt` 结尾，Windows 合法），改为真正的尾空格 `年度报表.txt `；首部空格行按 §5.13 不在拦截清单，断言为不阻断。样本修正让 R04 的两条拦截分支都能由语料驱动。
- 余下 pending：E03（只读目标，需权限事实采集与执行层接线）、Z01/Z02（C10 ZIP 执行器未建）。
- 退路：若后续产品要求超长目标在预览期呈"阻断"而非"跳过"，改回 `blocked` 只需在 `plan_f12` 一处切换，并同步设计 01 §5.1；不影响 apply/Journal。
