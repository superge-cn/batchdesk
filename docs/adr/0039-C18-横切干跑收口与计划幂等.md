# 0039. C18 横切干跑收口：计划幂等契约与横切 harness

- **状态**：已采纳（2026-11-01，开发代理按方案 §3.2/§5.15 条款落工程语义）
- **日期**：2026-11-01
- **决策者**：开发代理（方案条款已定，本 ADR 只落实现口径）
- **关联**：方案 §3.2 C18 行（"批处理先预览影响范围与差异再执行"）、§5.15（"重复预览幂等"）、§7.4（执行前预览）；不变量 1/2；ADR-0010（id 生成）；TC v0.3 §2.2（C18 PRE 05–06＝P5 重复预览幂等与巨输入）

---

## 1. 问题背景

C18 是横切能力："各功能实现统一预览接口，输出影响范围＋逐项差异，不落盘"。本仓库的架构决定（不变量 1/2：kernel 纯函数、plan 绝不落盘）已把"干跑"作为架构性质承担——plan 命令本身就是干跑。C18 收口需要回答：预览的**可复现性**由什么保证、横切验证由谁承载。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 干跑载体 | a) 独立 `--dry-run` 命令族；b) plan 命令即干跑（架构性质）＋横切 harness 验证 | **b**：每个功能的 plan 命令就是干跑接口（零落盘、纯函数）；横切性质用横切测试承载，避免 24 个功能各造一套 dry-run 面板 |
| 幂等保证 | a) 只约束无随机 id；b) 计划内全部 id 可确定性派生 | **b**：`platform::ids::derived_ulid(seed)`——blake3(seed) 映射 Crockford ULID 形态；F01–F03 的 `groupId` 改由 `derived_ulid("{kind}:{planId}:{file_index}")` 派生（F05 group 同理），重复预览输出逐字节一致 |
| 横切验证载体 | a) 各功能自查；b) apply_flow 单测试遍历全部 plan 命令 | **b**：一个测试遍历 9 个 plan 命令（c01/c04/c07/c08/c09/c13/c14/f01/f12）——两遍执行断言 stdout 逐字节一致＋源树快照前后一致（零落盘） |

## 3. 选择理由

- **发现真缺陷**：harness 首跑即抓到 f01/f02/f03/f05 的 `groupId` 每次运行生成新 ULID——重复预览非幂等，正违背 §5.15"重复预览幂等"。确定性派生修复后 harness 全绿。这验证了横切 harness 的价值：单功能切片各自验证时此类跨切片性质必然漏网。
- **`derived_ulid`**：纯函数、无时钟无熵池（与 `new_ulid` 的时序语义分离）；种子带前缀（`kind:planId:fileIndex`）避免跨计划/跨文件碰撞；首字符 `&= 0x7f` 保持 ULID 形态（`is_ulid` 可过）。
- **快照口径**：源树快照＝相对路径＋文件长度的清单（内容哈希属基准工具职能，长度+清单已能捕捉"预览写文件/删文件"类副作用）。

## 4. 后果与退路

- **后果**：新功能切片必须把计划内生成的 id 纳入确定性派生（否则 c18 harness 失败——这是期望的守门行为）；`new_ulid` 保持时序语义（planId 本身每次预览可不同，planId 相同的前提下其余输出必须一致——测试固定 `--plan-id`）。
- **退路**：若某功能确需"每次预览新鲜 id"（未见场景），可在 harness 中为该功能登记豁免并说明理由。
