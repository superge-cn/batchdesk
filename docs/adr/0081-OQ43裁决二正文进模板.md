## 1. 问题背景

ADR-0080 按 OQ-41② 落地映射表时实测出：f06/f07/c08/c12/c13/c14 六个功能的变换正文（来源列开关/列选择/归档规则/过滤条件/排序键/拆分合并规格）从不进 `plan.params`——计划只存计数（`ruleCount`/`fileCount`…），而参数快照＝计划自带那份（ADR-0072），映射表补不出正文，七个功能（登记时含 f11）的模板套用＝要么报错要么静默输出与模板意图不符的结果，故如实拒绝并把「正文进模板」登记 OQ-43。产品所有者裁②：把请求侧正文也存进模板。

## 2. 一处登记纠偏（先于实现）

复核发现 **f11 被误列**：它的「清单正文不随计划保存」不构成套用障碍——`F11ShellParams{list, root}` 两个都是**路径槽位**（清单文件与建档根由调用方在套用时现选），路由重新读取清单文件采集事实，快照里没有正文不影响回放。ADR-0080 §2 把 f11 与其余六个并列为「正文缺失」是分类错误；本轮更正为**可套用**（槽位落地断言恢复），OQ-43 的覆盖面随之从七收窄为**六**。教训同 R-29/R-31 的两次翻案：登记时写的结论也要被下一轮实测复核。

## 3. 决策

1. **配方 schema v6**：`TemplateStep` 增 `content: Option<Map<String, Value>>`（变换正文块）。与 `sampling` 同型——**进模板、不进快照**，快照保持「计划自带那份」（ADR-0072）不动；v5→v6 迁移**无字段可补**（正文从 v6 起才在保存时采集，旧模板留 `None`，需要正文的功能在套用时如实拒绝并提示重存——迁移不猜正文）。
2. **值形态门**：content 值只允许标量或标量数组（嵌套对象在 validate 拒绝）——嵌套对象不是任何路由参数的形状，也会把「模板是声明式数据」（方案 §15.2.4）变成任意 JSON 容器。脚本键同快照一起拒绝；**路径键同快照一起剔除**（`strip_paths` 覆盖 content；顺带补 `basedir` 进 `PATH_PARAM_KEYS`——f06 相对来源列的基准目录是路径，不在名单就会随 v6 正文/快照泄漏，本轮清点时钉出）。
3. **键白名单在壳层映射表**：`FEATURE_PARAM_MAP` 的静态 `refuse` 被 `content`（每键 `Required`/`Optional`）＋`content_any`（「至少一个」组）取代；未知键在注入时拒绝（不静默丢，方案 §15.2.4）；注入**覆盖**快照同名键（正文是保存时刻的请求侧真值）。`drop` 类新增：f06/f07 的计划展示键（`columns` 展示串、`sourceColumn` String|Null）与路由字段类型冲突，先剔再注入。`assess` 单源不变：`describeRecipe` 与 `build_invocation` 用同一份判定。
4. **六功能的键集**（逐字段实测自路由结构体）：f06 `sourceColumn`(必填 bool)/`sourceColumnName`/`sourceColumnRelative`；f07 `columns`/`columnIndexes`（至少一）；c08 `rules`(必填)/`recursive`；c12 `value`(必填)/`column`|`columnIndex`(至少一)/`op`/`filterMode`；c13 `sortColumns`|`sortColumnIndexes`(至少一)/`order`/`externalChunkRows`；c14 拆分规格或合并规格（`splitColumn`＋`splitSeparator` XOR `splitRegex`，或 `mergeColumns`…，至少一组）。**f06 相对来源列拒绝**：`sourceColumnRelative=true` 需要 `baseDir`（路径），模板不存路径 ⇒ 该形态套不了，保存侧提示、套用侧按正文拒绝。c11 按键列去重不在 OQ-43② 清单，维持整行可套用/按键列拒绝（机制已备，后续可循同路扩展）。
5. **保存侧（web）**：`contentFromForm(view, form)` 按功能从表单采集，取值形态与各功能 plan 构造分支一致（同一批 split/Number 规则，不另抄一份语义）。
6. **两处副本就门禁化**：浏览器 mock 的 `CONTENT_KEYS` 与壳层 content 声明由 `check_docs.py` 配方套用表核对逐键盯住（自校：需要正文的功能恰 6）；mock 的 `REFUSED_FEATURES` 静态清单随本裁决废除。

## 4. 边界

- c08 的 `unclassifiedDir` 是路径（可选路由输入），模板不存——套用时该输入缺失＝未分类文件留在原地（路由缺省），与模板意图的偏差如实存在于旧模板，v6 模板同样不携带（路径不入模板是不变量 13，优先级高于套用保真度）；ADR-0080 §4 的 CSV 族先验口径同理不变。
- f06 的 `sourceColumnRelative` 形态如上拒绝；界面本身不产出该形态（构造分支只认来源列名）。
- 空数组按「存在」计（`content_has` 只拒 null）——空规则/空排序键会穿过套用门，由路由自己的运行时校验响亮报错；不在映射层替路由做二次校验。
