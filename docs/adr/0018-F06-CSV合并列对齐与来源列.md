# 0018 F06 CSV 合并：列对齐、重复列与来源列

- 状态：已采纳
- 日期：2026-10-30
- 关联：[设计 01 §3.1/§5](../design/01-内核接口与IPC契约.md)、[方案 v1.19 §5.4](../baseline/产品方案-v1.19.md)、[TC v0.3 F06/T04/T07/T08](../testing/测试用例库-TC-v0.3.md)

## 1. 背景

F06「CSV 合并」要求在文件集合、列对齐策略、可选「来源文件名」列、表头处理与输出
编码之间建立确定语义（方案 §5.4）。与 F04（TXT 合并）相比，差异在于：

1. 各输入表头集合可能不同，必须按**表头名对齐**而非按字节顺序拼接；
2. 同名表头可能重复出现，不能简单用 `HashMap<String, _>` 覆盖；
3. 来源列与表头行都要写入产物，且无表头文件的列定位规则不同；
4. 输出必须同时给出 schema 差异报告（缺失列、额外列），并允许严格模式阻断。

## 2. 决策

1. **复用 `merge` 动作 + 追加式 `csvMerge` 载荷**：不新增 `PlanAction`。F06 与 F04
   同属 N:1 单条汇总条目；`PlanEntry` 追加可选字段
   `csvMerge{files, union, positionalColumns, hasHeader, sourceColumn, targetEncoding,
   invalid, delimiter, strict}`。旧计划不含该字段时反序列化为 `None`，F04 行为不变。
   两者同时存在视为计划非法（E1002）。
2. **列并集键 =（规范化列名, 出现序号）**：表头名先剥 BOM（`\u{feff}`）并 trim，
   再按出现顺序编号；因此重复列名不丢弃、按首次出现顺序进入 `union`。输出行按
   `(name, occurrence)` 映射，缺失补空，行尾多余字段按原顺序追加到该文件行末。
3. **来源列写入产物首列**：列名由调用方显式传入（CLI 默认「来源文件」，基线默认
   口径）；取值默认文件名，`--source-column-relative` 可改为相对 `--base-dir` 的
   路径。plan 期逐文件记录 `source_label`，label 缺失时计划条目 blocked E3004。
4. **无表头按列序号对齐**：`hasHeader=false` 时 `columns` 为空、
   `positionalColumns` 取各文件最大列数，输出按序号映射，缺少补空；无表头 + 来源列
   无法确定语义，计划条目 blocked E3004。有表头与无表头混合同样 blocked E3004。
5. **严格模式**：`strict=true` 时任一文件出现缺失列或额外列即 blocked E3004；
   非严格模式产出 `schema-missing-columns` / `schema-extra-columns` 告警并继续。
   另将列宽不一致记为 `csv-row-width-mismatch`、分隔符不一致记
   `mixed-delimiters`、源编码不一致记 `mixed-source-encodings`。
   **T07/T08 提示**：无表头模式发 `no-header-positional` 告警（按 1-based 列序号、
   最大列宽对齐）；表头经 BOM/trim 规范化发 `header-normalized` 告警；规范化后
   重复列名发 `duplicate-column-names` 告警（重复列按出现序号保留，不合并）。
   三者均为 Caution、不阻断，由 CLI/壳层预览原样展示。
6. **编码走整文件转码**：plan 期每个文件记录判定编码与分隔符；apply 时
   `read_bytes` → `transcode(source→Utf8{bom:false})` → `parse_records`，写出后
   `transcode(Utf8→targetEncoding)` 再 `write_atomic`。BOM 只在产物开头写一次，
   各输入自身 BOM 由解码剥离（沿用 ADR-0016 口径）。任一文件编码未确认 → 计划条目
   blocked E3001。
7. **apply 复核与撤销**：逐输入复核普通文件、占位、保护目录与大小；大小变化记
   skipped + E2010。表头在 plan→apply 间变化（规范化后不一致）同样记 E2010，不写
   半成品。Journal forward=`WriteAtomic{dataRef:None}`／reverse=`Quarantine`；覆盖
   既有目标时先 `backup_to_quarantine`、reverse=`WriteAtomic{dataRef}`。
8. **平台检查 `csv_merge_inspect`**：采样判定编码、嗅探分隔符、整文件解码到 UTF-8
   后统计表头字段、列宽、数据行与 dirty rows；采样窗口与块数由调用方显式传入，
   不在此发明数值阈值。UTF-16 源可被解码检查，不再短路为不可处理。

## 3. 后果

- 设计 01 §5 增加 `csvMerge` 载荷与 F06 的 `expected` 口径；契约版本升至 v1.12，T07/T08 提示补齐后升至 v1.15。
- 列并集与重复列规则要求下游预览/报告按 `(name, occurrence)` 展示，不能按列名去重。
- 当前 apply 整文件读入并转码，内存占用为 O(单个输入 + 产物)；大文件流式合并与
  逐文件进度仍为缺口，实施方案见 ADR-0016 §3 的同类退路。
- 无表头模式只按列序号对齐；需要按表头名对齐时必须先走 F07/F09 等表头处理。
  T07/T08 的“提示/显式告警”由 `plan_f06` 警告与 CLI 预览承载；F06 尚无桌面 UI 切片，
  UI 预览提示待 F06 UI 接入时复用同一警告字段。
- 来源列取值语义（文件名 vs 相对路径）属产品可见行为，已由基线 §5.4 与 CLI 参数
  显式表达；不在 ADR 内新增默认值。
