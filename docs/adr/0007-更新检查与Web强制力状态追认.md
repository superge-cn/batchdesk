# 0007. 更新检查与 Web 强制力边界的状态追认

- **状态**：已采纳（状态追认，2026-10-28）
- **日期**：2026-10-28
- **决策者**：产品所有者确认（《办公辅助工具产品方案》v1.16）；文档追认：AI 协作
- **关联**：ADR-0002（二进制加固与混淆边界）、方案 §9.7／§11.4-9／§11.6-7、设计契约 [05-Web强制力边界契约](../design/05-Web强制力边界契约.md)

---

## 1. 问题背景

ADR-0002 正文写于 2026-10-27，其中两处状态此后已经变化：

1. 关联行仍写“§11.4-9（更新检查，待最终确认）”；
2. §4 待办③仍写“Web／WASM 侧强制力归属以 §13.8 的单独设计定稿为准”。

产品方案 v1.16 已确认 §11.4-9：更新检查是独立可选项，默认手动、可彻底关闭；启用时仅拉取版本清单，不静默下载、不强制更新，更新包必须验签（§9.7）。设计契约 05 已建立并确认三条客户端边界结论；云端身份与配额服务端契约仍按设计 05 §7 后置。

按 `docs/adr/README.md` §3“不修改已采纳 ADR 的正文”，本文只做状态追认，不改变 ADR-0002 的任何加固决策。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A 直接改 ADR-0002 正文 | 把“待最终确认”改成“已确认” | 否决：违反 ADR 只追加的规则，历史决策失去可追溯性 |
| **B 新写追认 ADR** | 记录状态变化与新的关联文档，不改旧正文 | **选用** |
| C 不处理 | 让旧状态继续存在 | 否决：读者会把已确认项读成待定，排期与实现会被误导 |

## 3. 选择理由

- **B 保持历史可追溯**：ADR-0002 的加固决策、否决项与退路保持不变；只在索引中标注“状态追认见 0007”。
- **状态追认不等于实现完成**：更新通道的“防降级”（拒绝安装旧版本）仍是工程任务；§11.4-9 的确认只解除“是否做更新检查”的产品决策，不表示防降级已实现。
- **Web 侧边界已有载体**：设计 05 的 §0 三条结论已确认生效；云端强制力归属仍以云端服务端契约定稿为最终依据（设计 05 §7）。

## 4. 后果与退路

- **后果**：① ADR-0002 §4 待办①的前置条件（§11.4-9 确认）已满足，防降级可进入实现排期；② ADR-0002 §4 待办③关闭，Web／WASM 客户端边界引用设计 05；③ 不新增代码、依赖或数值。
- **退路**：若后续产品方案调整更新检查或 Web 授权边界，按方案 §11.6 重新确认，并新写 ADR 取代本文；不回改 ADR-0002。
