# 0035. C14 CSV 列拆分/合并：模式语义与列数评估口径

- **状态**：已采纳（2026-11-01，开发代理按方案 §5.15 既定一句话思路落工程语义）
- **日期**：2026-11-01
- **决策者**：开发代理（方案 §5.15 无细化条款，工程语义由本 ADR 定稿）
- **关联**：方案 §5.15（C14 一句话思路与风险"拆分后列数评估与空值处理"）、§3.2（C14 行）、§8.1 表注④（G0 单文件）；设计 01 §5（`csv-columns` 动作与 `csvColumns` 载荷）；ADR-0019（F07 同构管道）；ADR-0026（regex 引擎）；硬性不变量 1/2/4

## 1. 问题背景

方案 §5.15 对 C14 只有一句话："拆分：按分隔符/正则切分并映射到新列；合并：多列拼接加分隔符"，并点名风险"拆分后列数评估与空值处理"。切分产物落位、新列命名、源列去留、段数评估口径均未定；C14 复用既有 CSV 管道（F07 同构）后这些语义必须先行定稿。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 源列去留（拆分） | a) 源列保留＋新列紧随其后；b) 新列替换源列 | **a**：无损、与 Journal 撤销（产物整体删除）正交，用户可用 F07/C11 后处理 |
| 新列落位 | a) 紧随源列；b) 表尾追加 | **a（拆分）**：与源数据视觉对齐；**合并为 b（表尾追加）**：拼接天然是"派生汇总列" |
| 新列命名 | a) `<源列名>.1..N`；b) 用户显式命名 | **a 为缺省**（合并为"各列名按 joiner 连接"或 `--merge-name`）；无表头时无列名 |
| 列数评估口径 | a) 采样评估（与 F07 事实采集同源）；b) 全量扫描 | **a（采样）**：§5.15"评估"即近似口径，计划警告明示评估性质；执行期行内超出部分**原样保留不截断**、不足**补空串**（与既有 dirty rows 口径一致，无静默丢弃） |
| 切分方式 | 字面分隔符 / 正则 | 两者都支持（`--split-separator` / `--split-regex` 二选一）；正则复用 F13 的 `regex` 引擎（线性时间，无回溯爆炸）；连续分隔符产生空段（保留） |
| 合并拼接分隔符 | 空串是否合法 | 合法（`--join-with ""`＝直接连接）；缺省空串 |

## 3. 选择理由

- 保留源列与"紧随其后"使拆分结果可独立验证（源值与各段同行可见），撤销语义也不受影响（产物级撤销，与列无关）。
- 采样评估避免为 C14 引入第二次全量读盘（F07 事实采集已采样）；执行期"超出保留、不足补空"保证**无静默丢弃**，配合计划期 `split-parts-estimate`（Caution）警告满足"预览中明示容忍度"的同源要求（方案 §5.1 同款口径）。
- 复用 F07 管道（编码检测→RFC 4180 解析→变换→目标编码写出→Journal `WriteAtomic`/备份还原）与 C15 并发池资格，使 C14 计划/执行/撤销零新机制。

## 4. 后果与退路

- **后果**：拆分行内超出评估的段会使该行字段数多于表头（dirty 语义容忍）；`parts` 为采样值，跨样本分布突变时预览与实际有差异（警告已覆盖）。
- **退路**：未来若需"替换源列"变体，在 `csvColumns.split` 追加 `replaceSource?: boolean`（只增不改）；正则引擎替换仅影响 `split_value` 一处。
