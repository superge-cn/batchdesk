# 0052. 取消的处置：先停止派发，再问「是否一并撤销」，两个执行器统一留 Journal

- **状态**：已采纳（2026-11-02，用户裁决 OQ-34 取选项①）
- **日期**：2026-11-02
- **决策者**：用户（产品/工程）
- **关联**：方案 v1.19 §7.7／§7.8；设计 01 v1.42 §2.2；OQ-34；ADR-0033（条目级并发）、ADR-0047（臂级取消断言）；`crates/kernel/src/apply.rs`、`generic_apply.rs`、`archive.rs`、`src-tauri/src/lib.rs`、`src-tauri/src/tasks.rs`、`web/src/App.tsx`

## 1. 问题

方案 §7.7 写的是：**取消＝停止派发＋安全收尾＋询问是否回滚已完成项**（文案示例「已完成 128 项，是否一并撤销？」）。实现里从来没有这个询问，而且两个执行器各走一头：

| 执行器 | 取消时 | 与 §7.7 的差 |
|---|---|---|
| `generic_apply`（12 个写臂） | 立即按 Journal 反向回滚已应用条目 | 没问；且回滚是"替用户做了决定" |
| `archive::apply_archive_plan`（C10） | 保留已应用条目，靠 `undo_plan` 恢复 | 没问；与通用臂行为相反 |
| `apply_plan`（C09 隔离清理） | 立即回滚（`Rename` 逆向） | 与通用臂同病 |

OQ-34 把三条候选摆出来：① 加询问并统一（唯一与基线一致，改动最大）；② 追认自动回滚并删掉 §7.7 的询问；③ 追认保留＋可撤销。用户取 **①**。

## 2. 决定

**内核不再替用户决定。** 取消时执行器只做两件事：停止派发、把未派发条目记 `skipped`。已完成条目怎么处置由 `ApplyOptions.cancelPolicy` 指定：

```rust
pub enum CancelPolicy {
    #[default]
    RollbackApplied, // 立即按 Journal 反向回滚（无交互面的调用方）
    KeepApplied,     // 保留已应用条目与 Journal，等调用方问完再撤销
}
```

- **桌面壳**（唯一的取消入口）对所有 apply 任务显式传 `keepApplied`：`applyPlan` 在入队前覆盖该字段。任务终态仍是 `cancelled`，`ApplyReport.undone_by` 为空——如实表示"没有撤销"。
- **界面**在 `task://done` 后按报告统计已完成条目（`ok`／`overwritten`），且只对 `kind=apply` 的任务发问（`task://done` 为此追加 `kind` 字段，撤销任务被取消时再问"是否撤销"没有意义）：N>0 时弹「已完成 N 项，是否一并撤销？」；选「一并撤销」调用**已有的** `undoPlan(planId)`，走同一本 Journal 与同一个撤销执行器；选「保留」则条目留在磁盘，仍可在任务面板撤销。
- **C10 归档执行器**没有"执行中回滚"通道，只支持保留；壳层统一传 `keepApplied`，因此用户可见行为与通用执行器一致。若将来有调用方对 c10 传 `rollbackApplied`，报告里的 `undone_by=None` 就是"未撤销"的凭据，不会假装回滚过。
- **CLI** 不暴露取消（`cancel: None`），缺省 `rollbackApplied` 保持不变。

## 3. 为什么不把询问放进 kernel

- kernel 是纯执行层，让它在条目循环里阻塞等 UI 答复，会把用户交互耦合进领域引擎，并且单 worker 队列会被一个待答对话框卡住。
- 询问需要的 N 只有停止派发后才知道；先停、再问、再决定，比"边跑边问"更符合 §7.7 的时序。
- 撤销本身已有唯一实现（Journal 反向＋`execute_reverse`），再在 kernel 里复制一条"取消专用回滚"就是第二个撤销通道，违反不变量 4。

## 4. 后果与已接受的不完美

- **12 个写臂的既有断言不改**：它们用缺省 `rollbackApplied`，继续证明"无交互面调用方"的回滚路径；新增 `cancel_keeps_applied_entries_*` 两条（C09＋通用 rename 臂）证明 `keepApplied` 下条目保留且 `undo_plan` 能完整还原。
- **C10 的取消臂仍无 kernel 级断言**（`TC-C10-EXE-05` 保持 ◐）：archive 执行器没有可复用的 FsAdapter/ArchiveService 测试桩，补它要另建一套桩；本轮不为凑覆盖率硬造桩。用户可见语义已由"壳层统一 keep＋界面询问＋undo"覆盖。
- **崩溃窗口**：取消后若在用户答复前退出，已应用条目仍在 Journal 里（终态快照会剪枝，但 Journal 不剪），下次可通过 `undoDryRun`／`undoPlan` 恢复；本期不做"未答询问"的持久化提醒。
- **文案**：`DangerConfirm` 增加可选 `cancelLabel`（本次用于「保留已完成项」），焦点仍落安全项，危险按钮不带默认焦点。
- **E2E 口径**：`scripts/e2e-tauri.mjs` 的取消场景需在取消后点「一并撤销」才能保持"源文件全部还原、隔离目录清空"的断言；该脚本需真 WebView 环境，本批未在本机复跑，已在开发计划台账标注。
