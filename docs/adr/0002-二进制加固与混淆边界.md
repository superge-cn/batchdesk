# 0002. 二进制加固与混淆边界

- **状态**：已采纳
- **日期**：2026-10-27
- **决策者**：项目负责人（按 D-R4 决策）
- **关联**：方案 §8.0（安全边界声明）、§8.5（本地防篡改）、§4.10／§9.2（代码签名与依赖审计）、§11.3（残余盗版率）、§11.4-9（更新检查，待最终确认）、§13.5／§13.8（WASM 复用与 Web 版授权）；设计契约 [05-Web强制力边界契约](../design/05-Web强制力边界契约.md)（Web/WASM 零强制力的允许面与禁止面、发布断言）；ADR-0001（工作区结构）

## 1. 问题背景

方案第 8 节已把防篡改定为**成本策略**（§8.0：目标是把破解成本抬到超过收益；§8.5 已给出原则：校验点分散、适度混淆、不以明文分支呈现），§4.1 也把"原生二进制利于授权加固"列为 Rust 选型理由之一。但**"设计原则→出厂二进制"之间的工程层没有书面约定**：发行构建配置、符号与字符串卫生、混淆做到什么程度、反调试做不做，均未定义。

触发条件：kernel crate 与构建管线尚未建立，现在是定义这些约束成本最低的时点。不定的话，产物默认携带完整符号与明文字符串；也可能有人"好心"引入反调试或全量混淆，带来杀软误报（§11.2 已单列该风险）与排障负担。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A 不做处理 | 发行构建用默认配置，不设加固约定 | 否决：去符号、LTO 这类成本≈0 的纯收益项都不做，与 §8.5 的成本策略不符 |
| **B 基线加固＋书面边界** | 发行 profile 硬化＋字符串级卫生＋校验点分散；同时写明"不做"清单 | **选用** |
| C 重型加固 | 全量混淆／商用加壳／反调试 | 否决（理由见下） |

## 3. 选择理由

**C 为什么不够好**：① Rust 无成熟的商用级混淆工具链，LLVM 系方案维护成本高且随工具链版本漂移；② 商用加壳（VMProtect／Themida 类）带来杀软误报、崩溃定位困难与兼容开销，而 §11.2 已单列"杀软误报"风险；③ 反调试对目标用户（非技术办公人员）收益趋近于零，却伤害正常用户与排障，与 §8.5"降级不锁死、不伤害正常用户"的立场冲突。

**B 的边界怎么切**：抬高破解成本的主力不是混淆，而是 §8.5 已定的"在线复验＋服务端风控＋持续迭代"——**每次发版都让既有 patch 失效**。本 ADR 只补客户端侧的静态成本：把"看懂并改一个跳转"抬到需要真实技能、且逐版本重复投入。

**发行构建落地要求**（完整写法以 workspace 根 Cargo.toml 的 `[profile.release]` 为单一事实来源；以下为决策方向与理由）：

- 剥离符号与调试信息（`strip`）——不向逆向者提供现成的函数名地图；
- `lto` 全量、`codegen-units = 1`——牺牲发行构建时长换优化与内联（只在 CI 上跑，可接受）；
- `panic = "abort"`——移除栈展开元数据（前提：错误处理不依赖 `catch_unwind`）；
- 授权相关关键字符串不落明文（字符串级混淆可接受；属新依赖，须过 §4.11.4 审计）；
- 校验点分散、不收敛到单一布尔函数（§8.5"关键校验点分散在多处"的实现化约束）；
- 诊断包与崩溃报告不含许可证载荷与授权校验细节（对齐 §9.7 与 §12.5 的诊断包口径）；
- 加固要求进门禁：CI 在 release 构建路径上断言产物已生效（符号已剥离、授权关键字符串不落明文）——使本节要求可被机器验收，而非只靠人工确认（授权数据的完整性约束另见 ADR-0003）。

## 4. 后果与退路

- **后果**：① 对外分发的产物必须走 CI 的 release 构建路径（保证发行 profile 生效），手工构建产物不得对外分发，且该路径上执行产物断言；② 本 ADR 的"不做"清单是评审依据——反调试／全量混淆／商用加壳的提案须先推翻本 ADR，不是"顺手加上"；③ 防护上限有限：只抬高静态分析成本，不改变 §8.0 的结论（无法阻止高水平逆向，残余盗版率按 §11.3 接受）。
- **退路**：若闭门／公发阶段实测盗版损失超出 §11.3 预期，重做"成本／误报／收益"三方比选并另立 ADR；本决策不锁死升级路径。
- **待办挂账**（不阻塞本决策生效）：① 更新通道的"防降级"（拒绝安装旧版本）随 §11.4-9 的最终确认一并落地；② `src-tauri` 建立时补壳层加固（capabilities 权限最小化、CSP、生产构建关 devtools、不开 withGlobalTauri、不装用不到的插件）；③ Web／WASM 侧强制力归属以 §13.8 的单独设计定稿为准，本 ADR 不预判。
