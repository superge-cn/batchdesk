# 0087. F15 多轮会话历史的出端口径

- **状态**：已采纳
- **日期**：2026-11-09
- **决策者**：产品所有者（批准会话历史出端与同意文案）
- **关联**：设计 14 v1.1 §1/§9/§12；ADR-0085；ADR-0086

---

## 1. 问题背景

设计 14 §1 的 Phase 2 要求「单轮/多轮」，但 v1 的 §9 只允许发送当前用户文字、
文件数量/类型与 locale；多轮所需的会话历史属于新增数据出境面，必须先由产品所有者裁决。

## 2. 裁决

2026-11-09 用户批准：

1. **只发送本会话先前的用户消息文本**；不发送助手回复、文件名、路径、文件内容、许可证/设备信息。
2. 同意弹窗必须列明「本会话先前的指令（仅用户文字，不含文件名/路径/内容）」。
3. 历史仅当前会话，不持久化到 ConfigDocument/UiState/日志；关闭应用即丢失。
4. 不设数值型的条数/字符上限（任何阈值须由基线另行定值）；会话增长带来的 token/成本由 Provider 侧配额承担。

实现对应设计 14 v1.1 §9。

## 3. 实现

| 层 | 改动 |
|---|---|
| 前端 | `AiPanel.sendNow` 从当前会话消息中取 `role==="user"` 的文本，按时间序放入 `AiAskInput.history`；当前句不进历史。同意文案同步更新。 |
| IPC/DTO | `AiAskInput.history?: string[]`；Rust `AiAskInput.history: Vec<String>`（`#[serde(default)]`）。 |
| 编排 | `ModelRequest.history` 原样透传；空串过滤。 |
| Provider | `messages` = system + 历史用户消息 + 当前用户消息；历史不合并进当前句，保持轮次边界。 |
| 审计/日志 | 不记录 history 内容（沿用 ADR-0086 的日志边界）。 |

## 4. 后果与已知限制

- **提示注入面扩大**：历史文本与当前文本同样视为不可信数据；系统规则、工具 allowlist、参数校验与用户确认均不变。
- **无长度上限**：长会话会放大请求体与成本；若需上限，须按基线数值另行裁决。
- **仅用户侧历史**：模型看不到自己先前的澄清问题/回答，多轮连贯性弱于完整 chat history；后续如需助手回复出端，需再次裁决。
- **未完成**：真实模型 staging 验收（人工）；`loadRecipe` 工具仍未启用。

## 5. 测试锚点

- `ai::tests`：`history_is_forwarded_to_the_model_request`、`provider_request_body_includes_history_before_the_current_turn`、`history_defaults_to_empty_when_omitted`。
- `web/src/AiPanel.test.tsx`：`AI-UI-17`（第二次请求 history 只含第一句，不含当前句）；`AI-UI-02` 断言同意文案含「本会话先前的指令」。
