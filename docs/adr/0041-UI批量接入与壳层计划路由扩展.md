# 0041. UI 批量接入：壳层计划路由扩展与数据驱动页面注册表

- **状态**：已采纳（2026-11-01，开发代理按台账既定方向实施）
- **日期**：2026-11-01
- **决策者**：开发代理
- **关联**：ADR-0040（首批 UI 接入：F05/F11/F12）；设计 01 §4.1；设计 12 §3.1；方案 §10.2（阶段 0 出口标准）

---

## 1. 问题背景

ADR-0040 接入了三条主流程（F05/F11/F12），剩余 7 个功能（F01–F04、C01–C03）仍是 CLI-only。每接入一个功能都要在壳层重复"web 参数 → 壳层事实采集 → kernel 计划"的样板。为避免 7 份重复并控制后续接入成本，本 ADR 定稿批量接入的代码组织。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 壳层计划函数位置 | a) 继续放 `lib.rs`；b) 独立模块 `src-tauri/src/plan_kinds.rs` | **b**：lib.rs 已 900+ 行，按 kind 分模块；lib.rs 只留路由分派 |
| web 表单组织 | a) 每功能一段独立 JSX；b) 数据驱动注册表（`FEATURE_FIELDS`/`FEATURE_TITLES`） | **b**：字段规格（名称/标签/占位/宽度/textarea）声明式描述，渲染循环统一；新增页面＝注册表加一行 |
| 事实采集 | 壳层直接调 platform 函数（`csv_split_layout`/`sample_bytes`/`inspect_line_endings`/`inspect_file`） | **沿用**（与 ADR-0040 同模式）；错误经 KernelError.message 映射 IpcError |

## 3. 选择理由

- **plan_kinds.rs**：与 lib.rs 的命令层分离后，路由分派（`planOperation` 的 match）一眼可见；每 kind 的参数结构（serde camelCase）与 CLI 参数一一对应，错误经 E1002（参数）/E1003/E2001/E1004（事实）走 06 码位。
- **数据驱动注册表**：`FEATURE_FIELDS: Partial<Record<View, FieldSpec[]>>` 声明每页字段；渲染循环统一处理 text/textarea；`FEATURE_TITLES` 同构。新增页面＝注册表加条目＋壳层路由 match 加一臂，不再复制 JSX。
- **类型感知输入防污染**：C13 键列取值在壳层排除表头行（表头文本会污染 numeric/date 推断）——集成测试曾抓到此 bug。
- **c18 harness 仍绿**：新计划路由后 9 命令横切 harness 重复预览幂等与零落盘断言保持通过。

## 4. 后果与退路

- **后果**：壳层与 CLI 的 per-kind 事实采集逻辑存在受控重复（同源 platform 函数，语义一致）；若两者漂移，c18 harness 与 apply_flow 集成测试会分别报警。
- **退路**：若重复成为负担，可将壳层/CLI 共用的事实采集提取到 `platform::plan_facts`（纯 platform 函数，CLI/shell 各自包装错误）——接口已按此形态设计。

## 5. 关联

- 代码：`src-tauri/src/plan_kinds.rs`（f01–f04/c01–c03 壳层计划）、`src-tauri/src/lib.rs`（路由分派）、`web/src/FeaturePages.tsx`（注册表渲染）、`web/src/App.tsx`（导航扩展至 10 视图）；
- 后续：F06–F10/C11/C12 等按同模式接入；f01–f03 的 `targetBytes`/`linesPerPart`/`parts` 为三选一（shell 校验）。
