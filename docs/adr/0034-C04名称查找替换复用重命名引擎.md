# 0034 C04 名称查找替换：复用重命名引擎与双模式合一

- 状态：已采纳
- 日期：2026-11-01
- 关联：[设计 01 §3.1/§5.1](../design/01-内核接口与IPC契约.md)、[设计 13 §2.1](../design/13-CLI契约.md)、[方案 v1.19 §5.15](../baseline/产品方案-v1.19.md)、[ADR-0024](./0024-F12-批量重命名与两阶段计划.md)、[ADR-0026](./0026-F13-正则重命名引擎与捕获组替换.md)

## 1. 背景

C04 要求"名称批量替换，支持普通与正则，接预览"（方案 §2 功能表），§5.15 一句话思路明确"复用 F12 预览与执行引擎，仅把'规则'换成字符串替换"。工程上必须决定：两种模式的语义边界、与 F12 字面替换/F13 正则替换的复用关系，以及纯替换规则与 F12 组合规则（前缀＋查找＋后缀叠加）的差异如何落在计划参数里。若不固定模式语义，同一个"替换"在不同入口会产生两套匹配口径。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 单一 `plan_c04` 入口（kind `c04`）：plain＝字面非重叠左到右替换、regex＝与 F13 同引擎同捕获组校验；冲突/保留名/长路径/两阶段全部继承 `plan_rename` | **选用** |
| B | C04 只做 plain，regex 场景引导用户走 F13 | 否决：基线功能表明确 C04"支持普通与正则"，砍掉 regex 属产品裁剪（§11.6 范畴），工程不代行 |
| C | 为 C04 另写一套名称替换/冲突扫描 | 否决：违反"复用 F12 引擎"的基线思路，且重命名族已有 R01–R04/R06 语料断言与 Windows 实机验证，重写即放弃这层保障 |

## 3. 选择理由

- **plain 模式**：`transform_name(name, scope, |segment| segment.replace(find, replace))`——与 F12 字面查找替换同一语义（非重叠左到右、大小写敏感）；`find` 为空计划期 E1002（F12 规则校验同款）。
- **regex 模式**：直接复用 F13 的 `compile_regex`＋`validate_replacement`＋`apply_regex_rule`——非法正则/缺失捕获组引用计划期 E1002，`$1`/`${name}`/`$$` 语义与 F13 完全一致（含"裸 `$N` 后随字母数字/下划线须写 `${N}`"的边界，`$2_x` 会被解析为命名引用 `2_` 而报缺失）。两种模式一套口径，避免"普通替换"与"正则替换"行为漂移。
- **与 F12 的差异只在规则形状**：C04 是纯查找替换（无前缀/后缀叠加），计划 `params` 记录 `mode/find/replace/scope` 快照；F12 的组合规则叠加与未来序号规则的"名序一致"风险（§5.15 点名）留待序号规则切片处理。
- **继承面**：冲突扫描（existing/within-batch/case-only）、保留名/非法名拦截、计划级长路径分级、循环两阶段、Journal 逆改名撤销全部来自 `plan_rename`——R01–R04/R06 语料断言对 C04 同样成立，`existing_targets` 由壳层探测传入、计划排除本批次将移走的源。

## 4. 后果与退路

- 设计 01 §3.1 追认 `c04` 计划（复用 `rename` 动作，无新增载荷字段）；设计 13 §2.1 把 `c04` 纳入实验命令。
- 已知缺口（必须登记、不得表述为产品完成）：无大小写折叠替换选项（继承 F12 口径）；序号规则叠加未做；TC PRE/EXE/RBK 人工用例与 UI 预览未做；Windows 实机长路径/占用验收未做。
- 退路：若 C04 需要与 F12 不同的冲突策略或作用域扩展，在 `PlanC04Rule` 追加字段即可，`plan_rename` 引擎不动；plain 模式如需大小写折叠，扩展闭包内匹配逻辑，计划契约不变。
