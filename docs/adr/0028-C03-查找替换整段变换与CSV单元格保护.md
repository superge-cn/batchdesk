# 0028 C03 查找替换：整段变换、CSV 单元格保护与 UTF-8 切片边界

- 状态：已采纳
- 日期：2026-10-31
- 关联：[设计 01 §3.1/§5.1](../design/01-内核接口与IPC契约.md)、[设计 13 §2.1](../design/13-CLI契约.md)、[方案 v1.19 §5.14](../baseline/产品方案-v1.19.md)、[T v1.12 C03/K06/T01](../baseline/功能测试方案与验收标准-T-v1.12.md)、[ADR-0026](./0026-F13-正则重命名引擎与捕获组替换.md)、[ADR-0027](./0027-C02-换行转换流式重写与CSV引号保护.md)

## 1. 背景

C03 要求 TXT/CSV 的普通/正则替换、先预览再执行、匹配计数与上下文、默认备份可回滚（方案 §5.14）。工程上必须决定：CSV 结构如何保护、正则替换如何校验、编码与大文件边界放在哪一切片，以及与已建 `ContentRewriter`/二进制魔数如何复用。若不做单元格级保护，普通文本替换会直接改坏引号结构；若在本切片同时引入流式窗口，会把 C03 的预览语义与流式边界问题混在一起。

## 2. 候选与结论

| 候选 | 一句话定义 | 结论 |
|---|---|---|
| A | 本切片先做整段读取/变换；CSV 默认单元格级；UTF-8 源；流式窗口与行区间后置 | **选用** |
| B | 一次做流式扫描＋最大模式长度重叠窗口＋行区间 | 否决：预览计数、CSV 单元格与流式边界同时实现风险过高；先把行为、预览、撤销与结构保护定稳 |
| C | CSV 只做纯文本替换，不解析结构 | 否决：与 §5.14"默认单元格级、保护引号结构"冲突，T01 引号内命中也无法安全验证 |

## 3. 选择理由

- 整段读取让预览计数、上下文示例与执行变换使用同一套 `Matcher`/CSV 解析逻辑，避免"预览数与执行结果不一致"；大文件流式作为明确缺口登记，后续按 C02 的 `ContentRewriter` 通道替换实现。
- CSV 默认 `cell`：用现有 `parse_records`/`write_record` 按字段替换，引号内换行作为字段数据保留；不闭合引号计划期 blocked E3004，绝不进入 apply。`--csv-mode text` 保留纯文本替换能力但发 `csv-text-mode` 警告。
- 正则替换复用 F13 的 `regex` 引擎与捕获组引用校验：无效正则/缺失捕获组计划期 E1002；`$1`/`${name}`/`$$` 与 F13 同一语义。普通模式使用 `str::replace` 的非重叠左到右语义，计数与执行一致。
- 二进制魔数直接从 C02 的 `kernel::binary` 复用，K06 不再进入文本管道；空替换发 `empty-replacement` Danger 警告；无匹配的条目标 skip，不写盘。
- 编码边界：本切片只接受 UTF-8/UTF-8 BOM/ASCII；GB18030/UTF-16 等 blocked E3001 并提示先走 C01。这样字节级替换不会破坏多字节字符，也避免把 C01 的转码语义混入 C03。

## 4. 后果与退路

- 设计 01 §3.1 增加 `plan_c03`；§5.1 增加 C03 的 `edit-content`/params 语义；设计 13 §2.1 把 `c03` 纳入实验命令。
- 已知缺口（必须登记、不得表述为产品完成）：整段读取内存 O(文件)、无流式重叠窗口；无行区间限定；CSV 单元格模式会规范化记录终止符为 LF（字段内换行保留）；非 UTF-8 源需先 C01；TC PRE/EXE/RBK 人工用例与 UI 预览未做。
- 退路：流式化时保留 `Matcher`/`inspect_bytes`/`replace_bytes` 的纯函数接口，仅在 `ReplaceRewriter` 内改为块读＋重叠窗口；行区间可扩展为 `Matcher` 的文本切片参数，不影响计划/Journal；若要求保留原始 CSV 终止符与引号风格，需新增字节级单元格重写器，接口不变。
