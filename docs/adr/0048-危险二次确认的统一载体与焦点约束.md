# 0048. 危险二次确认的统一载体：alertdialog 组件＋「焦点落取消」硬约束

- **状态**：已采纳（2026-11-02，开发代理按台账既定方向实施）
- **日期**：2026-11-02
- **决策者**：开发代理
- **关联**：ADR-0047（参数变更失效落入口层）；方案 §3.3（S02 行）、§7.11、§7.4、§7.7、§5.10；U v1.3 §3.5／§3.1；设计 12 §5；AGENTS 硬性不变量 7／11

## 1. 问题背景

方案 §3.3 的 S02 行原文（v1.19 已核对）：**"保护目录命中即禁止写入（含二次确认），名单由用户自定义（默认空，v1 不预置——风险由预览危险级提示承担，见 7.11）"**；§7.11 又规定**危险（红）级"必须二次确认且确认按钮不带默认焦点"**。内核与壳层早已把保护命中判成 blocked（E2009）并在执行层跳过，但界面上**没有任何二次确认**——映射表里 `TC-S02-PRE-06` 因此只能标 ⛔ 待实现，`TC-S02-E○1` 的缺口是"提示呈现待 UI"。

同时，"危险确认"不是 S02 一处的需求：覆盖策略（§7.7）、删除进隔离目录（§5.10）、高危归档规则（§5.8 风险与对策）、C52 扩展名批量修改（§3.2）都要同一形态。若每处各写一遍，§7.11 的"避免各功能自定义口径不一致"就落空。

## 2. 候选与结论

| 议题 | 候选 | 结论 |
|---|---|---|
| 确认形态 | a) 行内警示条＋勾选框；b) 模态 `alertdialog` | **b**：U v1.3 §3.5 已给对话框的容器／结构／遮罩／图标规范（底 `--popover`、圆角 `--radius-lg`、`--shadow-2`、遮罩亮 0.4 暗 0.6、危险对话框只给标题图标着色、不整块红底），勾选框形态无法承载"回车即确认"的防护 |
| 焦点规则 | a) 焦点落确认按钮（效率优先）；b) **焦点落「取消」**，危险按钮不带任何自动强调 | **b**：§7.11 原文要求，且 U §3.1 写明"危险按钮不加脉动／默认高亮／品牌色描边"；实现上只在挂载时 `cancelRef.focus()` |
| 载体 | a) 每功能各写一份；b) 共享组件 `web/src/DangerConfirm.tsx`（title／body／items／confirmLabel／onCancel／onConfirm） | **b**：C09 工作台与 23 功能页的执行入口都改为"命中即先弹确认"，后续覆盖／删除／高危规则复用同一组件 |
| 判定放在哪 | a) 前端根据 `blocked.code === "E2009"` 决定是否弹；b) 新增壳层命令询问"是否命中保护" | **a**：计划的 `entries[].blocked.code` 已来自 kernel 判定，前端不需要第二次询问；**弹窗只确认"其余条目继续"，绝不改变命中条目被禁止写入的事实**（不变量 11：强制力在执行层） |
| 遮罩色 | a) 直接写 rgba 字面量；b) 新增语义 token `--dialog-backdrop` | **b**：值取自 U §3.5（亮 0.4／暗 0.6），按主题块各给一份；组件样式不出现裸色值（前端附加约束） |

## 3. 选择理由

- **不弱化判定**：对话框文案明确"这些条目已被禁止写入、不会执行（强制力在内核执行层，界面确认不改变该判定）"，确认后仍只派发非 blocked 条目——与 §3.3"命中即禁止"一致，避免把二次确认误做成"确认后即可写入保护目录"的放行入口。
- **可断言**：Vitest 用例断"未确认前 `applyPlan` 未被调用 → 确认后恰好一次"，并断 `document.activeElement` 是取消按钮；Playwright 两条在真实浏览器里断对话框可见、点名被保护落点、`toBeFocused()` 在取消而危险按钮 `not.toBeFocused()`，另加一条负向用例（保护名单为空时不得出现对话框，对应 `TC-S02-PRE-01` 的"默认空名单不误拦"）。
- **先红是实测的**：把两处 `protectionHits.length > 0` 临时改为恒假并重新 `pnpm build`（`tsc --noEmit` 必须过，否则 `vite preview` 会拿旧包得出假绿——ADR-0047 §3 已记过一次），e2e 1 failed／Vitest 1 failed；恢复后 12 passed／8 passed。

## 4. 后果与退路

- **后果**：映射表 `TC-S02-PRE-06` 由 ⛔ 待实现改判 ◐（只剩"文案观感属人工走查"），`TC-S02-E○1` 转 ✅；"待实现（前端无二次确认入口）"这一载体类别归零。新增两个前端测试文件项，web job 时长略增。
- **代价与边界**：入口层确认仍属**交互语义**，绕过前端直接调 IPC 不会看到对话框——与 §7.3 失效判定同层，真正的写入拦截在 kernel（`protected_target_is_skipped_before_any_change`、`protected_source_is_rechecked_during_execution` 已钉住）。
- **退路**：若日后要求"确认信息进 Journal／操作日志"或按功能定制风险等级（§7.11 的风险自动计算），组件的 `items`／`body` 已是入参，扩展点不必改调用方；若要求内核拒绝未确认的计划，则需改设计 01 的计划 schema（届时本篇标 Superseded）。
