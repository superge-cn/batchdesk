# 0099. F09 位置行抽取的区间流式读取

- **状态**：已采纳
- **日期**：2026-11-13
- **决策者**：开发代理（实现缺口修复；判据引 E5 配方①「内存占用不随输入线性增长」）
- **关联**：E5 判据点①（T v0.4 §2.3）；方案 §5.15 F09「流式跳过前 X−1 行……提前终止」；TC-F09-EXE-05

---

## 1. 问题背景

TC-F09-EXE-05 的缺口：「**选中区间仍读入内存后转码**」。

`perform_csv_range` 的做法是：`read_ranges` 把 header＋data 两个区间读成一个 `Vec<u8>`，再 `transcode(&raw)` 整段转码成另一个 `Vec`，最后 `write_atomic`。内存因此是 **O(选中区间)**——选中 1 GiB 就吃 1 GiB 以上。

E5 判据① 要求「内存占用不随输入线性增长（流式）」。F01/F02/F03 已各自流式化，F09 是剩下的一处。

## 2. 候选与否决理由

| 议题 | 候选 | 结论 |
|---|---|---|
| 怎么流式 | a) 用 `read_stream` 跳过前段；b) **新增 `FsAdapter::read_ranges_stream`** | **a 不可行**：`read_stream` 从文件头顺序读，要「跳过前 X−1 行」就得把前段也读一遍（白读）；区间读的意义正是不碰未选中的字节。**b** 在适配层 `seek` 到区间起点再分块回调，未选中的字节一个都不读 |
| 表头怎么办 | a) 也流式；b) **仍按需整读** | **b**：表头要解析列名与计划期的 `columns` 核对（E2010 一致性检查），且它只是**一行**；为它单独做流式解析会引入一套记录边界状态机，收益极小 |
| 不支持的适配层 | a) 静默回落 `read_ranges`；b) **返回 E5001 拒绝** | **b**：与 `read_stream` 的既有契约一致（「不得静默降级为 read_bytes，否则"流式"只是名义上的」）。回落会让「内存 O(块)」的保证悄悄失效 |
| 末条记录 | a) 补终止符；b) **不补** | **b**：源末尾没有换行就没有，产物不该凭空多出一条空记录（与 ADR-0098 的口径一致） |

## 3. 决策

1. **契约**：`FsAdapter` 增 `read_ranges_stream(source, ranges, callback)`，默认实现返回 E5001（不支持即拒绝，不回落）。
2. **平台实现**：与 `read_ranges` 同一套边界校验（空区间 E1002、越界／缩水 E2010），差别只在把「追加到 Vec」换成「边读边回调」；块大小 64 KiB，回调错误立即向上传播并中止。
3. **测试桩**：`TestFs` 同步实现（内存切片逐区间回调），并加调用计数。
4. **执行臂**：`perform_csv_range` 改为「表头按需读＋校验 → `write_atomic_with` 里流式转码数据区间 → 原子写」。目标编码的 BOM 由流式写统一加在产物最前面（表头用 `without_bom`，避免双 BOM）。
5. **断言**：既有用例补 `read_ranges_stream_calls() == 1`；平台侧新增「字节内容与 `read_ranges` 一致＋边界校验同口径＋回调错误传播」。

## 4. 后果

- **内核**：`fs.rs` 加 trait 方法；`generic_apply.rs` 的 `perform_csv_range` 重写为流式；`TestFs` 加实现与计数器。
- **平台**：`CliFsAdapter` 加实现（`seek`＋分块）。
- **不变**：`read_ranges` 保留（表头与其他调用方仍用）；产物字节与改前一致（同一套转码与 BOM 口径）。

## 5. 残余

1. **表头仍是 O(表头大小)**：单行表头通常极小；若真出现「超长单行表头」，由 E5 判据②（超长行按方案处理且有告警）兜底。
2. **回调错误即中止**：与 `read_stream` 同语义；写入侧的错误由 `write_atomic_with` 的临时文件机制兜底（不留半截产物）。
